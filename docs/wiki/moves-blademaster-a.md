# 近战招式与动作值：大剑・太刀・单手剑・双剑

> **三行摘要**
> - 本页给四把武器的**逐条动作值**（= 每次命中的威力百分比）：大剑 `w00` 61 条、太刀 `w07` 85 条、单手剑 `w01` 74 条、双剑 `w11` 152 条，全部来自 romfs `player/wNN/player/hit/pl_weNN_hitdata` 的 56 B 记录，**动作值 = 记录 `+0x04` u16**。
> - 招式名用**官方 chS 文本** `HN_WeaponControlsMsg_chS`（`WC_GS_*` / `WC_TAC_*` / `WC_SS_*` / `WC_DB_*`，即游戏内「武器操作」页的招名与连段窗口名），按键仍取 MHXX 镜像 wiki（`text/1950..1953`）。官方名表**不与 hitdata 记录号对应**，所以「哪条记录属于哪一招」仍只有仓库既有交叉核对（`motion-values.md` §3 锚点）和紧邻锚点的数值梯能绑定，其余一律标 `[U]`，不给猜名。
> - 每条数值都带 `wNN rec<idx>` 出处，可直接回查 JSON 与 romfs 字节；伤害用法见 `damage-formula.md`（动作值只是公式里的一个因子，还要乘面板/肉质/锋利度/会心）。

状态标记（本页口径见 §0）：

`[C]` = 已从 romfs 字节解出并抽检一致；`[B]` = 官方 chS 文本（romfs gmd，单源）；`[W]` = MHXX 镜像 wiki 文本；`[I]` = 推断；`[U]` = 未确认（宁标 `[U]` 不猜）。

本页的数值与原始字节做过抽检（JSON ↔ romfs 逐字节一致）：`w00` 全 61 条、`w01` rec27–31、`w07` rec44–48、`w11` rec96–102 均对上（偏移 `0x10 + idx × 0x38 + 4`）。所以「动作值」列统一按 `[C]` 用。

### 0.2 三个必须知道的口径

1. **「标记」列指的是「记录 ↔ 招式」的绑定强度，不是数值的可信度**。数值全是 `[C]`；绑定分三档：
   - `[C]` = 仓库既有交叉核对（`motion-values.md` §3 锚点表）已经对齐的记录，本页沿用，不改写；
   - `[I]` = 紧邻一个 `[C]` 锚点、且同一阶梯单调递增的记录（例：rec14 = 强蓄力斩（阶段 3）已锚定，则 rec12/rec13 = 72/90 按 3 级梯推为阶段 1/2）；
   - `[U]` = 没有任何证据能把这级威力绑到某个招名，只给 `rec idx → 动作值`。
2. **一条记录 ≠ 一招**。同一招在不同风格、不同段数、甚至左右手（双剑）都会各占一条记录，所以本表是「逐记录」清单，一条锚点记录不代表该招只有一条记录。
3. **`+0x04` 就是伤害公式用的那个数**（不是同记录里另一个 u16 `+0x30`）。两者多数记录相等，但 `w00 rec8` 是 `+0x04 = 2` 而 `+0x30 = 10`，`w04 rec3` 是 90 vs 2 —— 抄错字段会差一个量级（`mv-decoder.md`、`motion-values.md` §0.2 `[C]`）。

换算：动作值 48 表示这一击按面板攻击的 **48%** 计入，伤害 ≈ 面板 × 48/100 × 肉质/100 × 锋利度 × 会心（结构见 `damage-formula.md` §0/§2）。

### 0.3 命名口径

- **招式名**：以官方 chS「武器操作」文本为准（§0.1），每行标注 `label + #串号`；镜像旧名只作对照，便于玩家把页面上的名字对到旧攻略。民间名（道具 / 怪物 / 地图）不在本页范围内，统一由共享映射 `docs/data/folk-names.json` 落地后再替换，本页不手改。
- **风格名**：用社区词 **勇气**（官方 chS：英勇，`CommonMsg_chS` #181）、**炼金**（官方同名），与仓库其余页面保持一致。官方串里写作「英勇状态 / 英勇槽」，本页正文一律写「勇气状态 / 勇气槽」。

合计 372 条记录；**已绑定招名的只有 17 条**，其余 355 条只有「记录号 → 动作值」。招式清单（官方名 + 按键 + 镜像旧名）在各武器 §N.1，数值结构（阶梯 / 成对 / 最高值）在 §N.2 与各记录表。

怎么用：

- 想知道「某招多少动作值」→ 先看该武器的「能绑定的招式」小节；表里没有的招，本页不给数 —— 不是没有数，而是**没有证据把那条记录指给这一招**（§6 #1）。
- 想比「哪个动作更疼」→ 同一武器内比较记录值即可（数值同源同口径）；跨武器比较要看面板与命中次数，见 `weapons-overview.md` 与 `damage-formula.md` §2。
- 想算实际伤害 → 面板 × 动作值/100 × 肉质/100 × 锋利度 × 会心 × 任务修正（`damage-formula.md` §0）。

回查（任一数值都可重现）：

```bash
node tools/mhgu/hitdata.mjs dump --weapon w11    # 逐条列 idx / 动作值
node tools/mhgu/hitdata.mjs json                 # 重建 docs/data/json/motion-values.json
```

原始字节在位：`MHGU-private/romfs-extract/player/wNN/player/hit/pl_weNN_hitdata.4e2ef008`，第 `idx` 条起始于 `0x10 + 56 × idx`，动作值 = 该处 `+0x04` 的 LE u16。

相关页面：`motion-values.md`（记录格式 + 大剑/太刀逐条同表）、`damage-formula.md`（动作值在公式里的位置）、`styles-arts.md`（四风格按键差异与狩技）、`weapons-overview.md`（武器面板）。

## 6. 未确认（`[U]`）与补齐路径

| # | 项 | 现状 / 怎么补 |
|---|---|---|
| 1 | **逐记录 → 招名的映射** | 官方 chS **有**招名表（`HN_WeaponControlsMsg_chS`：`commandnote` 操作页提示、`skilltitle` 连段窗口名、`skillnote` 机制说明），但它**只给名称与文字说明，不带 hitdata 记录号**；romfs / main 里也没有「记录号 ↔ 动作 id」的显式表，所以本页 372 条里只有 17 条能绑定。补齐三步：(a) 解 `nativeNX/table/weaponProcessWNN.wpd`（逐武器 0x20B 记录 = 派生/取消顺序）拿动作 id 与派生图；(b) 在动作/参数表中找到「动作 id → hitdata 记录号」字段（候选 `player\param\pl_wNN`，rFreeUseParam，`0x496F8F22`）；(c) 用官方名 + 镜像按键/派生关系（例「横拍后不动摇杆 → 强蓄力斩」）把动作 id 对到招名。三步落地前不把剩余记录指给具体招。 |
| 2 | 谁进伤害公式：`+0x04` 还是 `+0x30` | 本页取 `+0x04`：拷贝器把它写进对象 power 槽，且能复现全部已知锚点（`mv-decoder.md`）。同记录 `+0x30` 是独立 u16，多数相等但 `w00 rec8`（2 vs 10）、`w04 rec3`（90 vs 2）不等；最终拍板仍待伤害计算路径，见 `motion-values.md` §5 #1。 |
| 3 | 一条记录 ≠ 一招 | 同一招在不同风格/蓄力段/左右手各占记录（双剑成对同值群、太刀气刃大回旋斩 6 条即例），所以本表是逐记录清单，「已绑定记录数」不等于「招式数」。 |
| 4 | 狩技倍率 | 狩技参数表（`hunterArtsData`，`tools/mhgu/arts.mjs`）只有槽代价/时长/消息类型，**不含倍率**；狩技的实际倍率落在本 hitdata 表里，但无法逐条定名 `[U]`。狩技名与解锁见 `styles-arts.md`。 |
| 5 | 命中类型 / hitbox / 属性 / 气绝 / 减气 | 本资源不承载这些：`+0x06`（命中类型）与 `+0x19`（hitsize 组号）在 870 条记录里全为 0；其余 u8/u16 语义未从伤害路径闭环（`mv-fields.md`），本页一律不用。 |
| 6 | 单手剑 / 双剑完全没有锚点 | 两表 74 + 152 条全部 `[U]`；`motion-values.md` §3 的锚点表只覆盖大剑/太刀。补法同 #1 —— 拿到动作 id 映射后，这两把武器可以一次性全部落地。 |
