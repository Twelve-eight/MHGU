# 武器总览（14 种武器：官方中文名 / 核心机制 / 面板区间 / 升级树导航）

> 1. 14 种武器 = class 1–15 里的 14 个非空档（class 6 在游戏里是空号，官方文本写作「中等弩（缺号）」）；每种给官方 chS 名、固有子系统（蓄力/瓶/炮击/弹种/音色/精华/瓶/斩击槽…）、下位/上位/G 级面板区间、以及「怎么在一棵升级树里查到某把武器要什么素材」。
> 2. 名称出自 romfs 官方 chS 文本；面板出自 `mhgu.db` `weapons`（= `docs/data/weapons/*.json`，两源数值一致）；**rank 分档不是数据自带字段**，由配方里的通用素材占位符（`LR/HR/G … Materials`）推导，覆盖 5,685 / 10,877 条（52.2%），其余 5,192 条不参与分档统计。
> 3. MHGU 没有旧作那种「武器种显示倍率」：面板数值直接进伤害公式，跨武器种比较面板是有效的（`damage-formula.md` §2，`[I]` + romfs 字节佐证）。**动作值（每招 %）目前全库无信源**，所以本页只给面板，不排强弱榜。

## 2. 面板怎么读（先看口径，再看数字）

### 2.1 一条记录 = 一个家族的一个等级

| 字段（`weapons/<type>.json`） | 类型 | 含义 | 来源 |
|---|---|---|---|
| `id` | int | `(class<<16) \| (familyIndex<<8) \| (level+1)`，等于 `mhgu.db weapons._id` | `docs/mechanics/equipment.md` §1.2（`[C]`） |
| `parentId` | int | 树上直接前驱；`0` = **没有前驱**（可直接生产/购买），不等于「低级武器」 | 同上 |
| `familyId` | int | `class*256 + familyIndex`；同家族各等级共享 | 同上 |
| `damage` | int | 面板攻击（= db `attack`） | 数值 `[I]`，两源一致 `[C]` |
| `affinity` | int | 会心 %，可负 | 同上 |
| `elemental.type` / `.amount` | str/int | 属性/状态种类与值（0 = 无属性） | 同上 |
| `slots` | 0–3 | 装饰品孔数 | 同上 |
| `rarity` | 1–11 | **家族级字段，不是游戏内稀有度**（见 2.2） | 同上 |
| `defense` | int | 武器自带防御加成（0–60） | 同上 |
| `sharpness` | str×3 | 红.橙.黄.绿.蓝.白.紫 七色；三段 = 基础 / 匠+1 / 匠+2；仅近战有 | `docs/mechanics/equipment.md` §1.5（`[C]`） |

### 2.2 三个必须知道的陷阱

1. **`rarity` 不是稀有度**。抽检 5 类（大剑 136 家族 / 大锤 131 / 弓 107 / 盾斧 79 / 双剑 124）**没有一个是族内 `rarity` 变化的**（同一 `familyId` 的多个等级 rarity 全同）；家族 257（化石大剑）11 级全部 `rarity=1`，可它的末级攻击是 320。⇒ 该字段只能当「家族档」，当不了武器档，也不能当 rank（`[I]`，复核 jq：`[.[]|{f:.familyId,r:.rarity}]|group_by(.f)|map(select((map(.r)|unique|length)>1))|length` 返回 0）。
2. **`parentId=0` 不等于新手武器**。每个家族的头一级都是 `parentId=0`，而有些家族头一级就是上位/G 级武器（例：大剑 root 攻击区间 50–330）。所以本页把这一行标成「直接生产」，不叫「起始武器」。
3. **两门弩炮没有属性；弓/轻弩/重弩都没有斩味**。`element` 恒空的只有轻弩炮与重弩炮（弓有属性，406 条）；`sharpness` 三者在库里都缺失（近战 8,721 条有斩味，2,156 条无，`docs/mechanics/equipment.md` §1.1）。弩的属性伤害来自弹药，不是武器面板。

### 2.3 rank（下位/上位/G 级）是从哪来的

`mhgu.db` 与 `weapons/*.json` **都没有 rank 字段**，`weapons.tree_depth`/`max_attack` 恒 0、`awaken` 全空。可用的 rank 证据在 `components`（配方表）里：大量配方带 1–2 个**通用素材占位符**，名字前缀就是该级配方的档位。

| 占位符道具 id | 名字（db） | 例 |
|---|---|---|
| 1966084 / 1966085 / 1966086 | `LR/HR/G Ore Materials` | 化石大剑 LV2–3 用 `LR Ore Materials`，LV10 用 `G Ore Materials` |
| 1966087 / 1966088 / 1966089 | `LR/HR/G Insect Materials` | 同族 LV4–5 = `LR Insect Materials`，LV11 = `G Insect Materials` |
| 1966081–1966083 等 | `LR/HR/G … Materials` | 整段占位符 id 落在 1966081–1966417：共 **277 个**（60 个 id 空号），内容是「档位 × 素材来源」的组合——既有通用类（Ore/Bone/Insect/Monster…），也有按怪/按小怪类（`LR Rathalos Materials`、`G Tigrex Materials`…），以及只有 HR 的 Hyper/Deviant 两种、只有 G 的怪；**不是完整笛卡尔积** |

**关键验证：三档互斥**。带占位符的 5,685 条武器记录里，「同时含 LR 与 HR」「同时含 LR 与 G」「同时含 HR 与 G」的记录数**都是 0** ⇒ 占位符前缀唯一确定该级的 rank，可放心当分档键。

| 指标 | 值 | 来源 |
|---|---|---|
| 有占位符的武器记录 | 5,685 / 10,877 = 52.2%（LR 1,224 / HR 2,216 / G 2,245） | `mhgu.db components`+`items`（`[I]`） |
| 同时含两档占位符的记录 | 0 | 同上 |
| 无占位符的 5,192 条 | 直接生产（`parentId=0`）的根武器、以及配方只写具体素材的条目 | 同上 |

本页每张分档表都标了 `条数`，就是该档**有占位符**的记录数；未进表的那部分不是「不存在」，而是「配方里没写通用素材，无法证明档位」。复核 SQL（可直接跑）：

```sql
-- 每种武器 × rank 的攻击/会心/有属性/属性值（与各节表格同口径）
SELECT w.wtype, r.rk, COUNT(*) n,
       MIN(w.attack) atk_min, MAX(w.attack) atk_max,
       MIN(CAST(w.affinity AS int)) aff_min, MAX(CAST(w.affinity AS int)) aff_max,
       SUM(w.element<>'' AND w.element_attack>0) with_elem,
       MIN(CASE WHEN w.element<>'' AND w.element_attack>0 THEN w.element_attack END) elem_min,
       MAX(CASE WHEN w.element<>'' AND w.element_attack>0 THEN w.element_attack END) elem_max
FROM weapons w
JOIN (SELECT c.created_item_id wid,
             CASE WHEN MAX(i.name LIKE 'LR %')=1 THEN 'LR'
                  WHEN MAX(i.name LIKE 'HR %')=1 THEN 'HR' ELSE 'G' END rk
      FROM components c JOIN items i ON i._id=c.component_item_id
      WHERE c.component_item_id BETWEEN 1966081 AND 1966417
      GROUP BY c.created_item_id) r ON r.wid = w._id
GROUP BY w.wtype, r.rk;
```

口径校验：`element<>''` 与 `element<>'' AND element_attack>0` 在全库等价（5,736 = 5,736，`element_attack=0` 的有种类记录为 0），所以上表的 `with_elem` 就是各节「有属性」列。

### 2.4 属性名与「有属性」口径

| 属性 | 官方中文 | 出处 |
|---|---|---|
| Fire / Water / Thunder / Ice / Dragon | 火属性 / 水属性 / 雷属性 / 冰属性 / 龙属性 | `chS/table/StartMenuMsg_chS.gmd` #435–#439（标签 `Fire_Attribute` … `Dragon_Attribute`）|
| Poison / Paralysis / Sleep / Blast | 毒 / 麻痹 / 睡眠 / 爆破（瓶名直接给出：毒瓶 `#426`、麻痹瓶 `#428`、睡眠瓶 `#430`、爆破瓶 `#434`） | `chS/table/itemData_chS.gmd` #426–#436 |
| 减气（Exhaust） | 减气（减气瓶 `#432`） | 同上 |

「有属性」= `element` 非空且 `element_attack>0`。全库 5,736 条有属性 / 5,141 条无属性（与 `docs/mechanics/equipment.md` §1.1 的 5,141 完全吻合，是这两份导出的交叉校验）。属性值区间 2–86。

**一个数据缺口**：斩击斧有 156 条记录 `element` 为空但 `element_attack` 5–45（黑曜石/历耀系，如 `Obsidian Axe 1` = db `_id` 590337，属性值 18）。这些武器在游戏内应有属性，但库里种类字段没填（`[U]`，未实机核对）⇒ 本页斩击斧的「有属性」计数把这两类分开写。

各节末尾的「属性覆盖：雷 85/68、水 90/38…」统一读作 **条数 / 该属性的最大属性值**（例：双剑冰属性 93 条，最高 42）。

## 3. 升级树导航：怎么查到一把武器要什么素材

### 3.1 树 = 家族 × 等级

- `family = class*256 + familyIndex`；`_id = (class<<16) | (familyIndex<<8) | (level+1)`，`level` 从 0 起（显示 LV = level+1）。反算：`class = _id>>16`、`familyIndex = (_id>>8)&0xFF`、`level = (_id&0xFF)-1`（`docs/mechanics/equipment.md` §1.2，`[C]`）。
- 一个家族一条升级链（`parent_id` 单亲，实测 **10,090 个有前驱的武器每个都只有 1 个父节点**），每家族恰好 1 个 `final=1` 的末级（1,585 家族 / 1,585 末级）。
- 存档只存「家族 + 等级」，**不存派生历史、不存是否已解锁、不存素材**（`docs/mechanics/equipment.md` §1.4，`[C]`）。

### 3.2 `components` 表：素材在哪一列

| 列 | 含义 | 注意 |
|---|---|---|
| `created_item_id` | 被做出/强化出的东西的 `items._id`（武器行也在这张 items 表里，`type='Weapon'`） | 与 `weapons._id` 同值 |
| `component_item_id` | 消耗物 `items._id` | 既可能是素材，也可能是**父武器** |
| `quantity` | 数量 | — |
| `type` | `Create`（生产）/ `Create B`（第二种生产配方，73 行，例：装饰珠可用「血奔珠 + 素材」造）/ `Improve`（强化） | `Improve` 行里必有一条 `component` 是父武器 |
| `key` | 同一配方内的分组序号 | `Create` 有 key 0/1 两种：**key0 + key1 合起来才是完整配方**（例：`Petrified Blade 1` = key0 大地结晶×1 + key1 铁矿石×4），不要读成两套可选配方 |

⇒ 「某武器要什么素材」= 查 `created_item_id = 武器 id` 的行，**排除** `component` 本身是武器的行（那是父节点），剩下的就是素材；`LR/HR/G … Materials` 是档位占位符（§2.3），不是真素材。

### 3.3 三条够用的 SQL

```sql
-- ① 一把武器（按 items 表里的英文名找）要什么素材
SELECT c.type, c.key, mi.name AS material, c.quantity
FROM components c JOIN items mi ON mi._id = c.component_item_id
WHERE c.created_item_id = (SELECT _id FROM items WHERE name = 'Petrified Blade 6')
ORDER BY c.type, c.key;
-- ② 整个家族的全树（按 familyId）
SELECT w._id, w.attack, it.name AS weapon_name,
       (SELECT GROUP_CONCAT(mi.name||' x'||c.quantity, ' + ')
        FROM components c JOIN items mi ON mi._id = c.component_item_id
        WHERE c.created_item_id = w._id AND mi.type <> 'Weapon') AS mats
FROM weapons w JOIN items it ON it._id = w._id
WHERE w.family = 257 ORDER BY w._id;
-- ③ 素材反查：这件素材能做/强化哪些武器
SELECT DISTINCT it.name FROM components c JOIN items it ON it._id = c.created_item_id
WHERE c.component_item_id = (SELECT _id FROM items WHERE name = 'Eltalite Ore')
  AND it.type = 'Weapon';
```

wiki 镜像侧另有同名树页可交叉看（节点带 `[生产]`/`[购入]`/`[生产G]`/`[XX]` 标记与攻击/斩味/孔）：剑士用 `text/1900`–`1909`（大剑 1900、太刀 1901、片手剑 1902、双剑 1903、大锤 1904、狩猎笛 1905、长枪 1906、铳枪 1907、斩击斧 1908、盾斧 1909），神枪手用 `1910`–`1913`（操虫棍 1910、弓 1911、轻弩 1912、重弩 1913），G 级追加部分在 `2882`–`2895`，各武器种「最终强化一览」在 `2700`–`2713`（`docs/mechanics/equipment.md` §数据源，`[W]`）。

### 3.4 完整示例：家族 257（Petrified → Scholarly → Sophos，11 级）

先消歧：**家族 257 不是「Buster」线**。Buster 系是另一个家族（`family 276`，9 级：`Buster Sword 1`–`6` / `Buster Blade 7`–`8` / `Buster Falx 9`，末级攻击 340），本节这条是化石系（`Petrified Blade 1–7` / `Scholarly Blade 8–10` / `Sophos Blade 11`，末级攻击 320）。两条家族互不派生，查素材时按 `family` 值区分。

中文名分段：贝鲁纳大剑（LV1–7）/ 贤者大剑（LV8–10）/ 智慧大剑（LV11）。依据 `weapon00MsgData_chS` #6/#8/#10，与英文名 `Petrified`/`Scholarly`/`Sophos` 一一对应（`[B]` + `[I]` 对齐）。素材里的 `LR/HR/G … Materials` 是占位符，按档位读作「下位/上位/G 通用矿石（或甲虫）素材」。

| LV | 英文名（JSON） | 攻击 | 配方档位 | 强化素材（chS） | 来源 |
|---|---|---|---|---|---|
| 1 | Petrified Blade 1 | 60 | 生产（无占位符） | 大地结晶 ×1 + 铁矿石 ×4 | `components`（`[I]`） |
