# HR 上限与等级解放（MHGU / MHXX）

> **本页能查到什么**
> 1. **HR1–HR12 的逐级阶梯**：每一级由**哪一条紧急任务**给出、同一条紧急还解锁什么（★ 星级 / G★ 星级），以及「HR = 已解禁到第几星」这条规则。
> 2. **HR 上限（cap）在哪解除**：G★4 最终任务「废墟之城」（阁螳螂）→ 公会下发「解除猎人等级上限的许可」→ HR 改由**猎人等级点数（HRP）**累积提升，上限 **999**。
> 3. **HRP 的量化**：全库 1,355 条任务的 HRP 分布（逐池逐档 Σ/最高），以及**为什么「每级需要多少 HRP」在本仓库里没有数值**（romfs / db / wiki / chS 文本四路否定证据）。
> 4. HR 门槛（承接条件 vs 出现条件）的分层索引与三个易错点；逐条门槛表见 [quest-requirements.md](quest-requirements.md) 与 [progression-unlocks.md](progression-unlocks.md) §6.2，本页**不重复**。

**三行结论**

1. **HR1–HR12 不是刷出来的，是打出来的**：每一条「星级入口紧急」把 HR 抬 1（唯二例外：集★6 要**两条**紧急一起完成；HR8 的那一步在官方文本里没有名字）。集★1–★7 的入口紧急 → HR1–HR7，G★1–G★4 的入口紧急 → HR9–HR12；**HR 数字 = 你已经解禁到第几星**（`npc_502 #10`、`npc_520 #23`）。
2. **「HR 解放」= 解除上限 = 打完阁螳螂**（G★4「废墟之城」q11432）。`npc_801 #90` 原句「公会已经对你下发了**解除猎人等级上限的许可**」，紧接着 `npc_802 #66/#67` 才解释「今后每完成任务，猎人等级点数就会增加，以此来提升 HR」。所以村★10 那 4 条要求「HR 解放后」的高难度，实际要的是**通关 G★4 最终战**。
3. **G 级的入口是「小试牛刀？」**（集★7，角龙 q10768）：完成即「许可你承接 G★1」并被「认可为 HR9」（`npc_801 #20/#21`）。这与 `progression-unlocks.md` §4 里「G★1 开放条件 wiki 未写 `[U]`」不冲突——那页没有 NPC 对话这一路来源，本页把它补上。

## 1. 先分清三个「HR 数字」

玩家问「我 HR 多少能打 X」时，三个数字经常被混为一谈：

| 数字 | 含义 | 数据位置 | 例子 |
|---|---|---|---|
| **承接条件 HR** | 点「承接」时的硬门槛（任务信息页「承接･加入条件」那一行） | `questData_<id>.ext` 的 `Requirement1/2`（文件 `+0x01A`/`+0x01B`） | G★1 全部 32 条 = HR9；EX 18 条 = HR100 · 见 [req§2/§4](quest-requirements.md) |
| **出现条件 HR** | 任务**在列表里出不出现** | 不在任务记录里；wiki 条件串 / main 侧谓词 | 村★10 四条终盘紧急 HR9+；G★4 的 HR35/40/…/100 |
| **HR 阶梯** | 你的 HR **怎么涨、卡在哪、上限多少** | 官方 NPC 对话（本页 §2–§3） | HR2 ← 集★2 紧急；HR9 ← 集★7「小试牛刀？」 |

- 三者是**不同字段/不同系统**。`Requirement` 枚举里**没有** HR35/40/70/80/90/95；HR20/25/30/45/50/60 虽有枚举值但本作 **0 条任务使用**；真正用到的最大值是 **HR13**（112 条）与 **HR100**（18 条，全是二名 EX）。见 [req§2](quest-requirements.md)、[req§6](quest-requirements.md)、[req§7](quest-requirements.md)。
- 官方文案也把两件事分开说：`CommonMsg #50` 只有「HR」两字；`npc_520 #23` 说的是「完成后 **HR 将会提升**，以后就可以承接高 1 个难度的任务」；`npc_129 #111`（`npc_130 #111` 同文）说的是「**猎人等级达到一定等级以上**的人才能接的任务海了去了」。

### 2.3 HR8 的两种读法 `[I]`

全部 NPC 台词里**没有任何「HR8」字样**：`grep HR[0-9]+` 扫 `chS/table/npc/script/*`（全部 NPC 台本）只命中 HR1/2/3/5/6/7/9/10/11/12，**没有 HR4 与 HR8**（HR4 只能由「上位猎人」推得，见 §2.2 注）。HR8 只能靠排除法定位：

- HR2–HR7 与 HR9–HR12 全部被 NPC 原句**点名**（§2.2）；
- 集★7 恰好有 **3 条紧急**（`2987.html`：千刃龙千刃龙 ← 集★6 关键全清；小试牛刀？与奈落的妖星 ← 集★7 关键全清），其中两条已分别对应 HR7 与 HR9；
- ⇒ 剩下的 **奈落的妖星 q10722** 是 HR7 与 HR9 之间唯一未被占用的紧急。
- 旁证：集★7 里有 **32 条任务要求 HR8**（`req§4.2`，req1=7），这些任务只受「集★6 狞猛化 ≥2 + HR8」约束（`2027`），说明 **HR8 必须在 G 级之前、集★7 内就能拿到**。

另一种同样自洽的读法：HR8 由「集★7 关键全清」这个事件直接给出（不挂在某条紧急上）。两种读法对玩家的差别很小（两条紧急都在同一时点出现），本页取前者并标 `[I]`。

> **对照记**：`progression-unlocks.md` §4 写「★7 三紧急全清 → G 级」是 `[I]`。本页把这一步细化成「**小试牛刀？**（角龙）单独即可开 G★1」（`npc_801 #20` 原句点名角龙）。奈落的妖星是否必须**先**打，官方文本没说 `[U]`。

## 3. HR 上限（cap）：在哪解除、解到多少

### 3.1 解除点 = G★4 最终战「废墟之城」（阁螳螂）

| 「**今后**，每当您完成任务的时候，『**猎人等级点数**』就会增加，以此来提升 HR」 | `npc_802 #66` | 从此 HRP 才驱动 HR |

### 3.2 上限值 = 999

| 证据 | 内容 |
|---|---|
| `KeyboardMsg #5/#6` | 集会所房间的 HR 过滤输入范围「（0～999）」——官方把 HR 当 0..999 的整数 |
| `GC_Title_1` 称号 | `RabbitName1_TXT_76` 起 =「**HR达到999**」；同文件 `name1_TXT_332` 也是「HR达到999」 |
| 称号里程碑 | 全表只有 **HR4 / HR8 / HR50 / HR100 / HR200 / HR500 / HR999** 七个「HR达到 N」称号（`GC_Title_1` name1_TXT_152–181 = HR4 ×30、182–211 = HR8 ×30、332 = 999；`RabbitName1_TXT_16–30` = 50、`_31–45` = 100、`_46–60` = 200、`_61–75` = 500、`_76` 起 = 999） |

- ⇒ **解除前可及的最高 HR = 12**（最后一个由紧急给出的 HR；`[I]`，依据「上限」语义与 §2.2 阶梯），解除后 0..999。解除前 HR 是否可能被 HRP 顶到 13：无文本、无数据 `[U]`。
- **注意 HR13 不是上限**：HR13 只是 `Requirement` 枚举里最大的**普通**承接门槛（112 条任务用它，主要是 G★4 与二名 G5），见 [req§2](quest-requirements.md)。

### 3.3 「HR 解放」这个说法

- 游戏内条件串写作「**HR 解放后**」（村★10 高难度 A 组 4 条：银阳不落 / 她是闪光的金火龙 / 出现在古代林的秘影 / 制止争吵拯救村庄，`2020` L251–307），NPC 文本写作「**解除猎人等级上限**」/「**上限开放**」。
- 两者是同一件事的最强证据：在 chS 全量文本内检索「上限」，与 HR 相关的只有 `npc_801 #90`、`npc_802 #65`、`npc_129 #110`（＋`KeyboardMsg #6` 的房间过滤文案）；「解放」作为 HR 用语只出现在 `2020` 的条件串里，而那是终盘内容，其门槛只能是终盘的 HR 状态。
- ⇒ **村★10 的「HR 解放后」= 已通关 G★4「废墟之城」** `[I]`（术语同一、时序自洽；无一句原文把两个词并列写死）。
- 由此得到一条不直观但可操作的结论：**村★10 的 16 条高难度里，A 组 4 条 + D 组 1 条（经 A 组继承）要求你先打完集会所 G 级最终 BOSS**；其余 11 条不要求（见 `prog§3.1`）。

### 3.4 存档转换会把 HR9+ 压回 HR8

`TitleMsg #61`（`Convert_Attention_005`，存档继承注意页）原文：

> 以下内容仅能继承一部分：･猎人等级点数 ･HR ※会作为勋章保留。
> **猎人等级点数会根据 HR 重置为一定数值。此外，HR 为 9 以上时，将重置为 HR8。**

- 读法 `[I]`：**HR8 是「前作（MHX）故事线的顶点」**，HR9 以上属于 G 级追加段，转换时不能带走 ⇒ 压回 8，由玩家在 MHGU 里重打 G★1–G★4 的紧急。
- 这也反证了本页阶梯 `[I]`：HR9–HR12 是 **MHXX 新增的 G 级段**，HR1–HR8 是 MHX 原有的故事段（与「集★7 内已有 32 条 HR8 任务」互相印证）。
- 转换同时「按 HR 重置 HRP 为一定数值」⇒ 代码里存在 HR↔HRP 的定值映射 `[I]`（该表本页未取到，见 §6）。

## 7. HR 门槛索引与三个易错点（不重复既有页）

**逐条门槛表**在这里：[req§4.2](quest-requirements.md)（逐星级承接条件）、[req§2](quest-requirements.md)（50 值枚举与计数）、[prog§6.2 表 C](progression-unlocks.md)（出现条件侧的 HR35–HR100 等）。本页只给「哪一档要求几」的一句话索引：

| 内容档 | 承接门槛 | 出现门槛 |
|---|---|---|
| 集会所 下位 ★1–★3 | 无条件（★3 仅 1 条 HR3） | ★N 开放后 |
| 集会所 上位 ★4–★6 | **HR4**（★6 有 1 条 HR8） | ★N 开放后 |
| 集会所 上位 ★7 | HR4 / **HR7**×4 / **HR8**×32 | MHXX 追加族另需「集★6 狞猛 ≥2」 |
| 集会所 G★1–G★3 | **HR9** | — |
| 集会所 G★4 | HR9×30 / HR12×1 / **HR13**×55 | HR35/40/45/50/60/70/80/90/95/100 逐条（不在任务记录里） |
| 二名 I–III → EX | HR2 → HR4–8 → HR9–13 → **HR100**（EX 18 条） | 逐关链式 + 4 只首关另需 HR2 |
| 村 ★1–★10 | 全部无条件 | HR9（★10 四条终盘）、「HR 解放后」（★10 高难度 A 组 4 条） |

**易错点**

1. **承接条件 ≠ 出现条件**：G★4 的 55 条任务写「HR13 以上」，但 wiki 给它们的出现门槛是 HR35–100。两个数字都真，只是不同字段（`req§7`）。
2. **HR13 不是上限，HR100 也不是「满级」**：上限 999（§3.2）。HR100 只出现在 18 条二名 EX 的承接条件里，是终盘内容门槛。
3. **条件串读法（否则整表错位一行）**：镜像 wiki 每条任务的「出现条件」写在**自己面板的末尾**（raw HTML 实证：`2016.html` 的 quest238203「兜帽在溪流！」面板内 = 「委托★坦吉亚港看板娘的委托2 + HR5 以上」；quest238204「黑狼鸟降临」面板内 = 「委托★顿多尔玛守护兵的委托1 + HR5 以上」；`2987.html` 的 quest229753「千刃龙千刃龙」= 「集★6 的关键任务全部完成之后」）。展平成 `text/*.txt` 后，条件行仍落在本任务的地图行之后、**下一条任务名之前**，所以「条件在前、任务在后」的读法会整体错位一行。`prog§6.2` 表 A 的配对与面板一致（本页抽查 兜帽在溪流 / 黑狼鸟降临 / 一对的巨影 三行全对）。

## 10. 复现

**① 阶梯任务与 HRP（SQL，`docs/data/mhgu.db`）**

```sql
SELECT q._id, q.name, q.stars, q.rank, q.hrp, m.name
FROM quests q
JOIN monster_to_quest m2q ON m2q.quest_id = q._id
JOIN monsters m ON m._id = m2q.monster_id
WHERE q._id IN (10216,10307,10335,10531,10606,10608,10710,10722,10768,11204,11319,11401,11432)
ORDER BY q._id;

-- 逐池逐档 HRP 总量
SELECT hub, rank, COUNT(*) n, SUM(hrp) total, MAX(hrp) mx
FROM quests GROUP BY hub, rank ORDER BY hub, rank;

-- 逐星（集会所）
SELECT stars, COUNT(*) n, SUM(hrp) total, MAX(hrp) mx
FROM quests WHERE hub='Guild' GROUP BY stars ORDER BY stars;
```
