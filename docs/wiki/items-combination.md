> 证据级：`[C]` = romfs 字节并已交叉核对 ｜ `[B]` = 单一百字节级来源 ｜ `[X]` = 两源冲突 ｜ `[W]` = wiki 文本 ｜ `[U]` = 未知。

## 0. 数据源、表结构与校验

| 记号 | 含义 |
|---|---|
| `db:<n>` | `MHGU/docs/data/mhgu.db` 的 `items._id`。`items` 表共 **21,153 行**（还含装备等，`_id` 最大到 1,966,417），其中只有 **2,866** 行的 `_id ≤ 2990`；落在这段里时 `_id` 同时就是 romfs `nativeNX/table/itemData.itm` 的记录下标（该表 2,991 条记录；`chS` 名表 5,982 串 = 2 × 2,991）。本页用到的 id 最大 2,060，全在该区间内 |
| `r<n>` | `mhgu.db.combining._id`，同时 **= `itemPreData.itp` 的第 `n−1` 条记录**（本页 §2 的行号列） |
| `chS:<n>` | 官方中文 `nativeNX/chS/table/itemData_chS.gmd` 的槽位 **2×id**（名称）。本页写成「道具名（id）」，id 即 `db:` = `chS` 槽位号减半 |
| `2503` `2506` `2615` `2201` | MHXX wiki 文本页 `docs/reference/mhxx-wiki/text/<n>.txt` |

**配方表落点**：`<romfs>/nativeNX/table/itemPreData.itp`，**4,400 B = 8 B 头 + 183 × 24 B 记录**（尺寸闭合）[C]。

| 偏移 | 类型 | 字段 | 依据 |
|---|---|---|---|
| 0x00（文件头） | f32 | 版本 **21.3**（字节 `66 66 AA 41`） | [C] 原始字节 |
| 0x04（文件头） | u32 | 记录数 **183**（`B7 00 00 00`） | [C] 原始字节 + 尺寸闭合 |
| +0x00 | u16 | 记录序号 `0..182`（与 `r−1` 一一对应） | [C] 183/183 连续 |
| +0x02 | u32 | 素材 1 的道具 id | [C] 与 db `item_1_id` 全等 |
| +0x06 | u32 | 素材 2 的道具 id | [C] 与 db `item_2_id` 全等 |
| +0x0A | u32 | 结果道具 id | [C] 与 db `created_item_id` 全等 |
| +0x0E | u8 | 成功率（55/65/75/90/95/100） | [C] 与 db `percentage` 全等 |
| +0x0F | u8 | 个数字节：**bit0–1 = 个数 − 1**（183/183 成立）；bit2–3（取值 0..3）语义未定。实测取值分布 `0×131 1×2 2×1 3×7 4×3 6×4 9×24 10×5 11×2 12×1 13×1 14×1 15×1` | [C] bit0–1 / [U] bit2–3 |
| +0x10..+0x17 | 8 B | 几乎全 0（+0x13 有 18 行非零、+0x17 有 3 行非零），语义未知 | [U] |

**校验（全表，非抽样）**：脚本逐条比较 `.itp` 记录 `r−1` 与 db `combining` 的 `_id = r`，比对 `(素材1, 素材2, 结果, 成功率)` 四个字段 ⇒ **mismatch 0 / 183**；序号连续、所有 id ∈ 0..2990 [C]。
成功率的直方图两侧完全相同：`55:8 / 65:13 / 75:33 / 90:44 / 95:30 / 100:55` [C]。
第二遍校验反向做：从本页 183 行表格里重新解析出 `(结果, 素材1, 素材2, 个数, 成功率)`，逐行对着 `.itp` 字节与 `chS` 名称表验 ⇒ **183/183 行全部通过，缺失 0、重复 0、问题 0**（含名称逐字比较）。
校验用的副本是 `.tmp/mhgu/extract/itemPreData.itp`（4,400 B）；脚本已断言它与 romfs 原件 `<romfs>/nativeNX/table/itemPreData.itp` **逐字节相同**（`copy identical: True`），所以上面的每一条对拍都是对 romfs 原表的对拍 [C]。

- 表的所有者是二进制里的 `cItemPreBase`（`0x1897e8`，`cItemPreBaseXML` 序列化器在 `0x1898a8`）；调合 UI 另有 `cMix` / `cMixBox`（`0x18be68`）与 `cMixList` / `cMixListBox`（`0x18e330`）`[B]`（`docs/analysis/code/batchA-classname-xref.md:184-188`）。「这四张表在启动时由这些类读入」是 `[I]`。
- 同族还有 `itemPreTypeData.ipt`（16 × 8 B = 136 B）；它是否给配方分类、如何与 183 条对应，仓库内无证据 `[U]`。

## 1. 规则

| 项 | 值 | 出处 |
|---|---|---|
| 输入 | 恰好 2 个素材（记录里就是两个固定槽位） | [C] 表结构 |
| 输出 | 1 种结果道具；183 条里没有一条是「1 进 2」 | [C] |
| 个数 | 1 / 2 / 3 / 4（分布见 §3）；增殖类固定 2–3 | [C] |
| 成功率 | 6 档：55 / 65 / 75 / 90 / 95 / 100 % | [C] |
| 素材左右顺序 | 两样放左放右结果相同 | `[U]`：表里只存一对固定槽位，`2503` 是纯配方列表、没有规则文字，无源可引 |
| 成功率加成 | 猫之调和术【小】+10%、【大】+20% | `[W]` `2506:202`、`2506:207` |
| 完全调合（狩技，波克村） | 一定时间内大幅提升调和成功率，**产量满额**（官方 chS 文本） | `[B]` `styles-arts.md:179` |
| 特定配方必成功 | 猫之善使异臭球术 → 异臭球；爆破手 10pt → 爆弹类 | `[W]` `2506:142`、`2201:324` |
| 解锁 | 调和书1入门篇 / 2初级篇 / 3中级篇 / 4高级篇 / 5达人篇（`db:1-5`），买价 1000 / 2000 / 5000 / 10000 / 15000 z | `[C]` `2615:165-174` 与 `db:1-5` 的五档价格逐值一致 |
| 书覆盖哪些配方、每本加多少成功率 | 表里没有「所需书等级」字段 | `[U]` |

> 官方 chS 名是「调和书」而不是「调合書」；本页其余地方用「调合」指机制本身，道具名一律照抄官方文本。

## 4. 冲突与待确认

1. **个数的三源不一致 `[X]`**。`db.combining.amount_made_*`（Kiranico 系）、`.itp +0x0F` 的 bit0–1（= 个数−1）、wiki `2503` 的「个数」列三者只能两两对上：
   - `r71` LV2通常弹：db **1**，`.itp +0x0F` = `0x04`（bit0–1 = 0 ⇒ 1），wiki **2-4**。
   - `r73` LV1贯穿弹：db **4**，`.itp +0x0F` = `0x03`（bit0–1 = 3 ⇒ 4），wiki **1-3**。
   - `r141` 铁矿石增殖：db **3**，`.itp +0x0F` = `0x06`（bit0–1 = 2 ⇒ 3），wiki **5**。
   ⇒ 本页取 db，因为 `.itp` bit0–1 与它 183/183 一致（两个独立来源）；wiki 的区间数与两者都不等。
2. **`.itp +0x0F` 的 bit2–3 `[U]`**：取值 0..3，与 db 个数无一一对应（位值 3 的 4 行里 db 个数分别是 1/2/3/4；位值 1 的 7 行、位值 2 的 31 行、位值 0 的 141 行）。它看起来是另一个维度（可能是配方类别或 UI 分组），本页不采信任何解释。
3. **`.itp +0x13`（18 行非零）与 `+0x17`（3 行非零）`[U]`**：语义未知，本页不引用。
4. **调和书覆盖面 `[U]`**：表内没有「所需书等级」字段，wiki 也没给每本覆盖哪些配方、每本加多少成功率；只有价格可证（1000/2000/5000/10000/15000 z）。
5. **失败处理 `[U]`**：「素材消耗、无产出」只是常见说法，本页找不到源：表里没有失败分支/损失字段，`2503` 是纯配方列表（没有规则文字）。
6. **增减益后的成功率上限 `[U]`**：+10%（猫之调和术【小】）、+20%（【大】）、特定配方强制 100%——三者叠加是否封顶 100%、以及「完全调合」把产量拉到多少，仓库内没有数值。
7. **大生命粉尘（32）没有配方**：183 条的三列 id 里都没有它 `[C]`；它的获取途径只有任务报酬/支给（`items-combat.md` §13-4）`[I]`。这里**没有源冲突**，写出来只是玩家须知。
