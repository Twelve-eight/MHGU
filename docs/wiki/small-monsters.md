# 小型怪物数据（MHGU / MHXX）：体力、肉质、异常记录与剥取

> **三行导读**
> 1. 本页覆盖**全部 43 个小型怪物单元**（槽 71–111、135、136）：官方简中名、基础体力、逐行肉质（斩 / 打 / 弹 / 火 / 水 / 冰 / 雷 / 龙 / 气绝 9 列）、异常阈值记录、剥取素材。
> 2. 数值的**唯一来源**是每个单元自己的 `romfs/nativeNX/arc/enemy/emsNNN_00.arc :: enemy\dt_tune\emsNNN_00_dttune`（解开后 316–664 B）。`mhgu.db` 对小怪**没有任何**体力 / 肉质 / 异常 / 弱点行（`monster_damage`、`monster_status`、`monster_ailment`、`monster_weakness` 四表的小怪行数均为 **0**），只有名录 `monsters`（36 行，`base_hp` 全 0）和剥取表 `hunting_rewards`。
> 3. 因此本页**没有 [C] 级数值**：单源字节读出一律记 **[B]**；数据形状与列序按大怪同格式推定、但无第二源可对拍的部分记 **[I]**；部位名、>100 的肉质值、占位单元语义等记 **[U]**。

**证据等级（本页专用）**

| 标签 | 含义 | 本页用在哪 |
|---|---|---|
| [B] | 单一字节级来源，逐值从 romfs 读出（无 db 可对拍） | 体力、肉质各值、异常记录数值、剥取（hunting_rewards 单源亦然） |
| [I] | 结构/顺序的推断（依大怪同格式），数值本身仍是 [B] | 肉质列序、异常记录 → 状态名的对应 |
| [U] | 未解 / 不可断言 | 肉质行的部位名、>100 的肉质值含义、`dummy1–7` 占位单元、肉质表后的 u32 |

## 1. 数据在哪、怎么读

### 1.1 文件

```
<romfs>/nativeNX/arc/enemy/emsNNN_00.arc            ← ARC 容器（v0x11）
  ├─ enemy\dt_tune\emsNNN_00_dttune                 ← 本页主数据，typeHash 0x48e8ac29
  ├─ enemy\dt_base\emsNNN_00_dtbase                 ← 194–280 B，本页未用
  ├─ enemy\dt_base\emsNNN_00_dtbparts               ← 77–136 B，本页未用
  └─ enemy\hagi\hagi_s0..s4_emsNNN_00               ← 5 张剥取表，346 B / 张，typeHash 0x33a84e14（ems100–106 无此成员）
```

- 单元 ↔ 怪物：小怪 `db_id = 4096 + unit_no`，`emid` 与槽号取自 `docs/data/json/monster-slot-map.json`（43 行 `kind: small`）`[B]`。
- 43 个单元都有 `dt_tune`；**36 只有名小怪**另带 **5 张 hagi**（`hagi_s0..s4`，346 B / 张；个别张为空表，如 ems044 的 `hagi_s0` 解析出 0 条）`[B]`；7 个 `ems100–106` 既**没有 hagi**（`hagi: []`），`dt_tune` 也只有 316 B（无肉质实槽、无异常记录，见 §5）。

### 1.2 `dt_tune` 的固定与浮动部分

| 偏移 | 内容 | 证据 |
|---|---|---|
| `+0x00` | 魔数 `DTT\0` + `6C A0 33 01`（与大怪完全相同） | [B] |
| `+0x08`–`+0x37` | 0/1 标志区（逐单元不同） | [B] 结构 |
| `+0x38` | **u32 基础体力**——与大怪「唯一定长字段」同偏移 | [B]（小怪无 db 对拍） |
| `+0x3C` | u32 未知小整数（60 / 1 / 150 / 300 …） | [U] |
| `+0x40`–`+0x8B` | 8 条 × 10 B 的部位记录，形如 `00 00 FF FF id u16 …`（ems001 只有 id=2 一条非零） | [B] 结构，语义 [U] |
| `+0x8C` 或 `+0x8E` | **肉质表起点**（见下） | [B] |
| 肉质表之后 | 一个小 u32（0–3，语义 [U]），随后是 f32 调参块（多数单元锚定在 `+0xE6`，ems045 盾虫在 `+0x136`） | [B] 位置 / [U] 语义 |
| 尾部 | 6 × u16 的**异常记录**，逐单元偏移不同（§3） | [B] 数值 / [I] 名称 |

**肉质表**：8 行 × 10 B，每行 `9 × u8 + 1 填充字节`，9 列依次为

```
斩(cut) 打(impact) 弹(shot) 火(fire) 水(water) 冰(ice) 雷(thunder) 龙(dragon) 气绝(ko)
```

- 列序与大怪同表（`docs/reference/formats/dttune.md`），本页沿用；位置证据：末两字节恒为「气绝值 + `0x64`」，龙列在气绝前；属性列先后与大怪一致 `[I]`。
- **未使用的槽位整行填 `0x64`(100)**，故实槽行数 = 表首连续的非整 100 行数（1–3 行，见 §2）。
- 表起点在 43 个单元里只有两种：`0x8C`（40 个）与 `0x8E`（ems004 蘑菇猪、ems023 雪狮子、ems048 云羊鹿）。
- 行内数值**可以超过 100**（ems004 150/150/120、ems005 打 120、ems020/021 打 110 且第 9 列 200），与大怪 0–100 的肉质百分比不同 ⇒ 数值本身 `[B]`，**换算方式 [U]**。
- 小怪的肉质行**没有部位名**（大怪的部位名来自 `monster_damage`，小怪无该表）⇒ 本页只标「行 1 / 行 2 / 行 3」，行内先后见 §5 `[U]`。
- **ems045 盾虫有两组 8 × 10 表**（`0x8C` 首行 `0A 17 1E 0A…`、`0xDC` 首行 `50 50 50 32…`），且前一组行尾填充是 `0x0A` 而非 `0x64`；哪一组是常态未定 `[U]`。

## 3. 异常阈值记录

小怪 `dt_tune` 尾部有 6 × u16 的记录块，形状与大怪完全相同：

```
u16 初始值(initial) | u16 A | u16 B | u16 时长(帧) | u16 递增(increase) | u16 上限(max)
```

- 记录顺序按大怪 spec 推定为 **毒 → 眠 → 麻痹 → 气绝** `[I]`；小怪没有 db 行可对拍，**状态名与记录的对应未经证实**，本页只发布记录本身 `[B]`。
- 时长 = 帧 / 60 秒（3600 = 60 s、2400 = 40 s、1800 = 30 s、900 = 15 s、720 = 12 s、600 = 10 s、300 = 5 s、2700 = 45 s、0 = 瞬时）。
- 小怪的 `A` 恒为 150 的整数倍（150 / 300 / 600 / 900 / 1200），`B` ≤ 20；大多单元 4 条记录，少数 3 条；`ems100–106` **没有任何记录**（全为 0 或哨兵）`[B]`。
- 每格格式：`偏移 = 初始/A/B/帧/递增/上限`。
