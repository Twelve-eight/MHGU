# 怪物肉质（打击部位）数据

> 3 行导读：本页给出 MHGU 肉质数据（斩/打/弹 + 火/水/雷/冰/龙/气绝，共 9 列）在游戏 ROM 里的真实存放位置与格式，并附 10 只代表性怪物的完整数据表（含愤怒/带电/积雪等状态行）。数值直接从 RomFS 的 `*_dttune` 文件逐字节解出，与机读库 `monster_damage` 逐值对拍；两源不一致处以 RomFS 为准（本作 GU 版对旧数据有再平衡）。文末附解码方法，可照此扩展到其余大型怪物。

**数值含义**：所有肉质为**伤害百分比**（伤害 = 武器值 × 动作值 × 肉质/100 × …），`0` = 该攻击/属性完全无效。`气绝` 列 = 该部位受到打击系攻击时的眩晕积蓄百分比，仅头部等少数部位非 0。

官方简体怪物名取自 `chS/arc/resident_chS.arc :: chS\GUI\06_msg\monsterName_chS`（槽位序，本文引用格式 `monsterName_chS #槽号`）。

---

## 1. 数据存放在哪里

每只大型怪物的调参数据打包在自己的资源档里：

```
<romfs>/nativeNX/arc/enemy/emNNN_00.arc        ← ARC 容器（zlib 载荷）
  └─ enemy\dt_tune\emNNN_00_dttune             ← 条目 typeHash 0x48e8ac29
```

`emNNN` 与怪物的对应关系：`em id = mhgu.db monsters._id`（1..88 段），权威对照表为 `docs/data/json/monster-slot-map.json`（137 槽）。样本核对：em001=雌火龙、em002=火龙、em032=轰龙、em037=迅龙、em057=雷狼龙、em063=碎龙、em080=斩龙、em081=电龙、em082=泡狐龙、em083=巨兽 `[B]`（按体型表逐槽比对，另见 `docs/analysis/monsters/mon-em-units.md`；注意 `docs/reference/formats/mod.md` 中「Rathalos em001」的旧注记是错的）。

`*_dttune` 内与本页相关的字段：

| 文件偏移 | 内容 | 证据等级 |
|---|---|---|
| `+0x00` | 魔数 `DTT\0` | [C] |
| `+0x38` | u32 基础体力（HP） | [C]（10 样本中 7 只与 db `base_hp` 逐字节一致；碎龙/斩龙/巨兽 3 只不一致，见 §2 注） |
| `+表起点`（逐怪不同，多为 `0x8E`） | 肉质表，每行 10 B | [C] |

怪物间**表起点会漂移**：em001/002/032/037/081/082/083 = `0x8E`，em057/080 = `0x8F`，em063 = `0x99`。因此定位肉质表不能背偏移，要用「已知行字节匹配」锚定（见 §4）。

## 2. 肉质表格式（供扩展）

- 每行 **10 B = 9 × u8 + 1 填充字节**，9 个值依次为：

  ```
  斩(cut) 打(impact) 弹(shot) 火(fire) 水(water) 冰(ice) 雷(thunder) 龙(dragon) 气绝(ko)
  ```

  列序证据：与 `monster_damage.json` 的 417 行在 `表起点 + 10k` 处逐字节一致（67/93 只怪可整体对上）；列内属性顺序由巨兽（火 10/水 0/冰 0/雷 15）与电龙尾尖（水 12/冰 20 的 10/12 组合）唯一判定 `[C]`。行尾填充字节在常态行读作 `0x64`(100)，语义未定 `[U]`。
- 行按 **8 行一组** 组织：第 1 组 = 常态肉质；后续组 = 状态肉质（愤怒、带电、积雪、加热……逐怪不同）。组内**未使用的槽位整行填 `0x64`**，实槽行数 ≤ 8；本体只有 7 个部位、且无状态组的怪（雌火龙/火龙）在最后一行出现整行 `0x64` 分隔 `[B]`。
- 状态组与游戏状态的对应（哪一组在何时生效）在数据里没有显式键名，本页标签由 `monster_damage.json` 的 `部位 (状态)` 后缀逐行对拍得出 `[I]`。
- 一个槽位可对应多个部位名（左右脚分开但数值相同），下表已合并写法。

> **与第三方机读库的差异**：`mhgu.db`/`monster_damage.json` 来自 MHGenDatabase v2.4.0（非官方数据）。对拍中 3 处不同，RomFS 为游戏真实值：雷狼龙常态尾尖 打 19→**20**；碎龙/斩龙/巨兽的 `+0x38` 基础体力分别比 db 低 100/100/400（GU 再平衡）。

## 4. 解码与扩展方法

```bash
# 1) 解包某怪的 dttune（ARC 容器 → zlib）
node MHGU/tools/mhgu/arc.mjs extract <romfs>/nativeNX/arc/enemy/emNNN_00.arc <outdir> "dt_tune"

# 2) 用已知部位行做 9 字节锚点定位表起点，再按 10 B 步长读行
#    脚本（工作区暂存，未入库）：
node .tmp/mhgu-scratch/scan-meat.mjs 1 2 32 37 57 80 83     # 逐行字节匹配 db
node .tmp/mhgu-scratch/dump-matrix.mjs 57 80                # 打印 10B 行矩阵 + db 标注
```

扩展步骤：(a) 从 `monster-slot-map.json` 取 em id 与官方名；(b) 解包 dttune；(c) 用该怪 db 各行的 9 字节模式在文件中扫描（首个命中 = 表起点）；(d) 从表起点按 10 B 读行、8 行一组，遇到整行 `0x64` 即组间分隔；(e) 组 2 起的状态标签用 db 的 `(状态)` 后缀行对拍。批量解全 93 只时注意：**表起点与组数逐怪不同**，不能沿用 `docs/reference/formats/dttune.md` 的固定「8 行 @0x8E」假设（该假设对 em057/080/063 会错位，见 §1）。
