# 弩炮弹药、弓瓶与箭种（MHGU 1.4.0 / MHXX）

> 面向玩家：32 种常规弩弹 + 41 种武器内藏弹（官方中文名）、每把轻/重弩炮的装填数从哪张字段读、后坐/装填/弹道偏移三张枚举、轻弩速射与重弩蹲射的表、弓箭 4 段蓄力（连射/贯穿/扩散/重射）与 12 种瓶。
> 每条数值都带出处标记；本库拿不到的一律标 `[U]`，不写成"事实"。
> **中文名一律取官方 chS 文本**（`chS/table/*.gmd`）**逐字不改**；英文名是第三方库 `mhgu.db` 的写法，只用于对号。

读表要点：

- **命名口径**：本页一律用**官方 chS 名**（`itemData_chS` 逐字）。镜像 wiki 用的是日文汉字写法（例：`徹甲榴弹` 对应官方 `穿甲榴弹`、`接击瓶` 对应官方 `近战瓶`，见 `docs/reference/mhxx-wiki/text/1912/1913/2201.txt` `[W]`）；统一映射由 `MHGU/docs/data/folk-names.json` 落地后由页面负责人替换，本页不手工改名。

- **槽 0–14 对所有弩炮都非 0**：每一把轻弩/重弩炮（703 + 718 = 1421 把）都能装填通常/贯穿/散弹/穿甲榴弹/扩散弹的全部 3 个等级 `[C]`。这是本页最强的结构不变量，也是识别槽位顺序的第一把尺子。
- **槽 15–29（属性弹与状态弹）才是差异所在**：火炎弹 310/703 把轻弩可装、灭龙弹只 148/703。槽 15–29 上**所有非 0 值都带 `*`**（`*` 数 = 可装数），带 `*` 与否不是"可装/不可装"。
- **槽 30/31 恒为 2**：捕获用麻醉弹与染色弹每把弩炮的装填数都是 2 `[C]`（wiki 树页同值 `[W]`）。
- **槽序 ≠ 道具 id 序**：道具表里是 `130 染色弹`、`131 捕获用麻醉弹`，而 `ammo` 里是「捕 → 染」。`StartMenuMsg_chS #334 捕获 / #335 染色` 与 `ammo` 一致 `[B]`。
- **LV1通常弹携带上限 = 1** 是游戏表原值（`.itm mMaxCount`），官方说明写「弹量无限」——它实际不进背包 `[B]`。

### 2.3 三个格式坑

1. **最后一个分隔符缺失**：全部 1421 把弩炮的 `ammo` 都以 `…|2*3*|` 结尾，即槽 31（染色弹）= `2*`、槽 32 = `3*`，两者之间没有 `|`。按 `split("|")` 得到 32 段，最后一段是 `2*3*`；按 `[0-9]+` 抓数字则得到 33 个数。解析时必须专门处理。
2. **槽 32 恒为 `3*`**（1421/1421）：`3` 是常数，不是任何一把弩炮的装填数，也没有任何槽位能与之对应 `[U]`。
3. **`*` 后缀语义未解码**：见下。

### 2.4 `*` 后缀：已排除的两种解释

| 假说 | 反例 | 结论 |
|---|---|---|
| `*` = 该弹出现在 `db:weapons.rapid_fire` 里（速射/蹲射对应） | 飞雷弩（轻弩）有 **13** 个带 `*` 的槽，`rapid_fire` 只写 `Thunder S Lv1:3:70:0` 一条；重弩 355331 有 **14** 个带 `*` 的槽，蹲射列表只有 3 条 | **不成立** `[C]` |
| `*` = 该弹可装填 | 飞雷弩槽 2（LV3通常弹）= `7` 无 `*`，但它确实能打（wiki `通 6 6 7`） | **不成立** `[C]` |
| `*` = 需装填数 UP 才能达到该发数 / 该槽受装填数 UP 影响 | 无法证伪：槽 15–29 的非 0 值 **全部**带 `*`，槽 0–14 混有带/不带 | **未定** `[U]` |

可核对的实测分布（每槽带 `*` 的武器数，见 §1 最后两列）：槽 0、30、31 恒带（703/718）；槽 1–14 的带 `*` 比例从 98%（槽 1，690/703）一路降到 29%（槽 11，201/703；重弩最低在槽 14 = 188/718 = 26%）；槽 15–29 一旦非 0 就必带。

### 8.3 `coatings` 位掩码：已知与未知

`db:weapons.coatings` 是整数位掩码（735 把弓）`[C]`：

| 位 | 置位的弓数 | 备注 |
|---|---|---|
| bit0 (&1) | **735（全部）** | 最低位恒 1；本页无法定位它对应哪个瓶 `[U]` |
| bit1 (&2) | 91 | |
| bit2 (&4) | 261 | |
| bit3 (&8) | 277 | |
| bit4 (&16) | 341 | |
| bit5 (&32) | 408 | |
| bit6 (&64) | 556 | 次高频 |
| bit7 (&128) | 177 | **置位的 177 把全部是属性弓**（177/177） |
| bit8 (&256) | 236 | **置位的 236 把全部是属性弓**（236/236） |
| bit9 (&512) | 328 | |
| bit10 (&1024) | 418 | |

- 取值范围 1–1913，**11 位**；735 把弓共出现 ≥60 种不同取值 `[C]`。
- **结构性发现**：bit7 / bit8 只在「有属性的弓」上出现（无属性弓 329 把，一把都没有这两位），其余 9 位与属性无关（各位置位者中属性弓占比 36%–62%，基线 55%）。因此 bit7/bit8 几乎肯定是**属性系瓶（属性强化瓶 / 强属性瓶）**的开关 `[I]`。

- 「道具 id 顺序 = 位序」的假说被否掉：若 bit2/bit3 = 属性强化 LV1/LV2，应满足 bit3 ⊆ bit2，实测有 **136** 把弓置 bit3 而不置 bit2 `[C]`。
- **位 ↔ 瓶名的对应仍未解码 `[U]`**；可用的约束就是上面这张频次表 + 「bit7/bit8 只出现在属性弓上」。

## 10. 未确认 / 缺口（不要当结论用）

1. **`ammo` 的 `*` 语义 `[U]`**：已排除「速射对应」与「可装填」两解（反例见 §2.4），剩余候选（装填数 UP 相关标记）无法用现有字节证伪。
2. **`ammo` 第 33 个数恒为 `3*` `[U]`**：1421/1421 相同，与任何弹种容量都不符；且与第 32 个数之间缺分隔符（数据导出缺陷）。
3. **`coatings` 位 → 瓶名 `[U]`**：只知道 bit7/bit8 是属性系，bit0 恒置位，其余 8 位无对应；`equipment.md` 与 `weapons-overview.md` 的「位序未定」仍然成立，本页只补了频次与属性相关性。
4. **`bgsd` 两列语义 `[U]`**、**`squs` 的 class 语义 `[U]`**、**`tams` 单条空记录 `[U]`**。
5. **内藏弹 shotId（32–73）与 41 个道具 id 的完整映射 `[U]`**：只钉住 6 个（§6.1）。另外 `mhgu.db` 出现 40 个英文内藏弹名 ↔ 41 个道具 id，缺一。
6. **灭龙弹口径冲突 `[X]`**：官方说明写「寻常轻重弩炮甚至无法装填」，但 `db` 里 148/703 把轻弩、121/718 把重弩的槽 19 > 0。可能是「需特殊条件/内藏」或 db 的槽 19 并非灭龙弹的另一种表现，未定。
7. **每发弹的威力 / 命中数 / 会心距离 / 属性值 `[U]`**：`items` 与官方说明都不给绝对值；候选载体是 `rHitDataShell` 与 `bgsd`，均未解码。本页因此**不排弹种强弱**。
8. **速射的后坐力与偏移修正 `[U]`**：wiki 只说「后坐力减轻技能对速射无效」`[W]`，速射自身的后坐档位无数据。
9. **蹲射的「发数」口径 `[U]`**：`rapid_fire`（重弩）给出可蹲射弹种与一个 5–15 的数字，本页按「一次蹲射的发数」理解 `[I]`，没有字节验证；`squs` 的 `class` 与它数值有重合但逐把对不上。
10. **Lv1 通常弹携带上限 = 1 与「弹量无限」的矛盾**：表值如此，机理解释未验证（推测它不进道具袋）。

## 11. 复现（Python，路径参数化）

```python
import sqlite3, json, struct, sys

DB = r"MHGU/docs/data/mhgu.db"
AMS = ["通常","通常","通常","贯穿","贯穿","贯穿","散","散","散","穿甲榴","穿甲榴","穿甲榴",
       "扩散","扩散","扩散","火炎","水冷","电击","冰结","灭龙","毒","毒","麻痹","麻痹",
       "睡眠","睡眠","减气","减气","回复","回复","捕获","染色"]
LV  = ["1","2","3","1","2","3","1","2","3","1","2","3","1","2","3","1","1","1","1","1",
       "1","2","1","2","1","2","1","2","1","2","",""]

def parse_ammo(s):
    """返回 (装填数列表33, 是否带*列表33)。'2*3*' 这种缺分隔符的尾段按两个数处理。"""
    toks = [t for t in s.split("|") if t != ""]
    caps, stars = [], []
    for t in toks:
        if t == "2*3*":                       # 槽31+32 粘连
            caps += [2, 3]; stars += [True, True]
        else:
            stars.append(t.endswith("*"))
            caps.append(int(t.rstrip("*")))
    return caps, stars

con = sqlite3.connect(DB)
rows = con.execute("SELECT _id, wtype, ammo FROM weapons WHERE wtype IN (?,?)",
                   ("Light Bowgun", "Heavy Bowgun")).fetchall()
for _id, wt, ammo in rows[:3]:
    caps, stars = parse_ammo(ammo)
    assert len(caps) == 33, (_id, len(caps))
    print(_id, wt, [(AMS[i] + "LV" + LV[i], c, "*" if stars[i] else "") for i, c in enumerate(caps)][:8])

# 结构不变量：槽 0-14 与 30 对所有弩炮非 0；槽 31 恒 2*，槽 32 恒 3*
for _id, wt, ammo in rows:
    caps, _ = parse_ammo(ammo)
    assert all(c > 0 for c in caps[:15]) and caps[30] > 0
    assert caps[31] == 2 and caps[32] == 3

# 官方中文名（道具 id → 名字）
gmd = json.load(open("MHGU-private/romfs-extract/gmd/table/itemData_chS.gmd.json", encoding="utf-8"))
name = lambda i: gmd["strings"][2 * i]["text"]
assert name(100) == "LV1通常弹" and name(204) == "鬼人硬化弹" and name(211) == "LV2属性强化瓶"

# raps：f32 版本 + u32 条数 + 每条 {shotId, 发数, 攻击%, 属性}
b = open(sys.argv[1], "rb").read()             # nativeNX/table/rapidshotData.raps
ver, n = struct.unpack_from("<fI", b, 0)
assert abs(ver - 0.6) < 1e-6 and n == 55 and len(b) == 8 + n * 4
recs = [struct.unpack_from("<BBBB", b, 8 + 4 * i) for i in range(n)]
assert recs[0] == (74, 0, 0, 0)               # 哨兵
assert recs[1] == (0, 5, 80, 0)               # Normal S Lv1:5:80:0
assert recs[4] == (3, 3, 70, 0)               # Pierce S Lv1:3:70:0
assert recs[12] == (12, 2, 70, 3)             # Clust S Lv1:2:70:3
assert all(r[0] <= 73 for r in recs[1:])      # shotId 空间 0..73
```
