# 动作值（近战其二）：大锤 / 长枪 / 铳枪 / 狩猎笛

本页给出 **4 把近战武器**（大锤 `w02`、长枪 `w03`、铳枪 `w09`、狩猎笛 `w12`）在 romfs 命中数据里的
**每一条记录的动作值**，并附**官方中文招名**与按键、官方机制文本，以及能通过结构校验的**候选归属**。

配套页：`motion-values.md` 给资源格式与**大剑 / 太刀**全表；其余近战武器（大剑/太刀/单手剑/双剑、
斩击斧/盾斧/操虫棍）与射手武器由同批页面覆盖。武器号 ↔ 武器名的双证见 `motion-values.md` §0。

> **一句话结论**：动作值本身 `[C]`（romfs 字节 + JSON 双证，229/229 吻合）；**记录 ↔ 招名的官方映射在数据里不存在**
> （56 B 记录没有 action-id 字段），所以除铳枪/狩猎笛少数通过结构校验的候选（`[I]`）外，"招式"一律 `[U]`。

| 标记 | 含义 | 本页出现处 |

## 0. 数据、读法与"招式为什么是 [U]"

| 武器 | 资源条目（`nativeNX/arc/player/quest/wNN.arc` 内） | 条数 | 文件长度 | JSON 选择子 |
|---|---|---|---|---|
| 大锤 `w02` | `player\hit\pl_we02_hitdata`（type `0x4E2EF008`） | **112** | 6288 B = 16+112×56 | `.[]\|select(.weapon=="w02")` |
| 长枪 `w03` | `player\hit\pl_we03_hitdata` | **36** | 2032 B | `.[]\|select(.weapon=="w03")` |
| 铳枪 `w09` | `player\hit\pl_we09_hitdata` | **19** | 1080 B | `.[]\|select(.weapon=="w09")` |
| 狩猎笛 `w12` | `player\hit\pl_we12_hitdata` | **62** | 3488 B | `.[]\|select(.weapon=="w12")` |

（条数 / 长度均为 `[C]`：文件头 `+0x08` = count，长度 = 16+count×56。）
（JSON = **`docs/data/json/motion-values.json`**，由 `tools/mhgu/hitdata.mjs json` 生成；右列选择子为 jq 写法。）

**记录位置与引用方式**（全页通用，`[C]`）：

- rec `i` 起始 = 文件 `0x10 + 0x38×i`；每条 56 B。
- **动作值 = rec `i` 的 `+0x04` u16** = 文件 `0x14 + 0x38×i`。
  依据 main 内拷贝函数 `0x168e98`：`ldrh r0,[r5,#4]` → `strh r0,[r4,#56]`（运行时 power 槽），
  与 `motion-values.md` §0.2 及 MvFields 报告的指令级结论一致。
- 因此本页每条值都可按 `pl_weNN_hitdata` + rec 号 + `+0x04` 复核；§5 另抽 4 条给出**文件绝对偏移**的字节。

**交叉核对**：4 个文件共 `112+36+19+62 = 229` 条，用 `mhgu_re_read_bytes` 全量重解与
`motion-values.json` 的 `records[].mv` 比对，**0 处不一致** `[C]`。`+0x06`（命中类型）与 `+0x19`（hitsize 组）
在 JSON 里（`hitType` / `hitsize`）229 条全为 0，字节抽查一致，并与全库 870 条一致 `[C]`。

### 0.1 为什么"招式"列是 `[U]`

1. **记录里没有招名/招式 id**。56 B 只有命中级参数：`+0x04` 是动作值，`+0x08`/`+0x0A`/`+0x0C` 是类型码
   （MvFields 报告仍标 `[U]`），没有任何字段能指回动作表。
2. **条数对不上**：大锤 112 条 vs §1.1 的 15 个招名；长枪 36 vs §2.1 的 17 个；狩猎笛 62 vs §4.1 的 15 个；
   铳枪 19 vs §3.1 的 19 个（唯一条数相等者，但见 §3.3 的错位证据）。一个招式可占多条记录（多段 / 多判定 / 风格变体），
   记录顺序 **不等于** 招名表顺序。
3. **镜像 wiki 没有动作值表**：对 `docs/reference/mhxx-wiki` 全目录按「动作值」及其日文写法检索 = **0 命中**，
   全站镜像只给招名、按键与系统（打击/切断/固定）。所以任务里设想的"用镜像动作值文本反查招名"这条路无数据可走。
4. 唯一可能闭环的路径是 `nativeNX/table/weaponProcessWNN.wpd` 派生顺序与记录索引对齐
   （`motion-values.md` §5 第 5 项，仍未解）`[U]`。

### 0.2 招名与按键的来源

- **招名**：官方 chS `table/HN_WeaponControlsMsg_chS.gmd`——`WC_HAM_*` / `WC_LA_*` / `WC_GLA_*` / `WC_HORN_*`
  的 `skilltitle_N`（连段里显示的招名）与 `commandnote_N`（按键提示），本页逐字引用 `[B]`。
- **按键 / 系统**：镜像 wiki `text/1954.txt`（大锤）、`1956.txt`（长枪）、`1957.txt`（铳枪）、`1955.txt`（狩猎笛）`[W]`。
- 官方招名与镜像旧作招表**不是同一套命名**（例：官方「直挥 / 横挥」，镜像作「纵挥 / 横挥」；
  官方「撩击」，镜像作「纵挥3（上撩）」）。本页以官方名为准，镜像名只用于对按键。
- **招名 ↔ 按键的配对是语义合并，属 `[I]`**：gmd 的 commandnote 文本已剥掉按键图标，按键列取自镜像 wiki，
  两者的对应按语义（同义招名 / 同段数）合并，不是官方并排表。招名本身仍 `[B]`。
- **风格名用官方 chS**：**英勇**（英勇槽）/ **炼金**；镜像 wiki 的旧译不作本页术语 `[B]`。

### 1.4 读表要点（大锤）

- 值域 **0–165**；出现最多的是 **20（25 条）**，其次 **5（12 条，全在 rec53–64）**、15（11 条）、60（7 条）、90（6 条）`[C]`。
- **rec53–64 = 12 条连续 5**：唯一的长同值簇，形态上是"多段弱判定 + 最后强击"序列（回旋系 / 挥舞 / 台风预警类）
  的候选，但**具体招名 `[U]`**。
- 顶部三条 **165(49) / 125(51) / 110(52)** 相邻，且三条的 `+0x2C` f32 乘数分别为 1.25 / 1.1 / 1.0，
  疑为狩技或强状态招的高伤段 `[I]`；官方招名侧既无记录号也无动作值可对锚，故不落名。
- **递增三连 65/70/80**（rec18–20）与蓄力 Ⅰ/Ⅱ/Ⅲ 的形态相符 `[I]`，但三条的 `+0x02` 同为 20，
  `+0x0C` 为 1/1/2、`+0x08` 为 35/36/73（类型码，语义 `[U]`），无法证明就是蓄力组，故仍 `[U]`。
- 大锤 **112 条 / §1.1 的 15 个招名**，逐条落名无锚点；本表只给值。

- 炼金：**中段强突刺 / 上段强突刺** 容易累积炼金槽（`skillnote_7`）。
- 英勇：**挥盾攻击** 带格挡判定，之后可接反击突刺（`skillnote_9`）。
