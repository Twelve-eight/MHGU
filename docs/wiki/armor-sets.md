# 防具系列与套装（Armor Series & Sets）

**这一页能查到什么**：MHGU（Switch 1.4.0）全部 **1242 个防具系列**按等级（下位 / 上位 / G 级 / 二名）分组；每行给官方中文名、稀有度、剑士/神枪手、件数、五件防御合计（初始 / 强化满）、五耐性合计、孔合计、五件技能点合计，以及按阈值**实际发动的技能**。G 级（**499** 系列）与二名（**36** 系列）逐条全列，下位（**236**）与上位（**471**）给按稀有度的合计统计 + 全名清单，四个数相加 = 1242（§3 闭合）。

**不在这里的内容**：单件的初始/满防御、逐件技能点、孔数分布见 `wiki/armor-talismans.md`（§1 身份、§2 稀有度、§3 孔与耐性、§4 强化档）；技能阈值、负档、装饰珠见 `wiki/skills.md`；护石见 `armor-talismans.md` §5。

**口径**：本页「技能点合计」只把**一套防具五件自身**的固有技能点相加（含二名树与真･二名树，它们就在防具身上）；不含装饰珠、护石、秘术（树 204）、护石强化（树 205）。所以它回答的是「这套衣服本身能发动什么」，不是「配完珠之后能发动什么」。

## 1. 一个「系列」= 一套 5 件

### 1.1 系列号

- 系列号 `N` 就是**存档里防具 `id` 的低 16 位**（u16，0–1286）；同一套的 5 件共用这个 `id`，部位由存档 `type` 1–5 区分（`armor-talismans.md` §1.1）。
- 上界来自 **ASD**：`163,457 B = 8 + 1287 × 127`，头 8 B = f32 `38.0` + u32 **1287** → 系列号 0–1286。系列 **0** 在名称表里是「无装备」（T #0–9）。
- 名称表 **T** 的条数闭合：`12,870 = 1287 × 10`，与 ASD 的 1287 条一一对应（B，两处独立计数）。

### 1.2 官方中文名与后缀（以火龙为例）

`series N` 的五个部件名 = `strings[10N+0..4]`。同一头怪的不同等级是**不同系列号**，中文名在**后缀**上区分：

| 系列号（剑士 / 神枪手） | 头部名（剑士 / 神枪手） | 后缀 | 稀有度 | 等级 | chS 出处 |
|---|---|---|---|---|---|
| 150 / 151 | 火龙头盔 / 火龙帽 | 无 | 3 | 下位 | #1500 / #1510 |
| 446 / 447 | 火龙**S**头盔 / 火龙**S**帽 | S | 6 | 上位 | #4460 / #4470 |
| 450 / 451 | 火龙**R**头盔 / 火龙**R**帽 | R | 6 | 上位 | #4500 / #4510 |
| 916 / 917 | 火龙**X**头盔 / 火龙**X**帽 | X | 9 | G 级 | #9160 / #9170 |
| 960 / 961 | 火龙**XR**头盔 / 火龙**XR**帽 | XR | 9 | G 级 | #9600 / #9610 |
| 1150 / 1151 | **GX**火龙头盔 / **GX**火龙帽 | GX | 9 | G 级 | #11500 / #11510 |

- **GX 是前缀**（「GX火龙头盔」），S / R / X / XR / Z 是后缀（「火龙X头盔」）。这条顺序反了会指错系列。
- **EX** 是活动装前缀（「EX雌火龙S头盔」= 既有 EX 又有 S），不是等级标记，按稀有度归级（§2.3）。
- 缺部件的部位，其名称串写「无装备」（例如只有腰带/护臂的单件系列，头部槽就是「无装备」）。**头部槽**写「无装备」的系列共 **79** 个；本页「系列（现存部件名）」列在这种情况下列**第一个存在的部件名**，其余少件装（缺件在胴/腕/腰/脚）的系列仍用头部名，件数列会显示 < 5（§3.3）。

## 2. 等级（下位 / 上位 / G 级）怎么判定

### 2.1 判定规则（按优先级）

1. 名字带 **X / XR / GX / Z** → **G 级**；
2. 带 **S** → **上位**；
3. 带 **R** → 看稀有度：8–10 → G 级，4–7 → 上位；
4. 其余（无标记，「base」）按稀有度：**1–4 下位，5–7 上位，8–10 G 级，11 二名**。

### 2.2 为什么必须「后缀优先」

稀有度单独不足以定级 —— 同样稀有度 4 里既有下位也有上位：

| 现象 | 证据 |
|---|---|
| 98 个 **S** 系列落在稀有度 **4**（如 `皮制S头盔` = `Leather S`，稀有度 4、上位） | D 的 `armor_families`：`name LIKE '% S' AND rarity=4` = 98 |
| 34 个**无标记**系列也在稀有度 **4**（如 `结云之笠･天`[209]、`奇猿狐头盔`[309]、`桃毛兽王头盔`[718]），属下位 | 同表 `rarity=4` 共 142 条 = 108 个 S/R + 34 个无标记 |
| 后缀组的稀有度区间互不交叠（除 R） | X 294 条 → 8–10；XR 60 → 8–10；GX 45 → 8–10；Z 16 → 8–10；S 203 → 4–7；R 59 → 4–10 |

> 结论：**后缀是游戏自己的等级标记**（B，chS 原文），稀有度只是旁证（I）。R 系列横跨两档（4–10），所以 R 只能按稀有度再分一次 → 这一小类（59 个系列）的等级标 **[I]**。

### 2.3 各等级系列数（合计 1242）

| 等级 | 系列数 | 稀有度范围 | 后缀构成 | 剑士 / 神枪手 / 通用 |
|---|---|---|---|---|
| 下位 | **236** | 1–4 | 无标记 236 | 110 / 110 / 16 |
| 上位 | **471** | 4–7 | 无标记 213・S 203・R 55 | 222 / 222 / 27 |
| G 级 | **499** | 8–10 | X 294・无标记 80・XR 60・GX 45・Z 16・R 4 | 241 / 241 / 17 |
| 二名 | **36** | 11 | 无标记 36 | 18 / 18 / 0 |
| **合计** | **1242** | 1–11 | 无标记 565・S 203・R 59・X 294・XR 60・GX 45・Z 16 | 591 / 591 / 60 |

- 闭合检验：236 + 471 + 499 + 36 = **1242**；后缀 565 + 203 + 59 + 294 + 60 + 45 + 16 = **1242**；类型 591 + 591 + 60 = **1242**。〔D，逐条计数〕
- **剑士与神枪手在每个等级里数量完全相等**（110/110、222/222、241/241、18/18）—— 这是「一套两版」的数据形态，也是 §2.1 规则自洽的一项旁证（若有系列被误判等级，两侧计数会错开）。
- 稀有度 4 同时出现在下位（34）与上位（108），稀有度 11 **只**是二名；二名全是 0 孔（36/36），见 §6。

## 4. 套装技能点与「发动技能」怎么算

### 4.1 算法（三步）

1. **逐件取点**：每件防具 1–4 条固有技能点（引擎留 5 槽，数据最多 4，`armor-talismans.md` §6 / `skills.md` §1.3）；来源 **DS**（`item_to_skill_tree`）。
2. **按树求和**：同一技能树（不是技能名）在 5 件上的点数直接相加，正负都算。例：火龙X 的树 18 逐件 4+3+6+3+4 = **+20**。
3. **按阈值定档**：同一棵树只发动「已达成的最高正向档」或「最低负向档」，正负不共存（`skills.md` §1.1）。阈值取 D 的 `skills` 表（+10/+15/+20、−10/−15/−20），技能中文名取 **SK**。

### 4.2 逐件点数 → 合计 → 发动（火龙X 剑士 [916]，稀有度 9，G 级）

| 部件 | 逐件技能点（树:点） | 摘录 |
|---|---|---|
| 头 火龙X头盔 | 71:4・18:4・5:1 | 痛击+4・攻击+4・听觉保护+1 |
| 胴 火龙X铠甲 | 71:3・18:3・5:1 | |
| 腕 火龙X腕甲 | 71:1・18:6・5:1 | |
| 腰 火龙X护裙 | 71:2・18:3・5:1 | |
| 脚 火龙X护腿 | 18:4・5:1 | |
| **合计** | **攻击 +20・痛击 +10・听觉保护 +5** | 防御 600/790，耐性 +20/0/−10/0/−20，孔 7 |
| **发动** | **攻击力UP【大】・弱点特效** | 听觉保护 +5 不到 10，不发动 |

### 4.3 交叉验证（本页的求和口径）

| 系列 | 本页合计 | 镜像 wiki 的系列合计行 | 结论 |
|---|---|---|---|
| 皮制 [1] | 防御 5/**125**，孔 5，技能 反复无常 +10・采集 +5 | `armor-talismans.md` §2.4 引文：「皮制 5 件 = `5 / 250` 防御、反复无常 +10 采集 +5、5 孔」 | 技能点与孔**逐字吻合**；防御差 2 倍（已知冲突，§9 #1） |
| 合金 [52] | 防御 60/**310**，孔 3 | 同页引文：「合金 5 件 = `60 / 310`」 | **逐字吻合** |

> 合计口径经两套独立系列验证（技能点、孔、合金防御全中），唯一的差异是皮制防御的 2 倍问题 —— 该问题在 `armor-talismans.md` §7 #10 已登记，本页不重复推导。

### 4.4 负点与惩罚技能

- 合计为负也会发动**负向技能**：野猪X 剑士 [802] 加护合计 −10 → 恶灵作祟；怪鸟X [809] 防御 −10 → 防御力DOWN【小】。
- 差一点不发动是常态：蓝速龙X [763] 饥饿 −8、毒蝎X 痛击 +8 都不触发。
- 负点合法的来源是防具本身（不是珠子）：`armor-talismans.md` §3.3 与 `skills.md` §1.1。

## 10. 复现

```sql
-- 等级判定（与 §2.1 逐字同规则）
WITH c AS (
  SELECT _id, name, rarity, hunter_type,
    CASE
      WHEN name LIKE '% XR' OR name LIKE '% GX' OR name LIKE '% X' OR name LIKE '% Z' THEN 'G'
      WHEN name LIKE '% S'  THEN 'HR'
      WHEN name LIKE '% R'  THEN CASE WHEN rarity >= 8 THEN 'G' ELSE 'HR' END
      WHEN rarity >= 11 THEN 'X'
      WHEN rarity >= 8  THEN 'G'
      WHEN rarity >= 5  THEN 'HR'
      ELSE 'LR'
    END rk
  FROM armor_families
)
SELECT rk, COUNT(*) FROM c GROUP BY rk;
-- 期望：G 499 / HR 471 / LR 236 / X 36

-- 一套的五件合计
SELECT f._id, f.name, f.rarity, COUNT(a._id) n,
       SUM(a.defense) d, SUM(a.max_defense) m,
       SUM(a.fire_res)||'/'||SUM(a.water_res)||'/'||SUM(a.thunder_res)||'/'||SUM(a.ice_res)||'/'||SUM(a.dragon_res) res,
       SUM(a.num_slots) slots
FROM armor_families f JOIN armor a ON a.family = f._id
WHERE f._id = 916 GROUP BY f._id;   -- 916 = 火龙X 剑士 → 5 / 600 / 790 / +20/0/-10/0/-20 / 7

-- 一套的技能点（按树求和）
SELECT t.skill_tree_id, SUM(t.point_value)
FROM armor a JOIN item_to_skill_tree t ON t.item_id = a._id
WHERE a.family = 916 GROUP BY t.skill_tree_id ORDER BY 2 DESC;
-- 期望：18→+20、71→+10、5→+5
```

- 中文名：`armorSeriesData_chS.gmd.json` 的 `strings[10N]`（头部名）；树名：`skillTypeData_chS.gmd.json` 的 `strings[2T]`；技能名：`skillData_chS.gmd.json` 的 `strings[2j]`（j = db `skills._id`）。
- 发动技能 = 对该树取「≤ 合计值的最高正向阈值」；合计为负时取「≥ 合计值的最低负向阈值」；都没有则不发动（表内 `—`）。
- 本页所有五件合计按 `family` 分组、按 `_id` 升序输出，G 级 499 行与生成结果逐行同序（行数已核：表格 499 行）。
