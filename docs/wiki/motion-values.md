# 动作值（Motion Values）

玩家每次攻击的**威力系数**（俗称"动作值"）存放在 romfs 的 per-weapon 命中数据资源里。本页给出
该资源的格式、文件位置，以及**大剑（GS）**与**太刀（LS）**两武器的全部记录。数值取自
`docs/data/json/motion-values.json`（`node tools/mhgu/hitdata.mjs json` 生成，14 武器 / 870 条）。

> 标记：`[C]` = 已从 romfs 二进制解出并可复核；`[I]` = 推断/单源；`[U]` = 仓库内无官方逐招名/字段语义未闭环。

## 0. 数据位置与格式

| 项 | 值 | 来源 |
|---|---|---|
| 所在容器 | `nativeNX/arc/player/quest/wNN.arc`（每武器一个） | `[C]` ARC 目录枚举 |
| 资源条目 | `player\hit\pl_weNN_hitdata`（type hash `0x4E2EF008`，zlib 压缩） | `[C]` w00.arc 条目表 |
| 命中体积 | `player\hit\pl_weNN_hitsize`（`HTS\0`，球体/胶囊组） | `[C]` |
| 武器参数 | `player\param\pl_wNN`（rFreeUseParam，`0x496F8F22`） | `[C]` |
| 动作流程表 | `nativeNX/table/weaponProcessWNN.wpd`（0x20B 记录：取消/派生顺序，**非**动作值） | `[C]` |
| 解码工具 | `tools/mhgu/hitdata.mjs`（`list`/`dump`/`json`），产 `docs/data/json/motion-values.json` | `[C]` |

### 0.1 `pl_weNN_hitdata` 文件头（16 B）

```
+0x00  u32  magic      "HDP\0"  (0x00445048)
+0x04  u32  version    0x20160209
+0x08  u32  count      记录条数
+0x0C  u32  0
+0x10  record[count]  每条 56 B
```
文件总长 = `16 + count*56`（w00 = 16+61×56 = **3432 B**；w07 = 16+85×56 = **4776 B**）。`[C]`

### 0.2 命中记录（56 B）

字段由 main 内的拷贝函数 `0x168e98`（把记录逐项搬进运行时命中对象 r4）确定。以下 offset 为记录内偏移，
右列给出拷贝器的实际读写与运行时落槽。

| offset | 类型 | 运行时槽 | 语义 |
|---|---|---|---|
| +0x00 | s16 | →f32 | 方向/角度参数 A `[I]` |
| +0x02 | s16 | →f32 | 方向/角度参数 B `[I]` |
| **+0x04** | **u16** | **+0x38** | **威力 / 动作值**（本页"动作值"列） `[C]` —— `ldrh [r5,#4]→strh [r4,#56]` |
| +0x06 | u8 | +0x3A | 命中类型：文件里 **870 条全为 0**，运行时 `0→归一化为 1`（`strbeq`） `[C]`；非零含义 `[U]` |
| +0x08 | u16 | +0x36 | 参数 `[U]` |
| +0x0A | u8 | +0x3B | 参数 `[U]` |
| +0x0B | u8 | +0x3C | 参数 `[U]` |
| +0x0C | u32 | +0x40 | 参数 `[U]` |
| +0x10 | u32 | +0x48 | 参数 `[U]` |
| +0x14 | u8 | — | 参数 `[U]` |
| +0x18 | u8 | +0x50 | hitsize 相关 `[I]` |
| +0x19 | u8 | — | hitsize 组号：文件里 **870 条全为 0**（本表不选 hitbox） `[C]`；非零含义 `[U]` |
| +0x1A | u16 | +0x52 | 参数 `[U]` |
| +0x1C | u8 | +0x55 | 参数 `[U]` |
| +0x1D | s8 | +0x56 (>0 时) | 参数 `[U]` |
| +0x1E | u8 | →f32 @+0x64 | 参数（0xFF→写 −100.0） `[I]` |
| +0x1F | u8 | →f32 | 参数 `[U]` |
| +0x20 | u8 | +0x6C | 参数 `[U]` |
| +0x21 | u8 | +0x57 | 参数 `[U]` |
| +0x22 | u8 | +0x58 | 参数 `[U]` |

| +0x2C | u8 | +0x9E | 等级 `[I]` |
| +0x2E | u16 | +0xA6 | 参数 `[U]` |
| +0x30 | u16 | +0xA8 | **独立 u16**（`ldrh [r5,#48]→strh [r4,#168]`）——**不是** +0x04 镜像：多数刀刃上相等，但 w00 rec8=2 vs 10、w04 rec3=90 vs 2 `[C]` |
| +0x34 | u16 | — | 参数 `[U]` |
| +0x36 | u16 | — | 参数（**非常数**：w00=0x4B、w11 rec0=8、w04 rec0=0） `[C]` |

**说明**：
- 本表（`pl_weNN_hitdata`）**只存动作值**：`+0x06`/`+0x19` 在全 870 条均为 0，即不在此资源里区分
  斩/打类型或选 hitbox（hitsize 组另有 `pl_weNN_hitsize`，w00 7 组 / w11 12 组）。
- 元素伤害倍率、气绝(KO)、减气、打击/切断细分由记录其余 u8/u16 共同决定，且伤害公式还叠加
  武器面板/会心/肉质；这些字段的语义未从伤害路径闭环，标 `[U]`。
- `+0x04` vs `+0x30` 究竟谁进伤害公式：copier 把 +0x04 放进对象的 power 槽且复现全部已知锚点，
  JSON 采用 +0x04；最终拍板需伤害计算路径（MvFields/RevMV）。

### 0.3 类与注册

- 资源类 `rPlayerManyAttacks`（type hash `0x18A9225C`）：对象体 0x78 B，`+0x64`=条数、`+0x6C`=记录基址、
  `+0x74`=u32 指针表；`get`（`0x271df0`）按索引返回 `base + idx*4`。
- 资源注册表（`.tmp/mhgu/inventory/resource-registry.txt`）首块 = `rHitSize` + 10×`rPlayerManyAttacks` + 3×`rFreeUseParam`。
- `pl_weNN_hitdata`（HDP,56B）≠ 敌方 `*_attackdata`（`HDE\0`,32B）：魔数/布局均不同（见 `tools/mhgu` 与 port 工具注释）。

## 4. 解码工具与扩展

一条命令直接产出全武器动作值表（`hitdata.mjs` 内部经 `arc.mjs` 读各 arc，无需手工解包）：

```bash
node tools/mhgu/hitdata.mjs json          # → docs/data/json/motion-values.json（14 武器 / 870 条）
node tools/mhgu/hitdata.mjs list           # 逐武器计数一览
node tools/mhgu/hitdata.mjs dump --weapon w00   # 单武器逐条
```
选项：`--out`、`--arcs`、`--gmd`、`--extract`、`--from-extract`、`--strict`、`--dry-run`。

- 已产 `motion-values.json`：每武器 `{weapon, zh, count, records:[{i, mv, hitType, hitsize}]}`。
- 其余 12 武器的逐招归属仍待把 `weaponProcessWNN.wpd`（0x20B 派生顺序）与记录索引对上 —— 本表只给 `+0x04` 动作值。
