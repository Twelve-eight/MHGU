# 大型怪物肉质总表（slot 0–46）

> 3 行导读：本页收录 MHGU 大型怪物槽位 0–46（共 47 槽、42 只怪，含二名/稀少种变体）的**全部**肉质行——常态 8 槽 + 每个状态组（愤怒/破坏/带电/冷却/积雪/透明/被钓起/怒阶段…）逐行给出。
> 每行 = `切 打 弹 火 水 冰 雷 龙 气绝` 9 个伤害百分比，数值直接读自 romfs `arc/enemy/emNNN_NN.arc :: enemy\dt_tune\emNNN_NN_dttune` 的字节，**偏移是该行在解包后 dttune 文件内的字节偏移**（行宽固定 10 B = 9×u8 + 1 填充）。
> 行尾来源标记：`[C]` = 与机读库 `mhgu.db monster_damage` 同部位同状态行逐值一致；`[X]` = db 有该行但数值有差（表内记 romfs 值，表下「db 差异」给出两边值）；`[B]` = db 无对应行（romfs 独有行）；部位名/状态名凡由 db 或槽位推断者标 `[I]`。已收录于 `monster-hitzones.md` 的 10 只怪（雌火龙/火龙/轰龙/迅龙/雷狼龙/碎龙/斩龙/电龙/泡狐龙/巨兽 的 `_00` 正体表）本页不重复。

## 1. 读表方法与格式

**源文件**：`<romfs>/nativeNX/arc/enemy/emNNN_NN.arc` 内的 `enemy\dt_tune\emNNN_NN_dttune`（typeHash `0x48e8ac29`，zlib 载荷）。本页所有偏移都相对**解包后**的 dttune 文件，与 `docs/reference/formats/dttune.md` 的字段表口径一致。

**肉质表结构**（逐怪定位，起点会漂移）：

| 项目 | 规则 | 证据 |
|---|---|---|
| 表起点 | 每只怪不同，本页 42 只实测 `0x8C`/`0x8E`/`0x8F`/`0x90` 四种（全 138 个 dttune blob 里另有 `0x91`）；本页每只按该文件实际起点标注 | [C] |
| 行 | 10 B：`切 打 弹 火 水 冰 雷 龙 气绝` + 1 填充字节（实槽行读作 `0x64`） | [C] |
| 组 | 8 行一组，第 k 组起点 = 表起点 + 80×k。第 0 组 = 常态；第 1 组起 = **条件覆盖层**（每槽=该部位在某条件下的替代肉质） | [C] |
| 空槽 | 组内未用槽位有三种形态：整行 `0x64`（未使用）、整行 0（无覆盖占位，见矛碎大名盾蟹）、与常态同值的副本行。表中 `0x64` 空槽不单列，后两种逐行列出 | [C] |
| 表尾 | 表长不一定是 80 的整数倍：大名盾蟹 `em019_00` 只有 15 行（第 2 组第 8 槽位置已是下一区段的起始字节） | [C] |
| 组数 | 每组 8 行；组内 ≥6 行行尾填充字节为 `0x64` 即视为肉质组，否则表已结束（其后是调参浮点区）。少于 6 的例外按数值形态判：白电第 2 组只有 5 行 `0x64`（另 2 行为 `0xFF`/`0xC8`），但 8 行数值与常态逐值相同，确属肉质 | [C] |
| 状态语义 | 由 db `monster_damage` 的 `(状态)` 后缀行对拍得出；无 db 行时该组标为「状态组 k 槽 n」并标 `[U]` | [I]/[U] |

**与 `docs/reference/formats/dttune.md` 的冲突（本文以字节为准）**：该格式文档称「条件状态肉质不存在于 dttune，db 的 Enraged/Charged 等行在 romfs 无对应」，此说法**不成立**。实测每只多状态怪在常态组之后紧跟一个或多个 8 行组，其数值与 db 的 `(Enraged)`/`(Break)`/`(Charged)`/`(Cool)`/`(Wind Barrier)`… 行逐值吻合（例：轰龙 `em032_00` 表起点 `0x8E`，愤怒组起点 `0xDE` = `0x8E`+80；`monster-hitzones.md` §3.3 已按行对拍）。故本页把状态组按原始字节全部列出。

**`[B]` 行与「条件覆盖层」的真实形态**：第 1 组起是条件行——每槽是**该部位**在某条件下的替代肉质，条件逐行取自 db 后缀，不是整组共用一个状态。多数怪一层内 8 槽同属一个状态（轰龙愤怒、雷狼龙超带电、巨兽积雪），但甲壳种是混合层：大名盾蟹一层里 6 槽是 `(Guarding)`（防御姿态）、第 7 槽是 `(Break)`（壳破坏后）；将军镰蟹一层里只有 `Shell (Skull Shell)`、`Softshell (Break Shell)` 两槽有值，其余整行 `0x64`。db 只收录「与常态不同」的部位，未变化的部位在覆盖层里以**副本行**出现——这些副本行 db 无同状态行，标 `[B]`，部位名按「同槽序号与第 0 组相同」推断 `[I]`。整行 0 的槽位（矛碎大名盾蟹 3 处）对应 db 也没有 `(Break)` 行的部位，语义按「无覆盖」处理 `[U]`。

**空槽示例**：怪鸟（7 部位）与黑狼鸟（7 部位）的第 0 组第 8 槽整行 100；白电（6 部位）与煌黑龙（6 部位）空 2 槽；蓝/黄/红速龙王各只有 2 个实槽（空 6 槽）。

> **怪物名**：本页一律用官方 chS 文本（`chS/arc/resident_chS.arc :: chS\GUI\06_msg\monsterName_chS` 的槽位串，权威勘误见 `docs/wiki/monsters-index.md` §5）。社区惯用名（如 大怪鸟/白电龙/大野猪王/尾槌龙）属于另一次本地化改写，本页不做手工替换。
