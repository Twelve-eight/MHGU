# 近战招式与动作值：斩击斧 / 盾斧 / 操虫棍

> **三行摘要**
> - 本页给三把武器的**逐条动作值**（= 每次命中的威力百分比）：斩击斧 `w08` 115 条、盾斧 `w14` 80 条、操虫棍 `w13` 58 条，全部来自 romfs `player/wNN/player/hit/pl_weNN_hitdata` 的 56 B 记录，**动作值 = 记录 `+0x04` u16**。
> - 招式名优先用**官方 chS 文本**（`HN_WeaponControlsMsg_chS`：`WC_SAX_*` / `WC_CAX_*` / `WC_IG_*`），按键与旧作招式表用 MHXX 镜像 wiki（`text/1958` / `1959` / `1960`）。记录里没有 motion/招式 id，所以「哪条记录属于哪一招」只有**数值签名**（同值连发、逐值重复、三段梯）能绑，其余一律 `[U]`，不猜名。
> - 每条数值都带 `pl_weNN_hitdata rec<idx>` 出处；瓶 / 猎虫 / 精华的附加伤害只写仓库里有出处的部分（§4），其余标 `[U]`。

本页给出三条武器树的**招式清单**与**逐条命中记录（hitdata record）的动作值**：

| 武器 | 武器号 | 记录数 | 命中数据资源 |
|---|---|---|---|
| 斩击斧 | w08 | 115 | `player/hit/pl_we08_hitdata` |
| 盾斧 | w14 | 80 | `player/hit/pl_we14_hitdata` |
| 操虫棍 | w13 | 58 | `player/hit/pl_we13_hitdata` |

- 动作值 = `docs/data/json/motion-values.json` 的 `mv`（`node tools/mhgu/hitdata.mjs json` 从上面三个资源解出），
  字段语义见 `wiki/motion-values.md` §0.2：记录 **`+0x04` u16**，拷贝器 `main:0x168e98`（`ldrh [r5,#4] → strh [r4,#56]`）。
- 招式名取**官方中文文本** `chS/table/HN_WeaponControlsMsg_chS.gmd`（`WC_SAX_*` / `WC_CAX_*` / `WC_IG_*`，
  即游戏内「武器操作」页的招式名与连段窗口名）；按键与旧作招式表取镜像 wiki
  `docs/reference/mhxx-wiki/text/1958.txt`（斩击斧）、`1959.txt`（盾斧）、`1960.txt`（操虫棍）。
- 标记：`[C]` 已从 romfs 字节或 main 代码复核（**数值与结构事实**）；`[B]` 官方文本单源；`[W]` 镜像 wiki 文本；
  `[I]` 推断（**记录 ↔ 招式**的绑定）；`[U]` 未定（仓库内无证据）。与同系列 `moves-blademaster-a.md` 同口径：
  「标记」不表示数值可信度，只表示绑定强度 —— 动作值本身全部是 `[C]`，绑定除标 `[U]` 者外都是 `[I]`，
  只有结构签名（同值连发 / 逐值重复）这一级的事实用 `[C]`。
- **特别说明 `[C]` 的边界**：本页签名表「标记」列里的 `[C]` **只表示「这一行描述的是可复核的结构事实」**
  （例：`rec68–rec71` 与 `rec74–rec77` 逐值相同、`rec0` 是唯一零值、文件峰值 250），**从不表示「这条记录就是这一招」**。
  招名绑定一律是 `[I]`；没有任何证据时是 `[U]`。A 页的 `[C]` 指「已有交叉核对锚点的绑定」，两页挂的对象不同，读法以各自 §0 为准。

## 0. 读法与三个文件的实际尺寸

记录引用格式：`pl_we08_hitdata rec17` = 该资源文件内第 17 条记录（0 基，56 B/条，文件头 16 B）。

| 文件 | 文件长度 | 头 `count` 字段 | 交叉核对 | 来源 |
|---|---|---|---|---|
| `pl_we08_hitdata` | 6456 B | `0x73` = 115 | 16+115×56 = 6456 ✓ | `[C]` 字节 |
| `pl_we14_hitdata` | 4496 B | `0x50` = 80 | 16+80×56 = 4496 ✓ | `[C]` 字节 |
| `pl_we13_hitdata` | 3264 B | `0x3A` = 58 | 16+58×56 = 3264 ✓ | `[C]` 字节 |

> 三份文件的长度都恰好等于 `16 + count × 56`，即没有尾部或填充字节 —— `hitdata.mjs` 的
> `parseHitdata` 强制这条等式（不满足即抛错），所以「文件长度 = 记录数 × 56 + 16」可以直接当结构校验用。

三份数据各抽两条**原始 u16 复核**（`read_bytes`，偏移 `16 + i*56 + 4`）：

| 文件 | 记录 | 偏移 | 原始 u16 | JSON `mv` | 结论 |
|---|---|---|---|---|---|
| `pl_we08_hitdata` | rec0 / rec1 | `0x14` / `0x4C` | `0x0000` / `0x0032` | 0 / 50 | 一致 `[C]` |
| `pl_we13_hitdata` | rec1 / rec40 | `0x4C` / `0x8D4` | `0x0015` / `0x0078` | 21 / 120 | 一致 `[C]` |
| `pl_we14_hitdata` | rec1 / rec53 | `0x4C` / `0xBAC` | `0x000F` / `0x00FA` | 15 / 250 | 一致 `[C]` |

三武器共通结构事实：

- **`rec0` 动作值 = 0，且是全表唯一的零值**（w08/w13/w14 皆然）⇒ 占位/判定空槽 `[C]`。
- `hitType`（`+0x06`）与 `hitsize` 组号（`+0x19`）在这三份文件里**全部为 0**（`motion-values.json` 逐条可查）
  ⇒ 本表不区分斩/打类型、也不选 hitbox 组（`motion-values.md` §0.2 同一结论）`[C]`。
- 记录里**没有任何 motion id / 招式 id 字段**，romfs 也没有「记录 → 招式」的映射表；
  `nativeNX/table/weaponProcessWNN.wpd` 的派生顺序尚未与记录索引对齐（`motion-values.md` §4 同一结论）。
  ⇒ 逐条归属只能靠**威力签名**（同值连发 = 多段判定；三段递升 = 蓄力/狩技等级；量级段 = 狩技）
  和**首条序位**推断，凡无签名可依的记录一律 `[U]`。

**风格名用官方 chS**：`英勇`（`CommonMsg_chS #181` `style_tatsujin` = 英勇、`#185` = 英勇风格；六风格清单 `LbHelp_chS` `Style_Trick_002` = 公会 / 强袭 / 空战 / 武士道 / 炼金 / 英勇）。
本页因此写「英勇状态」而不是镜像 wiki 的「勇气」；官方文本里的「勇气」只是**防具系列名**（`armorSeriesData_chS #510` 勇气头饰、`#4260` 勇气S头盔），与风格无关。
