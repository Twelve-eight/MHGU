# 伤害计算：面板攻击、肉质、锋利度、会心与任务修正

> **三行摘要**
> - 一次命中的伤害 = **面板攻击 × 动作值 × 部位肉质 × 锋利度（斩味）倍率 × 会心倍率 × 任务修正**；属性伤害共用这条链，但换成属性肉质与属性倍率各算一遍。
> - MHGU（= MHXX）**没有旧作那种「武器种显示倍率」**：面板上的攻击力就是公式里用的那个数（`[I]`，证据见 §2.2：14 类武器面板同量级 + romfs 武器表存的就是面板值），所以不存在「除以 4.8 换算真实攻击力」这一步。
> - 武器侧已核到：面板攻击、会心率、属性值、锋利度槽（仓库 JSON + romfs），以及**锋利度倍率**（物理 `0x01624b4c` / 属性 `0x01624b68`）与**会心 1.25 / 负会心 0.75 / 超会心 1.3–1.4**（`.rodata` 常量，乘算点未定位）；怪物侧已核到肉质（em001 本人读字节）。仍缺的是**动作值**与**全体防御率**，正文标 `[U]`，`待补` 写明去哪取。

状态标记：`[B]` = 本次直接读到 romfs/main 字节；`[C]` = 仓库既有文档/数据的定论；`[W]` = 仓库内 wiki 镜像文本（`docs/reference/mhxx-wiki/text/*.txt`，社区整理，非游戏文件）；`[I]` = 推断（含仓库外第三方数据）；`[U]` = 未核实。

**用词说明**：本页的怪物名、技能名、武器名优先用游戏内官方中文文本（chS）。怪物名的**主源**是 `chS/arc/resident_chS.arc :: chS\GUI\06_msg\monsterName_chS`（268 条带 key 的串，提取件 `MHGU-private/romfs-extract/gmd-arc/monsterName_chS.gmd.json`），引用写成 `monsterName_chS #i（label）`；`MonsterDemo_chS` 只作对照。技能/武器名引用格式 `chS/table/<文件>.gmd #<序号>`（提取件在 `MHGU-private/romfs-extract/gmd/`）。社区镜像与官方用词不同的地方只在括号里标注，例如武器表那一列的「斩位 (+2)」（`docs/reference/mhxx-wiki/text/1900.txt:66`）就是官方的「锋利度」。

**风格名**：社区/镜像用 **勇气**（`docs/reference/mhxx-wiki/text/2201.txt:438`「狩技/勇气/炼金槽累积速度上升」、`:474`、防具系列「勇气S/勇气X」`2306.txt`/`2308.txt`），官方 chS 写作「英勇」（`CommonMsg_chS #181` label `style_tatsujin`、`#185` `style_tatsujin_Formal`；`skillData_chS #401/#403` 亦作「英勇槽和炼金槽」）。本页按社区词写 **勇气（官方：英勇）**；炼金 两处用词一致。

## 1. 总公式

仓库既有文档给出的结构（`docs/mechanics/monsters.md:624`，`[C]`）：

```
实际伤害 = 武器攻击力 × 动作值 × 肉质/100 × 全体防御率 × 其它
实际体力 = base_hp × 任务体力倍率
```

其中 `base_hp` 的 romfs 出处也已定位：`arc/enemy/emNNN_00.arc :: enemy\dt_tune\emNNN_00_dttune **+0x38**`（u32；这是 dttune 里唯一与怪无关的固定偏移；em001 = 4500，与 `mhgu.db monsters.base_hp` 字节相等，`docs/reference/formats/dttune.md`，`[C]`）；任务体力倍率本身仍缺（§7.2）。

把它展开成玩家实际会遇到的完整形式：

```
物理伤害 = 面板攻击
         × 动作值/100          # 每个招式自带，见 §8 [U]
         × 肉质(斩|打|弹)/100   # 部位 × 攻击类型，见 §3
         × 锋利度物理倍率       # 社区称斩味倍率，见 §4.3（物理表 0x01624b4c）
         × 会心倍率             # 见 §5.2（1.25 / 0.75；乘算点 [U]）
         × 任务修正(全体防御率)  # 见 §7 [U]

属性伤害 = 属性值 × 属性肉质/100 × 锋利度属性倍率 × 任务修正
```

三条玩家最容易搞错的规则：

1. **斩、打、弹是三条独立列**。同一把大剑的「斩」与大锤的「打」在同一部位可能差一倍以上（§3 雌火龙表：头 斩 90 / 打 80，尾 斩 30 / 打 30）。
2. **肉质 0 = 完全免疫**，不是「很小」；`气绝` 列不是伤害列，是眩晕蓄积值。
3. **肉质有状态维度**：同一次狩猎里，同一部位可能因愤怒/部位破坏/特殊形态换成另一套数值（`docs/mechanics/monsters.md:331`，`[C]`）。

### 1.5 乘算点在哪（代码路径，`re-damage-site` 报告）

近战的乘算**不是一条链**，而是拆在几个函数里（全部 vaddr，`vaddr = flat - 0x100`）：

```
0x168e98  建每击请求结构（[atk+148]/[atk+152] 两个乘数初值 1.0）
  → 0x171000  分派（默认走近战）
  → 0x176ad0  近战总管（前置 0x1722c0 / 0x172474 / 0x172a90 / 0x17251c）
  → 0x178030  锋利度 + 基础乘算（只有两个直接调用者：0x171180 / 0x176dd8）
  → 0x1720d4  武器种等级倍率（5 档表 0x01624b34）
  → 写 victim+0x142C → vtable[1036] 分道应用 → vtable[1400] 肉质
```

| 环节 | 代码 | 结果 |
|---|---|---|
| 物理 | fn `0x178030`：`atkMult[atk+148] × rawSharp[color]` | 存到调用者 `arg8 / sp+80`（`VSTR @0x1781dc`）`[C]` |
| 属性 | 同函数：`elemSharp[color] × rows[color][case] × s8` | 存到 `arg7 / sp+84`（`VSTR @0x17821c`）`[C]`（`s8` 来源 `[U]`） |
| 会心钳制 | fn `0x176ad0` 尾部的 VCMP/VMLA/VSEL 块（`0x177ed4..0x177f20`） | 上界 `1.4` 就在该函数自己的字面量池 `0x178024`（本人 `read_words` = `3FB33333`）`[B]`；`0.75` 的载入点见下 |

仍未定位（`[U]`）：`s8` 的来源；取整方式（HP 路径以 f32 进 victim 虚函数，整数 `/100` 只出现在硬直/气绝计量 fn `0x17885c`）；动作值 `[r4+56]` 折进乘数槽 `[atk+148]` 的位置；肉质乘算点（在怪物侧 `vtable[1400]` 实现里）。

> 关于 `0.75`：报告称它也在同一字面量池，但我实测 `0x178010..0x17802c` = `100.0 / 1.2 / 1.1 / 1.4 / 0.9 / 0.05`（`0x178014` 是 **1.2**，不是 0.75），此处**没有 0.75**；因此「0.75 是 .text 字面量」这一说法不采纳，`0.75` 仍按 §5.2 的数据区地址引用，载入点记 `[U]`。

## 2. 面板攻击 = 公式里的攻击力（MHGU 没有「bloat」）

### 2.1 结论

旧作（如 MH4U/MH3G 时代）武器面板会按武器种乘一个「显示倍率」，所以同一份内部攻击力在面板上会显示成 4.8 倍、5.2 倍等不同数字；玩家因此要做「面板 ÷ 武器种倍率 = 真实攻击力」的换算。**MHGU 不再这样显示**（`[I]`，证据 §2.2、复核 §2.3）：面板数值本身就是公式里代入的值。

### 2.2 证据（三条独立）

**(a) 14 类武器的面板最大值落在同一区间**（`docs/data/weapons/*.json` 各自 `damage` 字段的 max）：

| 武器种 | 面板最大 | 武器种 | 面板最大 |
|---|---|---|---|
| 大剑 | 390 | 长枪 | 380 |
| 片手剑 | 380 | 铳枪 | 380 |
| 大锤 | 380 | 斩击斧 | 380 |
| 狩猎笛 | 380 | 盾斧 | 380 |
| 太刀 | 380 | 操虫棍 | 380 |
| 双剑 | 380 | 轻弩 | 380 |
| 弓 | 410 | 重弩 | 380 |

若旧作那种倍率仍存在（大剑在旧作口径上是片手剑的 3 倍以上），大剑上限应显著高于片手剑；实测两者只差 10 点（390 vs 380）。全部 14 个值均由 `docs/data/weapons/<type>.json` 的 `damage` 取最大值得到（`[C]` 数据，`[I]` 解读为「无倍率」）。

**(b) romfs 武器表存的就是面板值**。`romfs/nativeNX/table/weapon00LevelData.w00d`（大剑）：

| 项 | 值 | 依据 |
|---|---|---|
| 文件大小 | 14,393 B | 字节实测 `[B]` |
| 头 | `f32 1.2f` @0x00 + `u32 959` @0x04 | `[B]`；`8 + 959 × 15 = 14,393` 尺寸闭合 |
| 记录 | 15 B，第 k 条在 `0x08 + 15k` | `[B]`（按已知攻击值定位） |
| `attack` | **u16 @ 记录+8** | `[B]` |
| 记录 0..3 的 `attack` | 50 / 60 / 80 / 90 | 记录 1..3 = 60/80/90 与 `great-sword.json` 的 `Petrified Blade 1/2/3` 逐值相同；记录 0 = 50 与该文件 `damage` 的最小值 50 相同（前有一条额外记录，索引偏移 1） |

即「游戏表里的攻击力」=「仓库 JSON 的 `damage`」（这一相等是 `[B]`）；而「这个数就是玩家面板显示、也是公式代入值」是由 §2.2(a)(c) 的量级证据 + §2.3 自检推出的 `[I]`，不是仓库或代码里的明文。

**(c) 属性值也是 ×1 口径**：`Plesioth Wave Sword 1` 水属性 36（`great-sword.json`，`_id` 69377）。旧作属性面板是 ×10 显示（表里 36 会显示 360），此处是两位数，说明属性同样取消了显示倍率。

### 2.3 怎么自己一分钟复核

1. 在游戏里打开武器详情，读「攻击力」；对照 `docs/data/weapons/<type>.json` 同名武器的 `damage`。
2. 两者相等 ⇒ 面板没有隐藏倍率；若面板恰好是 JSON 值的 4.8 倍/5.2 倍等，就说明倍率仍存在（本页结论作废）。
3. 也可用属性列复核：属性面板若是 JSON 值 ×10，说明旧作式 ×10 属性显示仍在。

本页的结论是：**MHGU 面板 = JSON 值**（`[I]`，证据 §2.2）。这个复核只需 1 分钟，且不需要任何拆包。

### 2.4 对玩家的意义

- 不要用外部攻略里的「大剑倍率 4.8 / 大锤 5.2」换算 MHGU 面板——那是旧作口径。
- 跨武器种比较**面板数值本身**是有意义的（同一量级）；真正拉开差距的是**动作值**（每招百分比）与招式出手次数，而不是面板换算。
- 面板里的 `defense`（武器自带防御）是独立加成，不属于面板攻击（`docs/mechanics/equipment.md:200`，`[C]`）。
- **攻击力UP【小/中/大】是加在面板上的固定值**（技能树 18「攻击」，档位 10 / 15 / 20 点，`skills.json`；官方名 `chS/table/skillData_chS.gmd #62` / `#60` / `#58`），所以它吃后续所有乘数（肉质/锋利度/会心）；具体加多少只有负向档的 wiki 数值可查（攻击力DOWN【大】`#68`，−20 点 → 攻击力 **−15**，`docs/mechanics/skills-arts.md:163`，`[C]`），正向档数值 `[U]`。

## 3. 肉质（hitzone）：伤害里最容易被忽略的乘数

### 3.1 数据结构

`docs/data/mhgu.db` 的 `monster_damage`（893 行 / 93 只大型怪物）每行一个「部位 × 状态」：

| 列 | 含义 | 范围 |
|---|---|---|
| `cut` | 斩击肉质 | 0..100（%） |
| `impact` | 打击肉质 | 0..100 |
| `shot` | 弹肉质 | 0..100 |
| `fire` `water` `ice` `thunder` `dragon` | 五属性肉质（**文件/db 就是 火→水→冰→雷→龙** 这个顺序） | 0..100，0 = 免疫 |
| `ko` | 气绝（眩晕）蓄积值 | u8 |

**术语**：官方文本区分物理攻击类型时用「**切断属性**」「**打击**」（例：`chS/table/skillData_chS.gmd #185`「切断属性武器的拔刀攻击能积累昏厥效果」），弓/弩等射击类对应上表的「弹」列。

`body_part` = 基础部位名 + 可选状态后缀（`Head`、`Head (Enraged)`、`Back (Break)`…），后缀词表见 `docs/mechanics/monsters.md:107-132`（`[C]`）。

**数据源可信度**：`mhgu.db` 是第三方数据库（MHGenDatabase v2.4.0）。romfs 侧的同一张表在 `*_dttune` 里，形状固定为 **8 行 × 10 字节**（cut/impact/shot/fire/water/ice/thunder/dragon/ko + 1 pad，列序与 db 一致），但**表偏移逐怪不同**——本人读字节对拍：em001 雌火龙 **0x8E**、em002 火龙 **0x8E**、em013 黑龙 **0x8E**、em011 麒麟 **0x8C**（`0x8C` 起的 4 行 50/50/45/5/5/5/0/5/100 等与 db `monster_id=11` 逐值一致）；另有报告见过 0x8F，个别怪干脆没有该表；`*_dttune` 里**唯一固定偏移是 base HP @0x38**。逐怪偏移由 `MHGU/docs/data/json/monster-dttune-index.json`（DtTuneAll 批处理）发布，格式见 `docs/reference/formats/dttune.md`。⇒ 引用肉质时必须写「该怪自己的偏移」，不能套用别的怪。

em001（雌火龙）的肉质表已在该怪自己的文件里定位（**@0x8E**）并**逐字节复核**（解压件 `MHGU-private/romfs-extract/dttune/em001_00/enemy/dt_tune/em001_00_dttune.48e8ac29`，文件 1594 B；@0x8E 起 80 B）：8 行 × 10 B 与 `mhgu.db` 的 7 行逐值相等，第 8 行是全 100 占位。第 0 行（Head）字节 `5A 50 46 00 0F 0F 14 23 64 64` = 90/80/70/0/15/15/20/35/100 + pad 100；第 6 行（Legs）`2C 28 2D 00 05 05 0A 0A 00 64` = 44/40/45/0/5/5/10/10/0。第 7 行在雌火龙/雄火龙上是占位，而有 8 个真部位的怪（如黑龙）第 7 行是真数据——**部位数逐怪不同，不要按行号硬套部位名**。⇒ **本页 §3.2 的雌火龙表据此升为 `[B]`**；其余 92 只仍为 `[I]`，等批量偏移表落地后逐怪定位、对拍再升级。

- `气绝 100` 只在头（及少数怪的特定部位）非 0：这是眩晕蓄积，不是伤害。

### 3.3 状态维度

同一部位在狩猎中可能换表（愤怒、部位破坏、超带电、覆雪、赤热…）。`monster_damage` 用 `(Enraged)` / `(Break)` / `(Charged)` 等后缀分行；`docs/mechanics/monsters.md:331` 明确「一个部位在同一次狩猎内可以有 2–3 套肉质，任何伤害计算器都必须带 `state` 维度」（`[C]`）。

反例（防误读）：雌火龙的 `monster_damage` 只有基础行，即它**没有**愤怒肉质变化——不是数据缺失。

**状态行的来源边界**：`*_dttune` 的 8×10 表只有**基础一套**肉质（§3.1），db 里的 `(Enraged)` / `(Break)` / `(Charged)` 行不在这张表内（同文件 0xE6 起的 f32 区语义未定）。实证：麒麟（em011）的 db 有 4 条 `(Enraged)` 行，而它的 dttune 只写了 4 条基础行（`@0x8C` 起：50/50/45…、24/24/20…、15/15/15…、28/28/32…），其后全是 `64` 占位 ⇒ 状态肉质目前只有 `mhgu.db` 一个来源，全部按 `[I]` 处理。

## 4. 锋利度（社区称「斩味」，sharpness）

> 官方中文用词：**锋利度**（槽 = 锋利度槽）。对应技能：**锋利度等级+1 / +2**（`chS/table/skillData_chS.gmd #168` / `#166`，描述「武器的锋利度槽略微变长 / 变长」#169 / #167）；**利刃**（`#170`，锋利度消耗减半）、**钝器手**（`#180`，描述「武器的锋利度越低，攻击力越高」`#181`）。社区把这条槽叫「斩味」，两者是同一个东西。

### 4.1 颜色与三段数据

颜色顺序固定：**红 → 橙 → 黄 → 绿 → 蓝 → 白 → 紫**（`docs/mechanics/equipment.md:186`，`[C]`）。

`docs/data/weapons/*.json` 的 `sharpness` 是三段、每段 7 个整数（每段 7 色各自的长度）：

| 段 | 含义 | 触发条件 |
|---|---|---|
| `normal` | 基础锋利度 | 无 |
| `sharper` | 锋利度等级+1（社区「匠+1」） | 技能树 35「匠」达 **10 点** |
| `sharpest` | 锋利度等级+2（社区「匠+2」） | 同树达 **15 点** |

阈值来源：`docs/data/json/skills.json` 中 `skill_tree_id=35` 的两条记录 —— `Sharpness +1`（`required_skill_tree_points` 10）与 `Sharpness +2`（15）（`[C]`）；技能树 35 的官方树名就是「匠」（`chS/table/skillTypeData_chS.gmd #70`）。

玩家要点：

- 每段 7 个数的**总和只在 15–45 之间**（`docs/mechanics/equipment.md:192`，8721 条近战记录统计），所以「白色 2 格」这种武器一旦掉到蓝/绿，物理与属性倍率同时下降。
- JSON 这套刻度与游戏内的点数是**不同单位**：仓库明写「与游戏内 400/450 点制的换算镜像未写」（`docs/mechanics/equipment.md:629`，`[C]`）。这与 §4.2 的 `kireajiData.kad` 末项恒为 450 正好对上。
- 例：青熊薙最终形态基础段 `9.7.8.8.6.2.0`（白只有 2 格），匠+2 段 `9.7.8.8.6.6.1`（白 6 格 + 紫 1 格）。见 §8。
- **有技能会反转或改变锋利度的价值**：钝器手（`skillData_chS #180`）在锋利度越低时攻击力越高，利刃（`#170`）把消耗减半——两者都改变「必须维持白/紫」这个默认策略。数值均 `[U]`。

### 4.2 锋利度槽本体在 romfs 里

`romfs/nativeNX/table/kireajiData.kad`（字节实测 `[B]`）：

| 项 | 值 |
|---|---|
| 文件大小 | 2,304 B |
| 头 | `f32 1.2f` @0x00 + `u32 164` @0x04 |
| 记录 | 14 B = **7 × u16**，第 k 条在 `0x08 + 14k` |
| 尺寸闭合 | `8 + 164 × 14 = 2,304` |
| 记录 0 | `40, 100, 180, 300, 370, 450, 450` |
| 记录 1 | `60, 90, 190, 290, 390, 400, 450` |
| 记录 2 | `70, 100, 200, 290, 360, 440, 450` |

每记录 7 个 u16 **单调递增**、末项多为 450 ⇒ 这是「七色锋利度槽的累计阈值表」（`[I]`，数值本身 `[B]`）。它确实是**游戏运行时用的那张表**：fn `0x709a08` 按 `u16@+4` 找到记录，再用 `/100`（魔数 `0x51EB851F`）把当前点数与 7 个槽位依次比较、重算颜色；fn `0x70a06c` 在越阈/耗尽时把颜色字节 `+1 / −1`（见 §4.3）。它与 `weapons.json` 的 7 色长度是同一套信息的两种表达（一个给累计阈值，一个给分段长度），但两者的单位换算关系尚未标定 ⇒ `[U]`。

### 4.3 锋利度倍率（已定位到代码常量表）

倍率表在 main 的常量区（vaddr；`vaddr = flat - 0x100`），伤害函数用**同一个锋利度颜色字节**同时索引物理表与属性表。以下数值均由 `read_words` 逐字读出、并与索引指令对上：

| 表 | 地址（7 个 f32，颜色索引 0..6） | 数值 | 证据 |
|---|---|---|---|
| **物理（raw）** | `0x01624b4c`（7 值；`0x01624b48` 另有 1 个 0.5 无任何指针引用） | `0.5 / 0.75 / 1.0 / 1.05 / 1.2 / 1.32 / 1.39` | `read_words 0x1624b4c`（`3F000000 3F400000 3F800000 3F866666 3F99999A 3FA8F5C3 3FB1EB85`）`[B]`；索引代码 fn `0x1748a8`（`add r0,r1,r7,lsl #2` @`0x174984`）与 fn `0x178030`（@`0x1781ac..0x1781c0`）`[C]` |
| **属性（element）** | `0x01624b68` | `0.25 / 0.5 / 0.75 / 1.0 / 1.0625 / 1.125 / 1.2` | `read_words 0x1624b68`（`3E800000 3F000000 3F400000 3F800000 3F880000 3F900000 3F99999A`）`[B]`；同两个函数同索引 `[C]` |
| 分类倍率 7×6 | `0x01624a8c` | `rows[6*color + case]`，`case ∈ {0,2,3,4}`：颜色 0–2 = 0.6 / 0.7 / 1.0 / 1.05；颜色 3–6 = 1.0 / 1.0 / 1.0 / 1.05 | fn `0x178030` @`0x17817c..0x1781a0` `[C]`；`case` 语义 `[U]`（疑攻击种类） |
| 5 档表 | `0x01624b34` | `0.5 / 0.5 / 0.75 / 1.0 / 1.1` | fn `0x1720d4` 按调用参数索引，内部类 7 / 11 使用（疑炮击 / 瓶等级）`[I]` |

**颜色名与索引**：**index 0 基、红在 0**，且 **index 1 = 橙**。三条独立证据：

1. **颜色字节的来源**：两个消费者用的是同一个字节，取自锋利度槽对象——getter `[ *(u32*)(obj+0x13C4) + 508 ](obj)` @`0x1780a0..0x1780b0`（`movw #0x13C4` @`0x178098`、`ldr r1,[r0,#508]` @`0x1780a4`、`blx r1` @`0x1780ac`）；槽对象的颜色字节在 `obj+37`，读取 `0xdcc3c`（`ldrb r0,[r0,#37]`）、写入 `0xdcc58`（`strb r1,[r0,#37]`），推进函数 `0x70a06c` 越过阈值时 `+1`、耗尽时 `−1`（u8 回绕）。
2. **阈值表就是七色槽**：`romfs/nativeNX/table/kireajiData.kad` 的 164 条 × 7 u16（cap 450，§4.2）；fn `0x709a08` 用 `/100` 魔数 `0x51EB851F` 把当前点数与 7 个槽位依次比较、重算颜色 ⇒ **7 槽 = 7 色、由低到高**。
3. **官方色序 + 仓库数据**：`chS/table/HN_HunterTipsMsg_chS.gmd #294`（`HTM_Kireaji_P2`）「锋利度会表现为不同的等级，**红→橙→黄→绿**……以这个顺序」，红是最低色 = index 0；仓库侧反证——958 把大剑中**没有任何一把**的首槽不是红（不存在「从橙或更高开始」的作品），例如 `Rusted Great Sword 1 = 13.2.0…`（红 13 / 橙 2，止于橙）、`Petrified Blade 1 = 9.4.2`（红 9 / 橙 4 / 黄 2，止于黄），首槽一律是红 ⇒ 红只能对应 index 0。

于是物理表按 红→紫 完整读作 **0.5 / 0.75 / 1.0 / 1.05 / 1.2 / 1.32 / 1.39**（索引 `[C]`、数值 `[B]`），属性表 **0.25 / 0.5 / 0.75 / 1.0 / 1.0625 / 1.125 / 1.2**；颜色名 `[I]`（依据是属性列 7/7 值型对齐 + 官方色序）。

> **`[X]` 冲突备注（橙）**：社区/旧 wiki 的物理列写「橙 0.5、黄 0.75、绿 1.0、蓝 1.05、白 1.2」，与二进制不符。`0x01624b48` 那个 **不可达**的 `0.5`（无指针指向，`b4c + color<<2` 也索引不到）正是旧世代 7 值列（红 0.5、橙 0.5、黄 0.75、绿 1.0、蓝 1.05、白 1.2、紫 1.32）的遗留；GU 把代码表重定位到 `b4c` 并在末尾补了 1.39 ⇒ **GU 的橙色物理倍率是 0.75，不是 0.5**。

> 玩家侧结论：锋利度倍率是**两套**（物理走 `0x01624b4c`、属性走 `0x01624b68`），颜色越高倍率越高；白→紫的物理收益只有约 1.39/1.32 ≈ **+5.3%**，而蓝→白是 1.32/1.2 = **+10%**，掉到黄及以下（1.0 或更低）损失最大。

### 5.4 期望值公式

会心是概率事件，做配装比较时用期望。把 §5.2 的两个数值代进去（会心 **1.25**、负会心 **0.75**；数值 `[C]`、语义 `[I]`、乘算点 `[U]`）：

```
a ≥ 0（正会心率 a）：E = 1 + a × (1.25 − 1) = 1 + 0.25a
a < 0（负会心率 a）：E = 1 + a × (1 − 0.75) = 1 + 0.25a     ← 同一个式子，a 为负时 E < 1
```

因为 1.25 与 0.75 关于 1 对称，两侧可合并成 **E = 1 + 0.25a**（a 为会心率小数）。配了超会心后只改正向那一半：`E = 1 + a × (c⁺ − 1)`，`c⁺` 取 §5.2 表里对应的 1.3 / 1.35 / 1.4 槽（哪把武器取哪槽仍 `[U]`）。

| 会心率 | 期望倍率 E（无超会心） |
|---|---|
| −30% | **0.925** |
| −15% | **0.9625** |
| 0% | **1.000** |
| +20% | **1.050** |
| +50% | **1.125** |
| +100% | **1.250** |

注意两点：

- 这张表建立在「1.25 / 0.75 确实按会心结算」的前提上（乘算点尚未定位，`[U]`）；如果后续把乘算点也定位了，表里的数字不变，但标签可升。
- 「残忍会心」（`skillData_chS #302`）会把负会心按概率转成强会心，届时 `a < 0` 的那半不再适用；发动条件与概率 `[U]`，配负会心武器时按实测替换。

## 7. 防御率与任务修正

这里有两个不同方向的「防御率」，不要混用：

### 7.1 玩家受伤（防具防御力）

- 防御力数值来自防具：`docs/data/armor/*.json` 的 `defense`（初始）与 `max_defense`（强化满），范围 1..140 / ≤180（`docs/mechanics/equipment.md` §2.1，:222，`[C]`）。
- 武器自带 `defense` 是独立加成（`equipment.md:200`）。
- **「防御力 → 减伤百分比」的换算公式没有任何仓库数据或代码地址支撑** ⇒ `[U]`。可确定的是：防御力越高受伤越少、且技能描述里出现「防御力 ×0.9 −10」这类乘算式（`docs/mechanics/skills-arts.md:164`，`[C]`），说明防御力是乘加混用的复合量，不能当成线性减伤。

### 7.2 怪物侧：任务难度修正（含「全体防御率」）

wiki 的「出现任务」强度条画两条轴：**绿色 = 体力倍率、橙色 = 全体防御率**，且两者都随任务变化（`docs/mechanics/monsters.md:63`，`[C]`）。仓库里能核到的是**结构与字段**，不是数值：

| 层 | 字段 / 文件 | 说明 | 状态 |
|---|---|---|---|
| 任务记录 | `romfs/nativeNX/loc/quest/questData/questData_<7位id>.ext`，`Monsters[5]` @记录 `0x05C`，每条 13 B | 每个目标怪带 `HealthTbl`(HP 表号) / `AtkTbl`(攻击表号) / `OtherTbl`(其它表号) / `StaminaTbl` / `Difficulty` | `[C]` 文档（`docs/data/romfs-tables.md` §2；361 B 尺寸闭合已验，逐字段未实测 ⇒ `[I]`） |
| 难度等级 | 同记录 `0x00B` `EnemyLevel` | 1 = 下位 / 3 = 上位 / 5 = G 级 | `[C]`/`[I]`（同上） |
| 星级 | 同记录 `0x00A` `Level` | 1..10 = ★1..★10，11..15 = G1..G5，16 = EX，101..116 = 二名 | `[C]`/`[I]`（同上） |
| 表本体 | `main` 侧难度倍率表 | 任务只存**表号**，倍率表本体未定位 | `[U]` |

**结论**（`[I]`）：同一只怪在「村下位 / 集会所上位 / G 级 / 二名 EX」里挨的伤害不同，是任务记录里的 `HealthTbl`/`AtkTbl`/`OtherTbl` 三个表号 + 全体防御率造成的，而不是怪物肉质变了（肉质表本身没有随难度的行）。具体倍率（例如 G 级比下位多减多少）**没有任何可信来源** ⇒ `[U]`。

## 8. 算例：青熊长笔【鲑兽戏画】× 雌火龙

### 8.1 输入（全部可核）

**武器**：青熊薙系最终形态，官方中文名 **青熊长笔【鲑兽戏画】**（`chS/table/weapon07MsgData_chS.gmd #268`；同族 `#264` 青熊薙、`#266` 青熊长笔【留跳】），等级 8。数据取 `long-sword.json`（`familyId` 2092，`_id` 535560，英文名 `Arzuros Telltail 8`）；`docs/mechanics/equipment.md` §1.2（:111）已把存档 `(type=14, id=44, LV=7)` 与该条对齐。

| 字段 | 值 |
|---|---|
| `damage`（面板攻击） | **350** |
| `affinity` | **0** |
| 属性 | 无 |
| 锋利度 `normal` | 9.7.8.8.6.2.0（红橙黄绿蓝白紫） |
| 锋利度 `sharper`（锋利度等级+1 / 匠+1） | 9.7.8.8.6.4.0 |
| 锋利度 `sharpest`（锋利度等级+2 / 匠+2） | 9.7.8.8.6.6.1 |

**目标**：雌火龙（Rathian，`mhgu.db` `monsters._id` 1）头部，斩肉质 **90**、龙肉质 35（§3.2 表）。

### 8.2 能算的部分（不依赖任何 `[U]` 常数）

动作值先按「100% 的一击」计（即把动作值因子暂时置 1）：

| 步骤 | 计算 | 结果 |
|---|---|---|
| 物理基数 | 350 × 90/100 | **315.0** |
| 同一武器砍后腿（斩肉质 44） | 350 × 44/100 | **154.0** |
| 头 ÷ 腿 | 315.0 / 154.0 | **2.05 倍** |
| 会心因子 | 会心率 0% ⇒ 1 + 0 × (c − 1) | **1.00**（与 c 无关） |

所以「同一把 350 面板的太刀，砍头得到的物理基数永远是砍后腿的 2.05 倍」——这条结论只需要面板 + 肉质两个已核实的输入。注意它是**比值**：即使 §2 的「无 bloat」结论被推翻（面板要乘一个武器种常数），该常数在比值里也会约掉，2.05 仍然成立。

### 8.3 把剩余因子接上

锋利度因子现在有数值了（§4.3 的物理表），315.0 的基数按当前颜色变成：

| 当前颜色 | 物理倍率 | 315.0 × 倍率 |
|---|---|---|
| 紫 | 1.39 | **437.85** |
| 白 | 1.32 | **415.8** |
| 蓝 | 1.2 | **378.0** |
| 绿 | 1.05 | **330.75** |
| 黄 | 1.0 | **315.0** |

剩下的因子：

```
对头一刀的物理伤害 = 上表的值
                   × 动作值/100        ← [U]；太刀表在 `MHGU-private/romfs-extract/player/w07/player/hit/pl_we07_hitdata.*`（85 条 × 56 B，字段待 MvDecoder 解）
                   × 1.00（会心）       ← 该武器会心 0%，因子恒为 1（§5.4 的 E = 1 + 0.25a）
                   × 全体防御率         ← [U]，取决于任务
```

属性支路：该武器无属性 ⇒ 属性伤害 = 0。若换一把龙属性 30 的太刀打同一个头：

```
属性基数 = 30 × 35/100 = 10.5
白锋利度下 = 10.5 × 1.125 = 11.8125   （§4.3 属性表；任务修正仍 [U]）
```

### 8.4 这把武器的两个实战提醒

1. **基础锋利度白只有 2 格**（`9.7.8.8.6.2.0`），不配匠时白几乎是「一进场就用完」；锋利度等级+2 档（`9.7.8.8.6.6.1`）才拿到 6 格白 + 1 格紫。倍率见 §4.3：白 **1.32**、紫 **1.39**、蓝 **1.2**——同一刀从白掉到蓝是 415.8 → 378.0（**−9.1%**），从紫掉到蓝是 437.85 → 378.0（**−13.7%**）。
2. 会心 0% ⇒ 洞察/超会心这类会心向技能对它是纯增益（期望因子从 1.00 往上抬，§5.4）；而负会心武器（如 `Plesioth Wave Sword` −15）在不配「残忍会心」时，期望只有 `1 + 0.25×(−0.15) = 0.9625`（比 0 会心低 **3.75%**）——要么先补会心，要么用「残忍会心」（`skillData_chS #302`）把负会心赌成强会心。
3. **算例假定「无练气加成」**：太刀的练气槽会改面板与锋利度——官方文本 `chS/table/HN_WeaponControlsMsg_chS.gmd :: WC_TAC_skillnote_1`（#202）写明「根据练气槽颜色来**提升攻击力**」「达到 MAX 后**锋利度会暂时变得锋利**」。所以 §8.1 的 350 与那三档锋利度都只是**基础状态**；练气各色对应的倍率与「变锋利」的具体效果 `[U]`，本页不给数值。

## 10. 一页结论（玩家版）

1. **面板攻击直接用**，不换算；跨武器种比面板有意义，差距来自动作值与招式次数。
2. **打对部位**：同一把武器砍头 vs 砍腿可以差 2 倍以上（90 vs 44 的算例 = 2.05×）。
3. **锋利度（社区「斩味」）颜色越高越好**：物理倍率 红 0.5 / 橙 0.75 / 黄 1.0 / 绿 1.05 / 蓝 1.2 / 白 1.32 / 紫 1.39（§4.3，索引与数值均已定位），白→蓝就掉 **9.1%**；锋利度槽长度（尤其白色格数）决定这个收益能维持多久。
4. **会心是概率期望**：`E = 1 + 0.25a`（会心 1.25、负会心 0.75 关于 1 对称，§5.4）——0% = 1.00、+20% = 1.05、−15% = 0.9625；配超会心后正向那一半按 §5.2 的 1.3 / 1.35 / 1.4 取表。
5. **属性看属性列**：物理弱点头部未必是属性弱点（雌火龙头部火 0 / 龙 35）。
6. **任务难度会改伤害**：同怪同肉质，下位/上位/G/二名的实际伤害不同（任务表号 + 全体防御率），不要拿村任务的伤害数字推 G 级。
