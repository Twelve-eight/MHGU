# 护石来源与生成（Talisman Sources & Roll）

- 本页只回答一条链：**护符从哪来 → 进哪张 `amskl` 表 → 池里怎么抽 → 出几个孔**。护石的面板数值、存档 36 B 记录、炼金菜单原文已在 `armor-talismans.md` §5 记过，本页不重复，只补来源与 roll 规则，并关闭该页 §7 的 #5（`.amskl` 文件号 ↔ 护符档/技能槽）与 #8（哪种任务/矿点出哪种护符，部分）；#6（`.amslt` 行索引）仍未闭合，见本页 §9 #1。
- 全链（`C` = main 代码 + romfs 字节实测）：

  ```
  矿点采掘 / 任务报酬
        ↓ 4 种护符（道具 id 353/354/355/356）
  鉴定（鉴定箱 / 任务结算）
        ↓ sMakeAmulet 0x14bba8：按 id 硬编码选「第一技能表 + 第二技能表 + 孔数表 + 种类组」
  技能树（池内等概率）→ 点数（正负 50/50，炼金恒正）→ 孔数（按点数评分选行）
        ↓
  护石（种类 1–10 由来源护符 + 点数档位决定）
  ```

- **档次不可跨越**：谜之护符永远进不了 03 表的 −10…+13 池，风化护符也永远进不了 00 表的 +1…+10 池。想要某个技能的高点数，必须刷对来源护符（`C`，见 §2/§3）。

## 2. 护符 → 两张技能表 + 一张孔数表（代码链）

`sMakeAmulet 0x14bba8` 的参数是 `(输出记录, 表集合, 护符道具 id, 无负点数标志)`。它对 id 做**硬编码**分派，字节级证据：

| 指令 | 含义 |
|---|---|
| `0x14bbe4` `movw r0,#0x162` | 354 |
| `0x14bbec` `sub r3,r10,#0x162`；`0x14bbf0` `cmp r3,#2`；`0x14bbf4` `bhi 0x14bc24` | id 不在 354–356 → 走默认分支 |
| `0x14bc24` `mov r11,#100`；`mov r1,#1`；`mov r0,#0`；`mov r2,#0` | 默认分支：A[0]、A[1]、B[0]、阈值 100 |
| `0x14bbfc` `mov r7,#35`；`0x14bc00` `sub r2,r10,#0x161` | 阈值基数 35；孔数表下标 = id − 353 |
| `0x14bc08` `add r1,r0,r3,lsl #1`（r0=3） | 第二技能表号 = 3,5,7 |
| `0x14bc10` `add r0,r0,r3,lsl #1`（r0=2） | 第一技能表号 = 2,4,6 |
| `0x14bc34`–`0x14bc48` | `A = 基址+0x1c`（8 个 amskl 指针）、`B = 基址+0x3c`；取 `A[r0]`（第一）、`A[r1]`（第二）、`B[r2]`（孔数） |

| 护符 | 第一技能 `amskl` | 第二技能 `amskl` | 孔数 `amslt` | 种类组（§5） |
|---|---|---|---|---|
| 353 谜之护符 | 00（59 条） | 01（**空表**，0 条） | 00 | 1–2 |
| 354 发光护符 | 02（71 条） | 03（74 条） | 01 | 3–4 |
| 355 陈旧护符 | 04（56 条） | 05（105 条） | 02 | 5–7 |
| 356 风化护符 | 06（62 条） | 07（94 条） | 03 | 8–10 |

- 条数 = `(文件长度 − 8) / 4`，逐文件整除（**SKL**，`armor-talismans.md` §5.4 同源）。
- **偶数表 = 第一技能、奇数表 = 第二技能**：该页原为 `[推断]`，此处升级为 `C`——`A[r0]`（偶数）喂给第一个技能槽（`0x14bc48` → `0x14bc74`），`A[r1]`（奇数）喂给第二个槽（`0x14bc38` → `0x14bd70` 起）。
- 访问器：`rAmuletSkillData 0x12806c` / `rAmuletSlotData 0x1284cc` 同一形态——`count = [表+100]`；`if (count <= index) return 0`；`return [表+108] + index*8`。即内存里每行 **8 B**，有效载荷在 `+4`（文件里为 4 B：`{u8 树, u8 0, s8 下限, u8 上限}`）。
- `rAmuletData 0x127bb8`（`amuletData.amlt`）同形态但步长为 **16 B**，唯一调用点是通用表分派器 `0x13c3d0`（`C`）。

## 3. 技能池与点数

### 3.1 池子的形状（**SKL**，逐表取自 `armor-talismans.md` §5.4；§3.4 为本页一手复验）

| 表 | 条数 | 树 id 范围 | 下限 | 上限 | 角色 |
|---|---|---|---|---|---|
| 00 | 59 | 1–134 | +1 | +10 | 谜之护符·第一 |
| 01 | **0** | — | — | — | 谜之护符·第二（恒无） |
| 02 | 71 | 1–133 | +1 | +10 | 发光护符·第一 |
| 03 | 74 | 1–134 | −10 | +13 | 发光护符·第二 |
| 04 | 56 | 5–133 | +1 | +8 | 陈旧护符·第一 |
| 05 | 105 | 4–161 | −10 | +13 | 陈旧护符·第二 |
| 06 | 62 | 5–133 | +1 | +10 | 风化护符·第一 |
| 07 | 94 | 5–179 | −7 | +13 | 风化护符·第二 |

- 第一技能表的池永远非负（+1 起），第二技能表的池含负值——这与 §3.3 的「正负 50/50」是两件事：正负由点数 roll 决定，池子只决定**该槽可能出现哪些树、以及点数绝对值上限**。
- 树 id 上限 179：180 以上（复合/二名/身体系统/秘术等）不进任何护石池（`armor-talismans.md` §5.4）。

### 3.2 抽哪个技能：等概率（`C`）

`0x14bc4c` 取 `count = [表+100]`，为空则跳过；否则 `0x14bc64` 取随机数 → `0x14bc68` 载入 count、`0x14bc6c` `udiv`、`0x14bc70` `mls` 求余，算出 `index = rand % count` → `0x14bc74` 调 `rAmuletSkillData(表, index)`。第二个技能槽同样处理（`0x14bd7c`–`0x14bd9c`）。

⇒ **同一张表内，每条记录的命中概率 = 1/count，与点数上限无关**。例：风化护符第二技能池（07）94 条，任意一条都是 1/94。

### 3.3 点数怎么掷（`C`）

| 步骤 | 指令 | 规则 |
|---|---|---|
| 取该条的 `[min, max]` | `ldrsb r0,[r9,#7]`（max）、`ldrsb r6,[r9,#6]`（min） | s8 |
| 无负点数标志 ≠ 0（炼金） | `0x14bca4` `bne 0x14bcf8` | **只走正分支** |
| 否则掷符号 | `0x14bca8` rand、`tst r0,#1`、`bne` | **奇数 = 正，偶数 = 负（50/50）** |
| 正分支 | `r7 = max`、`r6 = 1`，`0x14bd08` 起 `rand % r7` 后 `add r6, r0, r6` | 均匀取 **+1 … +max** |
| 负分支 | `r7 = 1 − min`、`r6 = min`，同样 `rand % r7` | 均匀取 **min … 0** |
| 点数 0 | `0x14be4c` `cmp r7,#0`；`moveq r5,r7` | 该槽按「无技能」处理（树 = 0） |

- 由此推出两条可直接用的概率（`C` + 算术）：
  - 某个正数 `v`（1 ≤ v ≤ max）的概率 = `1/2 × 1/max`（鉴定路径），炼金路径 = `1/max`。
  - 表中下限为负的条目，在鉴定路径下取到 **0（等于没有该技能）** 的概率 = `1/(1−min)`（min = −10 → 约 9.1%）。
- 第二技能槽额外有两道闸：**空表**（01）与**概率闸**（§3.5）。

### 3.4 一手复验（本页实测字节）

- `amuletSkillData01.amskl` = 8 B，`count = 0`（空表）——谜之护符的第二技能恒不存在。
- `amuletSkillData00.amskl`（59 条）：下限全为 **+1**，上限 3–10，树 1–134；攻击 = **+1…+4**，池内没有匠。
- `amuletSkillData02.amskl`（71 条）：下限全为 **+1**，上限 3–10，树 1–133；攻击 = **+1…+4**，池内没有匠/痛击。
- `amuletSkillData03.amskl`（74 条）：下限 −10…−3，上限 3–13，树 1–134；攻击 = **−7…+7**，池内没有匠/痛击。
- `amuletSkillData06.amskl`（62 条）：下限 **+1…+5**（全为正），上限 5–10，树 5–133；痛击 = +2…+6；**池内没有攻击、没有匠**。
- `amuletSkillData05.amskl`（105 条）：树 18 攻击 = **−10…+10**、树 35 匠 = −5…+5、树 71 痛击 = −3…+3、最大树 id = 161、最大上限 = 13。
- `amuletSkillData07.amskl`（94 条）：树 18 攻击 = **−7…+10**、树 70 达人 = −7…+10、树 35 匠 = −3…+5、树 71 痛击 = −3…+5、树 120 = −5…+12、树 162–179 = −3…+3、最大树 id = 179、最大上限 = 13。
- 直接推论：**原值 攻击 +10 只可能来自表 05（陈旧护符·第二）或表 07（风化护符·第二）**；发光护符（03）的攻击最高 +7，谜之护符（00）最高 +4（`B`+`C`）。
- 同一条读法下的其他上限（本页实测 02/03/05/06/07）：**匠（树 35）不在 02、03、06 的池里**，只在 05（−5…+5）与 07（−3…+5）⇒ 匠 +5 只能来自陈旧护符或风化护符的第二技能槽（出现率 75% / 85%，§3.5）。**痛击（树 71）**在 05 只到 +3、07 到 +5、**06 到 +6**（+2…+6）⇒ 痛击 +6 只能来自风化护符的第一技能槽。**攻击（树 18）不在 06 的池里**，因此风化护符的攻击点数也只能从第二技能槽（07）出。

### 3.5 第二技能出现率（`C`）

`0x14bbfc` `mov r7,#35`；`0x14bc14` `add r3,r3,r3,lsl #2`（r3 = 5×(id−354)）、`0x14bc18` `rsb r3,r3,#0`（r3 = −5×(id−354)）、`0x14bc1c` `add r11,r7,r3,lsl #1` ⇒ **r11 = 35 − 10×(id−354)**；默认分支（谜之护符）为 100。`0x14bd68` `cmp rand%100, r11` + `0x14bd6c` `bcc` 跳过第二技能：

| 护符 | 阈值 r11 | 第二技能出现率 |
|---|---|---|
| 353 谜之护符 | 100（默认分支） | **0%**（叠加空表，双重保证） |
| 354 发光护符 | 35 | **65%** |
| 355 陈旧护符 | 25 | **75%** |
| 356 风化护符 | 15 | **85%** |

## 4. 孔数概率（`amuletSlotData00..03.amslt`）

### 4.1 格式与列义

- 8 B 头（f32 `30.0` + u32 `21`）+ 21 × 4 B `{u8, u8, u8, u8}`；4 个文件均 92 B（**SLT**）。
- 四列 = **0 孔 / 1 孔 / 2 孔 / 3 孔**的百分比。该页原为 `[推断]`，此处升级为 `C`：`0x14bf4c` 起 `rand%100`，然后按列顺序做**累计阈值**判定——`[row+4]` 先比（命中即 0 孔），再累加 `[row+5]`（1 孔）、再累加 `[row+6]`（2 孔），余下为 3 孔（`movwhi r0,#2` 分支）。

### 4.3 选哪一行（`C` 数据流 / `[推断]` 公式）

- 行号不是随机的：`0x14bea8`–`0x14bf24` 对两个技能槽的点数各做一段 VFP 运算，`0x14bf28`–`0x14bf48` 收尾并把结果转成整数（`vmov r5, s0`，前面 `0x14bf40` 一带应有整数/浮点转换）——该整数即行号，再作为 `rAmuletSlotData(孔数表, r5)` 的下标（`0x14bf54`–`0x14bf5c`）。
- 访问器对 `index ≥ count` 直接返回空指针（`0x1284d8`–`0x1284dc`），所以该分数必然被限制在 **0–20**：行号是一个「点数评分档」，0 = 最好的一档、20 = 最差。
- 精确公式（除数、两个技能点的权重）尚未解出 → §9 #1。方向性结论也留空：本仓库现有证据**不足以**断言「点数越高孔越好」或相反。

### 6.3 炼金结果的点数在炼金时就已掷好（`C`）

所有炼金分支都以 **第 4 参数 = 1** 调 `sMakeAmulet`（`0x196904`、`0x196b8c`、`0x196708` 均 `mov r3,#1`）。调用之后，代码把 36 B 结果里的 5 个字（20 B，`0x196928` 起的 `ldm/stm` 对）和一串 `strh` 写的护符 id（`0x19694c` 等）一起存进「待收取」结构。含义：

1. **炼金路径永不出现负点数**（标志 = 1 → 跳过 50/50 符号掷），与官方文案一致（`C`）；
2. 产出的护符在**炼金时就带着一份掷好的结果**（`C`）；官方文案仍称产出为「护符」，即仍需经鉴定才显示能力。「鉴定时取用这份存下的结果，还是重新掷」本页未证 → §9 #8。

## 7. 存档：`+18..19` 就是来源护符的道具 id

`armor-talismans.md` §5.6 记的是「`+18` 种类常量 97/98/99/100、`+19` 常量 1」。本页给出统一解释：

- `sMakeAmulet` 在 `0x14bbe8` 执行 `strh r10,[r4,#22]`，把**护符道具 id（u16）**写进记录 `+22`（`C`）；
- 该记录与存档 36 B 护石记录相差 4 B：`+4` = 类型（`0x14bbcc` 先 `and #0xffe0` 再 `orr #6`）、`+6` = 种类（`0x14c098`）`strh`、`+16/+17` = 树（`0x14bd30`/`0x14be58`）、`+18/+19` = 点数（`0x14bd34`/`0x14be5c`）、`+20` = 孔数（`0x14bfd4`）——7 个字段与 E 的 `+0/+2/+12/+13/+14/+15/+16` 逐一对应，故 `+22` = **存档 `+18`**（`[推断]`，依据是 7 字段全对齐）；
- 353–356 = `0x0161`–`0x0164`：低字节 `0x61`–`0x64` = **97–100**，高字节 = **1**。

⇒ 存档 `+18..19`（u16 小端）= 该护石由哪种护符生成（353 谜之 / 354 发光 / 355 陈旧 / 356 风化）。E 的两条「常量」是同一 u16 的两个字节，这也解释了「4 组 × 10 种类」的组数来源。
