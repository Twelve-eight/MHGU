# 怪物部位与体力（HP / 部位破坏 / 断尾 / 捕获）

> **三行摘要**
> - 一只怪的实际体力 = **基础 HP × 任务 HP 倍率**：基础 HP 存在怪物自己的 `dttune` 文件里（romfs 字节，已与第三方库逐字节互证），任务倍率在任务数据里只存一个**表号**，由游戏再查隐藏的难度表。
> - 部位破坏 / 断尾按**部位**累积伤害，与本体 HP 是两套计数；断尾的武器类型限制按系列惯例推断 [I]。
> - 捕获需把怪的血量压到**低位**（表现为跛行回巢）+ 陷阱 + 捕获玉 [I]；**具体阈值未解**（主程序内候选线索：`mParam.hokaku_point` 字段）。

状态标记：`[C]` = romfs 字节与仓库既有数据双重验证；`[B]` = 直接读到 romfs/main 字节（结构确认）；`[I]` = 推断或仅第三方库（mhgu.db = MHGenDatabase v2.4.0）；`[U]` = 未核实。

---

## 1. 基础 HP：数据在哪、怎么读

每只怪的资源包 `romfs/nativeNX/arc/enemy/emNNN_00.arc` 里有 `enemy\dt_tune\emNNN_00_dttune`（zlib 压缩，ARC 容器）。解码格式见 `docs/reference/formats/dttune.md`：

| 字段 | 位置 | 验证 |
|---|---|---|
| 基础 HP | dttune `0x38` u32（**唯一定长字段**） | em001 雌火龙 4500 / em002 火龙 4200 / em013 黑龙 9000，与 `mhgu.db monsters.base_hp` 逐字节一致 [C] |
| 肉质表（9 列 × 8 部位） | dttune 内偏移**逐怪浮动**（实测 0x8E、0x8F…） | 雌火龙/火龙/黑龙/斩龙均与 `mhgu.db monster_damage` 一致（各怪实测定位后对拍）[C] |
| 状态阈值（毒/眠/麻/气绝/减气/骑乘/跳跃/爆破） | dttune 内偏移**逐怪浮动**（0x324/0x35C…，个别怪缺失） | 与 `mhgu.db monster_status` 一致（已定位怪）[C] |

注意：dttune 的头部长度**逐怪有差异**（em001 头部 0x0E 字节 `37 0c …`，em080 为 `43 0e …`），肉质/状态表偏移必须**逐怪定位后才能引用**；全怪物逐怪偏移将由 `docs/data/json/monster-dttune-index.json`（DtTuneAll 批处理）发布 [B]。

## 2. 任务 HP 倍率：任务里存的是表号

任务文件 `loc/quest/questData/questData_<7位id>.ext`（记录格式见 `docs/data/romfs-tables.md` §2）里每个目标怪物带一个 13 字节槽（记录偏移 0x05C 起）：

| 偏移 | 字段 | 语义 |
|---|---|---|
| +0 | Id u16 | em 编号 |
| +5 | HealthTbl u8 | **HP 难度表号** |
| +6 | AtkTbl u8 | 攻击表号 |
| +7 | OtherTbl u8 | 其它表号 |
| +9 | Size u16 | 个体大小（% 基准 100） |
| +0xC | StaminaTbl u8 | 疲劳参数号 |

本次用自写脚本（`.tmp/mhgu-scratch/quest-decode.mjs`）解码全部 1849 个 .ext：287 个 (怪物， 敌等级) 组合，表号为 0..135 的整数索引 [B]。

### 2.1 难度表本体（em_nando_tbl）

`loc/arc/resident.arc :: enemy\resident\em_nando_tbl`（4528 B = magic `NAN\0` + 12 B 头 + 141 × 32 B = 4516…4528，行自 0x10 起）[B]。每行 = `{f32 A, f32 B, f32×6 修正}`，A 从 0.1 单调升到 6.5（前段约 +0.03/行，后段 +0.05…+0.2/行），B 从 0.5 升到 21.0。任务里的 `HealthTbl` 索引直接指向该表行：

| 索引→A（=HP 倍率） | 例 |
|---|---|
| 13 → 0.49 | 村★4 雌火龙（q409） |
| 19 → 0.67 | 集★2 雌火龙（q10219） |
| 49 → 1.57 | G 级雌火龙低端 |
| 60 → 1.90 | 老山龙斗技？ |
| 85 → 2.75 / 102 → 3.60 | G 级高端 / EX 级 |
| 30 → 1.00 | 老山龙村级（q90016） |

**换算**：实际 HP ≈ 基础 HP × A。量级全部落在合理域（G 级雌火龙 4500×1.57–3.60 = 7065–16200），但绝对值尚未实机校验 → **公式 [I]**，表本体位置与结构 [B]。

玩家侧结论（不依赖精确数值）：
1. **同一只怪，村★4 → 集★2 → G 级的 HP 倍率单调上升**，G 级约是村★4 的 3–6 倍 [I]。
2. 任务文本与报酬表**完全看不出** HP 差异，同一星级内的怪也可能用不同表号 [B]。
3. 连战任务（双目标）每只怪独立取各自槽位的表号 [B]。

### 2.2 表的 8 个列各是什么（2026-10 逆向结论）

| 列 | 行内偏移 | 范围（全 141 行） | 角色 | 证据级 |
|---|---|---|---|---|
| A | +0x00 | 0.10..6.50（141 个不同值，逐行单调不降） | **HP 倍率**（HealthTbl 选择） | [C] |

行窗口说明 [C]：行 128..140 的 C..H **全为 1.00**，所以「行 0..127」与「全部 141 行」在后 6 列上同域；而 A/B 的最大值只出现在行 128..140（A 4.90..6.50 / B 15.00..21.00）。旧表头写「行 0..127」却填进 A/B 的 6.50/21.00，行窗口自身不自洽，本次统一按全表给。

**D 列 = 攻击倍率（[B] 强）**——三条可复算证据（`[C]` 只覆盖「表结构 + 选择器字节」，不覆盖「引擎真的把 D 乘进攻击」）：

1. **只有 D 存在「单列孤立递增族」**：固定其余 5 列，族内该列取 ≥3 个单调值即记一族 → D 有 **7 族**（行 60..64 = 0.90/1.00/1.25/1.35/1.50，其 C/E/F/G/H 全等 0.90/1.25/1.05/0.30/0.80；行 65..69 = 1.60/1.80/2.00/2.20/2.40 而 E 冻结在 2.00；行 73..75 = 1.40/1.50/1.60 而 E..H 全为 1.00），C/E/F/G/H 各 **0 族**。即「只让一项变强」的档位永远动 D。
2. **随难度单调爬升**（2672 个目标槽按 EnemyLevel 取各自 AtkTbl 行的列值，中位）：D = 1.00 / 1.20 / 1.40 / **2.30**（村下位 / 集下位 / 上位 / G 级；均值 1.09 → 2.56）；同期 C 反向为 1.00 / 1.00 / 0.85 / 0.75，E 为 1.00 / 1.20 / 1.50 / 2.00，H 为 1.00 / 1.00 / 1.10 / 2.10。
3. **极值只在最高难度**：全表 max D=6.00 是行 104（A 3.70），仅 5 槽（Level 14 = G★4 占 4 槽、二名 113 占 1 槽）；Atk 实际选中的 108 个行覆盖 D 0.40..6.00。

**getter 级证明**（哪个 f32 落进怪物对象的哪个字段）仍 [U]——`rEnemyNandoData` 行对象由 ctor 0x564bc 构造、经 vtable 属性访问器读取，静态代码里没有可指认的乘法点。两条未闭合的反证也记 [U]：狞猛化任务（槽 +0x03 = 1，如 q11333「The Pinnacle of Terror」）最常用的 Atk 行是 108/109（用 108/109 的 83 槽里 65 槽带该标志；D=1.95/2.00，**低于**同段普通任务行 92/93 的 2.30/2.40）→ 狞猛化的攻击加成不在 D；D 的最小值 0.40（行 100，36 槽 = 二名 109/110/115 共 24 槽 + G★3/G★4 12 槽）与「难度越高倍率越高」相反，语义不明。

结构性事实（均 [C]，2026-10-26 全量重算）：AtkTbl 与 OtherTbl 选**不同的行**（Atk 用 108 个不同行、Other 65 个；仅 195/2672 槽 = 7.3% 同号；相关系数 0.87 Health↔Atk、0.92 Atk↔Other）；行 60..64 族内 C..H 只动 D（0.90/1.25/1.05/0.30/0.80 全等），Atk **51 槽**选它（上位 50 + 村下位 1）、Other 0 槽，Health 也有 142 槽用它——与狞猛化标志无关；行 72 是 A 2.26 / B 3.70 / C..H 全 1.00 的「无修正」预设，**101 槽**的 Atk 用它（Other 0 槽）；行 128..140 的 C..H 全为 1.00，属「高 A、无修正」的填充行：Other 从不选（实测最大 118），Atk 仅 8 槽选行 128/130/131/132/135（全是二名 EX Level 116，D=1.00），Health 有 1 槽选行 135。（旧版「38 槽 / 88 槽 / 行 128..140 从不被选择」三个 [C] 数字与实测不符，已按上句更正。）

对玩家的意义（[I]）：任务难度不只加血——**攻击倍率（D 列）与防御侧系数（C 列）同样随难度变化**，G 级怪打得更痛、也更抗打；「全体防御率」不再是黑盒，而是一个 1.00→0.35 的表列。

## 3. 部位破坏与断尾

### 3.1 机制

- 每个部位有一个**耐久值**，怯核和破坏共用；断尾另有一个**切断耐久**。数值存在 dttune 0x3C 起固定 80 字节的部位耐久块（格式见 `docs/reference/formats/dttune.md`「Part durability block」）[C，138 个文件，2026-10-26]。雌火龙：胴 140、翼 100/100、脚 180/180、颈 90、头 190、尾 150、切断 230；火龙：胴 150、翼 100/100、脚 190/190、颈 90、头 230、尾 120、切断 320；角龙：胴 350、切断 500。
- 断尾条件：**斩系物理伤害**累积到尾部阈值；打击、弹药、属性伤害不参与累积 [I]（系列通用规则，本作数值未解码）。
- 部位资源包里的 `enemy\dt_base\*_dtbparts`（magic `DTP`）有记录流 `{u32 数值, u32 部位id(100+), 位域}`（雌火龙 5097@101 等）。2026-10-26 复核：这一段在雌火龙和火龙上逐字节相同，与两者不同的部位耐久对不上，所以**不是**部位体力，不要引用；各怪的 dtbparts 文件整体并不相同（40 多种大小）（`.tmp/reports-rds/rev-gu-break-values.md`）。
- dttune `0xE6..0x18A` 的 f32 串（500/6000/1500/…/2500/5000，怒时类数值对）与 db 无对应，格式文档标 [U]；其中含怒时失衡/眩晕调参的可能。

### 3.2 玩家怎么知道破坏进度

- 部位外观变化（角断/壳裂/尾断）即破坏完成，**游戏不给进度条**。
- 狩猎笔记（HN_MonsterListMsg_chS）的弱点提示不含部位 HP。
- 需要精确「破坏耐久表」请看 `待补` §6。

## 4. 捕获：阈值与条件

### 4.1 阈值证据

- 主程序 `.text` 内嵌常量对 **f32 0.35 / 0.65**（vaddr 0xF513A0/0xF513A4）[B]。两者属于**函数 `0xF511DC`** 的常量池（0xF513A8 是池后的另一个函数），由该函数读取（`vldr s0,[pc,…]`@0xF5122C → 0.35、`vldr s7`@0xF51248 → 0.65），用于 `new = 0.35·原始值 + 0.65·上一帧值` 形式的指数平滑（对象 +0x40/0x44/0x48 → +0x1D0..+0x1D8）。**因此这对常量更像插值权重，不是捕获阈值证据** [I]；捕获阈值本身 [U]，候选线索见下。
- 网络同步参数块字段名串池含 `mParam.hokaku_point`（捕获蓄积，flat 0x1559AE2）与 `mParam.hp_vital`（HP 同步字段）[B]（`mParam.*` 名池）。
- 任务记录 `GekitaiHp`（击退血量阈值，rec+0x016）只用于「讨伐或击退」型任务，与捕获无关 [B]。

### 4.2 捕获的玩家规则

1. 把怪的血量压到**低位**后才能捕获成功；最可靠的时机信号是**跛行**（一瘸一拐换区/回巢睡觉）[I]（精确百分比 [U]）。
2. 需要**陷阱**（落穴或麻痹陷阱）+ **捕获用麻醉玉**（陷阱中投掷；陷阱有效期内 2 颗内生效）[I]。
3. 任务目标是「捕获」时，**杀死目标 = 任务失败**；目标是「狩猎/讨伐」时，捕获也算完成（报酬按捕获结算）[I]。
4. 古龙种**不可捕获**（陷阱无效）[I]；老山龙等特殊体型怪同样不可。
5. 部位破坏与捕获互不冲突：捕获结算同样拿得到破坏素材 [I]。

## 5. 一页结论（玩家版）

> 本节为玩家向速览，均为 [I]/[U] 级推断；硬数据（逐怪字节）见 §1–§2。

1. **血条是「基础 HP × 任务倍率」**：同一只怪在村、集会所、G 级完全是三个血量；G 级怪血量约是村级同怪的 3–6 倍 [I]。
2. **基础 HP 硬数据存在**（每怪 dttune +0x38，[C]/[B]）；主流库（mhgu.db）与 romfs 在已对拍的 7 只怪中 6 只逐字节一致（斩龙两源冲突，见 §1.1）。
3. **部位破坏看外观不看血条**：每个部位有独立耐久（雌火龙头 190、尾切断 230 等，见 §3.1），游戏内不显示。
4. **断尾只能用斩系武器**；锤/狩猎笛/弩枪打尾部不累计断尾值 [I]（系列惯例，本作数值未解码）。
5. **跛行 ≈ 进入可捕获血量** [I]（精确阈值 [U]）；捕获任务别手滑杀死，狩猎任务捕获不亏。
6. 古龙不能抓，陷阱对它无效 [I]。
