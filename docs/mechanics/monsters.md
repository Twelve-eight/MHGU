**wiki 的排序 ≠ 存档顺序**（关键结论）
- wiki 采用**五十音分组**：侧栏分 `[大型A行] [大型K行] [大型S行] [大型T行] [大型N～H行] [大型M～R行]` 六块（原文为日文假名行名，此处按首音字母转写），组内按中文译名音读排列，正体/亚种/二名**不一定相邻**（例：`金火龙`、`紫毒姬雌火龙` 排在 `雌火龙` 之后但在 `雄火龙` 之前，属同一「M～R行」块）。
- `MonsterForm` 的 137 行按**槽号原序**排列，分四段：`0..70` 大怪（MHX 本传阵容，族谱式：正体 → 亚种/稀有种 → 该正体的二名）、`71..111` 小怪、`112..134` 大怪（MHXX 回归怪 + XX 新二名/特殊个体，尾部 133/134 是阁螳螂两形态）、`135..136` 小怪（大雷光虫 / 小桃毛兽）。大怪段仍是族谱式；小怪段夹在中间是引擎表的原样，不是编辑器的排版选择（分块表见 §12）。
- 因此「wiki 第 N 个大型怪」和「存档第 N 槽」**没有任何对应关系**，不能用作槽号推导。

**总表（`2501`）的字段规则**（读表前必读）
- 列：`怪物名 | 状态 | 斩 | 打 | 弾 | 火 | 水 | 雷 | 冰 | 龙 | 麻痹陷阱 | 落穴陷阱 | 闪光玉 | 音爆弹 | 陷阱肉`。
- `斩/打/弾` 三列填**该攻击类型最有效的部位**（不是数值）；`火/水/雷/冰/龙` 填相对等级符号；后五列是道具是否有效（`※` = 有条件有效）。
- 等级符号：`◎ > ○ > △ > × > 无`（左端最有效，`无` = 无效）。
- 一行常被拆成多种「状态」子行（`下位·上位` / `G级`、`通常时` / `怒时` / `部位破坏后` / `暴走时` …），子行可继承上一行的道具列 ⇒ 扁平化文本里出现「列数不齐」是正常现象。**需要精确数值时必须去单个怪物页**（`2501` 只有部位名与符号）。

## 2. 体力（HP）模型

wiki **不给出任何绝对体力值**：`出现任务` 表里的「强度条」只画相对强弱，页脚说明原文含义为：绿色 = 体力倍率、橙色 = 全体防御率，二者汇总成条；且「怪物固有的体力不同，不能用于跨怪物比较」。所以：

- **基础体力**只能取自机读库 `monsters.json` 的 `base_hp`（93 条大型全覆盖，见 §12 映射表）。
- **实际任务体力 = base_hp × 任务体力倍率**；`全体防御率` 是同一任务内的独立减伤系数（对玩家伤害）。两个倍率**都不在当前任何数据源里**（`quests.json` 只有报酬/HRP/限制，没有 HP 倍率；`monster_to_quest.json` 只有 `unstable`/`hyper` 两个标志）⇒ 具体倍率标 `[未确认]`，只能靠实机或拆包 quest 表补。
- 量级参考（`base_hp`）：最低 `大野猪王 1800`、`蓝速龙王/彻甲虫/跳狗龙 2000`；常规主力怪 3200–6000；古龙跨度很大（`麒麟 3200`、`钢龙 4200` → `岚龙 8700`、`骸龙 14000`）；超大型 `老山龙 25000`。二名普遍比正体高（例：`荒钩爪 6000` vs `轰龙 5000`；`银岭巨兽 6800` vs `巨兽 5400`）。
- 捕获判定：wiki 未给阈值，`monster_weakness.json` 也不含此字段 ⇒ `[未确认]`（编辑器若要显示「可捕获」必须另找信源）。

## 3. 肉质（hitzone）模型

### 3.1 字段结构（两源完全一致）

单页 `肉质` 表 = `部位 × 9 列`：

`切 | 打 | 弾 | 火 | 水 | 雷 | 冰 | 龙 | 气绝`

- 数值为伤害百分比（`0` = 完全免疫该属性）。
- **括号内 = 特定状态下的肉质**，由页面上的注记说明是哪种状态（常见：愤怒时、部位破坏后、赤热时、青白时、超带电状态、暴走时、覆雪装甲时、被钓起时）。镜像里这些注记是日文原句，此处按语义转写。
- `气绝` 列 = 该部位造成的眩晕（KO）值；只有头部等少数部位非 0（轰龙头 `100`，愤怒 `130`）。
- 机读库 `monster_damage.json` 用英文部位名分行，并对「有愤怒肉质变化的怪」额外给出 `(Enraged)` 行；`(Break)` 等后缀表示破坏后形态。

**交叉验证（逐值一致）**：`雌火龙` wiki 头 `90/80/70/0/15/20/15/35/100` = `monster_damage`(monster_id=1, Head) 同值；`轰龙` wiki 头 `65(70)/55(65)/55(60)…气绝 100(130)` = `monster_damage`(32, Head) 与 `Head (Enraged)` 同值。⇒ **两源肉质可直接互替**，wiki 多出的只是「愤怒/破坏/特殊状态」的括注。

### 3.3 弱点表（单页 `怪物的弱点`）与符号

- 结构：`斩 | 打 | 弾` 填最有效部位（可并列两个，如 `头`+`脚`），元素列填相对等级 `◎○△×`。
- 该符号是**同一只怪内部的相对强弱**，不是跨怪绝对量表。
- `monster_weakness.json` 的 `fire/water/thunder/ice/dragon` 是 0..6 的**另一套序数**，与 wiki 符号**不同源、不能硬映射**：`雌火龙` DB `火1 水3 雷4 冰3 龙5` 与 wiki `× △ ○ △ ◎` 恰好同序；但 `雄火龙` DB `雷6 / 龙5` 而 wiki 标 `雷○ / 龙◎`（6 大于「◎」），`黑龙` DB `火4 水1 雷2 冰1 龙5` 而 wiki 为 `火○ 水× 雷× 冰△ 龙◎` ⇒ 只有在同一只怪内比较大小才有意义。`0` = 该属性无效。

### 5.2 机读库侧：蓄积阈值（wiki 没有）

`monster_status.json` 全表 **728 行 = 91 只 × 8 行**：每怪固定 8 行 `Poison / Sleep / Para / KO / Exhaust / Mount / Jump / Blast`，字段 `initial`、`increase`、`max`、`duration`、`damage`。**93 只大型里只有 2 只没有行：老山龙(12) 与 黑龙(13)**（攻城/巨型战不设异常蓄积；红黑龙 269 / 祖龙 525 有行）。

- 语义：首次触发需 `initial` 点蓄积；第 k 次触发阈值为 `initial + (k-1) × increase`，上限 `max`。
- **免疫编码**：某状态整行 `0/0/0/0/0` = 该状态无效（例：骸龙的眠/麻/晕/减气/骑乘/爆破全 0，只吃毒 400；天慧龙减气 0；阁螳螂爆破 0）。与 wiki 的「无效」逐条对应。
- 自洽校验：`max = initial + 4 × increase` 在毒/眠/晕/减气/骑乘上成立（雌火龙 毒 180+4×100=580 ✓、晕 150+4×150=750 ✓、骑乘 80+4×120=560 ✓），麻痹 `180+5×110=730`、爆破 `70+20×30=670` 用别的次数收口 ⇒ **各状态的「可触发次数」不同，公式细节 `[未确认]`**。
- `damage`/`duration` 与 wiki **大体一致但非完全**（雌火龙 毒 150/60、轰龙 毒 240/60、荒钩爪 爆破 80、轰龙 爆破 100 都对得上；**反例**：天慧龙麻痹 `duration` 库里是 **9 秒**、wiki 写 10；煌黑龙的爆破行在库里是 `0/0/0/0/0`（无效），wiki 仍给 100）。所以**不能无条件用 JSON 覆盖 wiki**，冲突时按 `monster_status` 为准并逐条核。
- **二名 vs 正体**：`荒钩爪(1056)` 与 `轰龙(32)` 的毒/麻/眠/晕/减气/骑乘阈值**完全相同**，仅 `Jump`（60/90→70/110）与 `Blast`（伤害 100→80、`increase` 30→50）不同 ⇒ 二名差异主要体现在 HP、肉质、耐久值、抗骑乘，而不是异常蓄积。

## 10. 剥取 / 捕获 / 掉落物 / 生息地（数据模型）

## 11. 小型怪物与「总表」缺口

- `2502` 小型怪物一览：镜像里**只有名字与表头，所有数值列都是空的 / `-`**。原因是原站该表由 JavaScript 渲染（页面残留「JavaScript 无效…此功能无法使用」提示），爬虫取不到数据 ⇒ **小型怪物的肉质/弱点无法从 wiki 获得**。
- 小型怪物只能靠机读库，但机读库也只有「名录」：`monsters.json` 有 36 条（`class=1`，`_id` 4097..4144，`base_hp` 全 0 = 不适用），**`monster_damage.json` 只覆盖 93 只大型怪**（`[.[].monster_id]|unique|length = 93`）⇒ 小型怪的肉质/弱点**两个信源都没有**。
- 用途差异：小型怪**有自己的击杀槽**（71..111、135..136，计数真实，§13.3），但**不参与捕获与尺寸表**（8 个 `.hnt` 里 43 个小怪槽的捕获与尺寸记录全 0）⇒ 狩猎记录里的小怪只有讨伐数；它们同时是任务副目标（`monster_to_quest.json` 里以 4097..4144 号段出现）与生态对象。
- 槽位与名称不同量：137 槽里 43 个是小怪槽（71..111、135..136），但 `monsters.json` 只有 **36** 条小怪、chS 名表也只有这 36 个名字 ⇒ 槽 105..111（emid 4196..4202）**无名字**（资源全部 `roEms100.cro`），只能按编号显示；它们照常有击杀计数（槽 106 = 小型怪物#4197：clean 档 5、HR198 档 29）。

## 13. 与存档的关联（怪物统计 / 尺寸 / 索引映射）

### 13.1 存档字段（char_off，权威值来自 `DEVELOP.md` §怪物统计）

| 字段 | obj 偏移 | char_off 区间 | 长度 | 结构 |
|---|---|---|---|---|
| 击杀计数 | `obj+0x72C` | `0x5EA6..0x5FB7`（**24230..24503**） | 274 B | u16 数组（137 × u16，无表头；§13.3） |
| 捕获计数 | `obj+0x83E` | `0x5FB8..0x60C9`（**24504..24777**） | 274 B | 同上，同构 |
| 尺寸记录 | `[obj+0x950]` 表 / `[obj+0x954]` 条数 变长读入 | `0x60CA..0x62ED`（**24778..25325**） | 548 B | 每槽 `u16 mini + u16 maxi`（4 B × 137 = 548，无表头） |

编辑器读点（`MonsterForm.cs:173-175` 定义基址、`:196` 单循环 137、`:201-205` 读值）：

```
击杀:      24230 + 2*i     (i = 0..136，i 就是槽号)
捕获:      24504 + 2*i
尺寸 mini: 24778 + 4*i      (只取低字节)
尺寸 maxi: 24778 + 4*i + 2  (只取低字节)
```

- `24230 (0x5EA6)` 就是击杀数组的**块首**，不是「块首 + 4」：`0x5EA2..0x5EA5` 那 4 B 属成员#4 尾部（`DEVELOP.md` 2026-10-23 定案）。三条 stride 与块长自洽：`24230 + 137*2 = 24504`、`24504 + 137*2 = 24778`、`24778 + 137*4 = 25326 = 0x62EE`（= 装备箱起点，§13.3）。
- 计数器为 **u16**（0..65535），跨下位/上位/G 级累计，不区分等级；也没有「本次会话」之类的临时区。
- 尺寸值是**百分比**（推断基准 100：实测样本 `0x60 = 96`、`0x69 = 105`，只有以 100 为基准才讲得通）；编辑器控件 0..255 且只写低字节 ⇒ 若高字节非 0，写回会得到 `高字节×256 + 新值`（`audit-monster.md` F5/I-2，`[未确认]` 高字节是否恒 0）。
- 冠（大金冠 / 小金冠）：存档只存「遇到过的最小 / 最大体型」，**冠的判定阈值不在任何现有信源里** ⇒ `[未确认]`。若要显示冠，只能按「maxi ≥ 阈值 → 大金冠」实测标定（MHGU 的基准是 100%）。

### 13.2 槽号 ↔ 怪物：137 槽全覆盖

- 名字表与存档数组**等长同序**（137 ↔ 137，单循环 `MonsterForm.cs:196`），§12 已逐槽对上：94 个大怪槽（0..70、112..134）+ 43 个小怪槽（71..111、135..136），**没有无名槽**（槽 105..111 只有编号占位串 `小型怪物#4196..4202`，但槽存在、计数也真实）。
- 「旧代码跳槽」只剩历史意义：早期版本用两段循环，并在天慧龙之后留 `if (i != 91)`，使槽 92 不可达、第 93 行写到槽 93。现行代码是单循环 137，槽 91/92 分别 = `羚鹿`/`飞甲虫`（都是小怪），**没有空洞**。
- 逐槽可达性：`i = 0..136` 全部可达，写点 = `24230+2i / 24504+2i / 24778+4i`；数组末端精确接装备箱（§13.3 的闭合式）。
- 历史提法「槽 93..134 未知」**作废**：槽 93 = `甲虫`（emid 4123）、槽 112 = `岩龙`（emid 4）、槽 132 = `天慧龙`（emid 86）、槽 134 = `阁螳螂`（emid 88），全部有名可查（§12.2/§12.3）。

## 14. 给开发者的最小数据模型

```
Monster {
  i:        u8       // 0..136  槽号 = MonsterForm 行号 = 存档数组下标（§12 的「槽」）
  db_id:    u16      // monsters.json 的 _id（取多语言名/图标）
  kind:     物种     // 飞龙/鸟龙/兽龙/海龙/鱼龙/甲壳/牙兽/两生/蛇龙/鋏角/甲虫/牙龙/古龙/不明
  flags:    { deviant, variant, elder, capturable, hyper_capable }
  base_hp:  u32      // monsters.json base_hp（不含任务倍率）
  parts: [ Part {
     name,            // 头/首/胴/背/腹/翼/前脚/后脚/尾/尾先 …
     state:           // normal | enraged | broken | special(暴走/赤热/青白/超带电/雪装甲…)
     cut, impact, shot, fire, water, thunder, ice, dragon: u8   // 0..100
     ko: u8                                                    // 气绝值
  } ]
  durability: [ { part, value, cutting_value?, hyper_value?, aura_value? } ]
  status:  [ { kind, initial, increase, max, duration, damage, ease } ]
  items:   { shock_trap, pitfall_trap, flash, sonic, meat, dung: seconds|0 }
  threat:  { roar: 大/小/—, wind: 大/小/—, tremor: bool, bind, blights[], ailment }
  ecology: { initial_area, move_areas[], rest_area }           // 生息地
  save:    { kill_off: 24230+2i, caught_off: 24504+2i, size_off: 24778+4i }
}
```

**计算链**：`实际伤害 = 武器攻击力 × 动作值 × 肉质/100 × 全体防御率 × 其它`；`实际体力 = base_hp × 任务体力倍率`。两个倍率都缺（§2 / §15 U5）。

**属性选择**：以 wiki 单页「怪物的弱点」符号为准（同怪内相对），跨怪比较用 `monster_damage` 的绝对肉质数值，**不要**用 `monster_weakness` 的 0..6 序数做跨怪比较（§3.3）。
