## 尾部易变性的终局证据（pass7/pass8 + .hnt 对照）

**同一 .hnt 与 system 槽的逐区等值率**：

|---|---|---|---|
| `hunterB.hnt` vs **clean slot0** | **99.31%** | **100.00%** | 50.96% |

⇒ 结论巩固：尾部是**每次保存整体重写的缓存**，其边界只能是结构性质。

**宿主内存残留取证**：UTF-16 `android.gui.IGraphicBufferProducer` 类 Binder parcel 串出现在 sys slot1（7 处，含成员区 m13 `0x2E349`/`0x2EB39`）、dirty slot0（2 处）、`hunterB.hnt`（4 处），而 sys slot0 与 `hunterA.hnt` 为 0。⇒ **存档确实携带写入宿主（Android 运行时）的内存残留**，与 632B 头里 `0x270..0x273` 的栈垃圾同源。这类字节**无游戏语义**，「每字节可解释」对它们只需判定为「宿主残留」。

**16B 头数组归属**：`sys slot1`=7,292 条、`sys slot0/dirty/.hnt`=0 ⇒ 该数组只出现在 system 文件的特定槽快照，不是 .hnt 数据。

## 随从猫 324B 记录内部（`0x263368`，Palico324 定案）
7 个读块：`+0x000/32`(名字) → `+0x020/224`(主体) → `+0x100/14`(7×u16 id，逐项 `0x143894` 查名) → `+0x10E/12` → `+0x11A/36` → `+0x13E/4` → `+0x142/2`，和 = 324。
- **`+0x11A..+0x13D`(36B) = 9 × {R,G,B,0xFF} 四元组**（编辑器此前只标注了第 1 组=毛色、第 4 组=衣色；第 4 字节 27 次采样全 `0xFF`）
- **`+0x58..+0x5E` 不是「配信标志」**，是指针样残留（`0x066025E9`/`0x047759EA`）⇒ 编辑器 `+88..91==0` 的配信判定**不可靠**（待修）
- `idx("猎人A") = 156 = 0x9C`（rec0/1/2 三条一致）⇒ 记录内 `+0x9C` = 主人名
- member[6] 是同一结构模板的**未初始化槽**（整体 +0x7C 位移、12B/36B 块是指针垃圾）——与 member[7] 的 324B 模板同源，可作交叉印证

## 尾部性质的**重大更正**（2026-10-23，TailDense pass1-8）

先前的「尾部 = MHGU 序列化容器」判断需要收回一部分：

1. **`0x3783A` 不是内容边界**：`0x37835` 起是连续 float（646.91f / 646.77f / 646.63f），该切点落在第 2 个 float 的第 2 字节上；member[17] 的 2B 尾巴只是 reader 的末字段。
2. **真正的结构是 16B 定长记录网格**：零字节在绝对地址 `≡2 (mod 16)` 处 2.85× 集中（15,813 vs ~5,000）；`lag=16` 等值率 0.3977，`lag=15/17` 仅 0.154。相变点 `0x6383A`（1KB 密度 48%→93%），记录类型接管点 `0x63671`；头型数组实体 = **`0x63671..0xBCC20`（366,000B，22,875 条）**，`0x80000` 在其中部（**不是边界**）。
3. **phase B** = 单一 8B 前缀 `ff 00 49 92 24 49 92 24`（7,291/7,291 条，100%）+ 8B 高熵载荷（7.534 bit/B）；phase A = 2,670 种 8B 前缀混合。
4. **无容器格式**：无合法 zlib（25 个 `78 xx` 头 inflate 全失败）、无真实 4B/8B 长度前缀（`0x3F80` 候选全是 `00 00 80 3F`=float 1.0 的错位伪命中）、无 ≥64B 零洞、最大非零间隙 43B、无 0x10/0xFF 填充段、无真实 ASCII。
5. **该 16B 头数组只在 clean `system` slot1（猎人A）存在**：slot0/slot2/dirty slot0 全 0，同角色独立 `hunterA_HR5_V7.hnt` 也 0；`hunterB.hnt` 与 `system` slot0 该区 **100.00% 等值**且都无头数组。

⇒ **[INFERENCE，中-高] 尾段主体是某次保存留下的宿主/模拟器（Android）进程内存残留，不是 MHGU 序列化 schema 的固定字段**。旁证：Binder 长度头 `22 00 00 00` + UTF-16LE `android.gui.IGraphicBufferProducer`（slot1 共 7 处，含 member[13] 段内 `0x2E349`/`0x2EB39`）。
⇒ 因此「尾部每字节可解释」的正确结论是**判定其为宿主残留/可再生缓存**，继续逐字段标注预计无收益。
