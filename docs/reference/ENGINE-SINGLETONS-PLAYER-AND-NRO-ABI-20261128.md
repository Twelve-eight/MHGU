## 1. 镜像映射与运行时插件 ABI 规范

### 1.1 `main.140.flat.bin` 静态镜像几何 `[C]`

- **文件总长**：`25,472,632 B`（`0x0184ae78`）。
- **扁平偏移换算**：`flat_offset = vaddr + 0x100`（前置 `0x100 B` 展平头）。
- **代码段边界**：`TEXT_END = 0x013f1dec`（位于 `0x00000000 .. 0x013f1dec`）。
- **静态镜像末地址**：`IMG_END = 0x0184ad78`（含 `.rodata`、`DTI`/虚表、`.data` 与 `.got`；`.bss` 段自 `0x0184ad78` 之后不落盘）。

### 1.2 32 位 ARMv7 `NRO0` 插件加载与虚表覆写 ABI

- **Guest 加载基址关系 `[B]`**：Switch 原生 32 位 ARMv7 环境与重编译运行时的 Guest 地址空间中，若主模块 `main` 装载于 `main_base`（典型 Guest 基址 `0x00200000`，即 `guest_vaddr = main_base + flat_vaddr`），代码段、`.got` 与静态虚表指针均保持同一模块内相对偏移不变；`NRO0` 插件通过 `main_base` 叠加本文所列 `vaddr` 定位单例与函数。
- **4 字节 `bx lr` 桩函数与 DTI 实例虚表覆写原则 `[C]`**：
  - 在 `main.140.flat.bin` 的虚表中存在大量紧邻排列的 **4 字节空桩函数**（仅单条 `0xe12fff1e` `bx lr` 指令）。例如在 `uPlayerQuest07` 实例虚表 `0x174cf64` 的前 400 个槽位中实测有 **45** 个 `bx lr` 桩函数，其中 `slot 56..59`（`+0xe0..+0xec`）连续指向相邻 4 字节地址 `0x53b4e8`、`0x53b4ec`、`0x53b4f0`、`0x53b4f4` `[C]`。
  - 若直接对 4 字节 `bx lr` 桩原地写入 8 字节 ARM32 绝对跳转跳板（`ldr pc, [pc, #-4]; .word target`），将直接覆盖下一虚表槽的指令。因此针对虚函数拦截，应采用 **复制/修补虚表或覆写 DTI 实例首字 `*(u32*)instance` 虚表指针** 的方式（而非原地覆写 `bx lr` 桩）。

### 3.2 6 种狩猎风格调度与 `uPlWeapon` 动作切换 `[C]`

- **风格查询虚函数**：`uPlayerQuest` 虚表 **`slot 90` (`+0x168` = `#360`)** 返回风格枚举 `0..5`（在 `0x29b584`、`0x29b5f8` 等处统一经 `ldr r1, [r0, #360]; blx r1` 调用，对应资源包 `player\quest\w%02d_m%d`）[C]；枚举号 `0..5` 对应 6 大风格（公会/强袭/空战/武士道/勇气/炼金）`[B]`。
- **子对象动作切换 `0x2899fc(player, bankIdx, motionId)`**：校验 `*(u32*)(bankObj + 0x1378) <= 1` 后写入 `[bankObj + 0x137c] = motionId`、调 `0x306e98(bankObj, 2)`，并分发至 `0x2875c0(player, bankIdx, motionId)`（猎人）或 `0x2837fc`（猎猫）。其中 `0x2875c0` 按 `bankIdx = 0..8` 跳转并调用 `0x27b34c(player, ...)`；在命令执行器 `0x2836e4` 中，`cmd[4] & 0x1f == 22` 会固定以 `bankIdx = 7`（`uPlWeapon` `+0x23a0`）调用 `0x2899fc` `[C]`。

### 3.3 操虫棍 `uPlayerQuest13` 与猎虫实体 `uShellPlw13_000` `[C]`

- `uPlayerQuest13`（`13,152 B` = `0x3360`，DTI `0x2b6264`，instVt `0x1750450`）尾部 `+0x3338` 持有猎虫实例 `uShellPlw13_000*`（`5,712 B` = `0x1650 B`，DTI `0x482164`）[C]。

## 4. 狩技系统完整运行时规格 `[C]`

本节已闭合 Wave 8B 遗留的全部 3 项狩技运行时未知量：

### 4.1 装备侧（`cAcPlayerEquip`）与任务玩家侧（`uPlayerBase`）狩技槽位 `[C]`

1. **装备侧 `cAcPlayerEquip`（`equip = *(player + 0x13c4)`，大小 `952 B = 0x3b8 B`，DTI `0x3542b8`）**：
   - `0xe79c8(equip + 4, slot)`（`slot = 0..2`）直接读取 `*(u16*)(equip + 0x240 + slot * 2)`（即 `+0x240 / +0x242 / +0x244`，`equip + 4 + 572 + slot * 2`），返回 3 个槽位当前装备的狩技 ID；`0xe79b4` 负责写入。
   - `0xe7a6c(equip + 4, slot)` 读取 `*(u16*)(equip + 0x246)` 并测试 `(val >> slot) & 1`，返回该槽是否启用 SP 狩技标记（`0xe7a20` 置位/清除）。
   - *(注：`0x334008` 为 `0x353b1c` 调用的内嵌属性反射函数，反射预设数组 `mStyle[0..4]`、`mSuperArts1..3[0..4]`（自 `+0x60 / +0x6a / +0x74` 起步长 `2 B`）与 `mSuperArtsX1..X3Flag`（`+0x3b2..+0x3b4`）；而 `0x51d12c`（由 `0x51d0a0` 调用）操作的 `+0xd24 / +0xd3c / +0xd54` 各 `24 B` 属于外层存档/装备箱结构，非 `0x3b8 B` `cAcPlayerEquip` 本身。)*
2. **玩家实例侧 `uPlayerBase` 运行时狩技区（`+0x24f4..+0x24fc` 与 `+0x2754..+0x276a`）**：
   - **`+0x24f4 / +0x24f8 / +0x24fc`** (`void*[3]`)：3 槽狩技参数对象指针，由 `0x2878a0`（在 `0x287968` 调用 `0x285fd4`）加载，`0x285fb4(player, slot)` 读取，`0x2acb60` / `0x2acbec` 经 `0x2731b4` 解包 `+100..+120` 参数字段。
   - **`+0x2754`** (`u32`)：**当前选中/触发的狩技槽号（`0..2`，`3` = 无）**。`0x2990bc`（`0x299438`）初值 `3`，`0x2a8b34` 写入 `0..2`，触发/取消时写回 `3`（`0x2a8c20`、`0x2ac668`、`0x2e9c08`）。
   - **`+0x2758 / +0x275a / +0x275c`** (`s16[3]`)：**1–3 号狩技当前积攒能量值**（`0x29946c..0x29947c` 清零）。
   - **`+0x275e / +0x2760 / +0x2762`** (`s16[3]`)：**1–3 号狩技满槽所需最大能量值**（`0x299454..0x299464` 初始化）。
   - **`+0x2764`** (`u32`)：当前激活狩技等级 `0..2`（`0x2acbec` 在 `0x2acc68..0x2acc98` 按 `(artId - 11) % 3` 计算写入）。
   - **`+0x2768 / +0x2769 / +0x276a`** (`u8[3]`)：各槽 SP 强化激活标志（`0x2acbec`、`0x2e9d54` 在 `0x2eb364..0x2eb3c4` 读写，`0x2a2db4` 查询）。

### 4.2 能量积攒、满槽判定与消耗清零链 `[C]`

- **`cHunterArtsBase` 与 `rHunterArtsData` 职责边界**：`cHunterArtsBase`（`32 B`, DTI `0x4cc29c`, `instVt 0x1769140`）及 `rHunterArtsData`（`112 B`, DTI `0x4ce6b0`）仅承担静态参数与序列化加载；**实时能量计算全部在 `uPlayerBase + 0x2758..+0x2762` 上完成**。
- **能量增加函数 `0x2a2720(player, rawAmount)`**：
  - 由攻击命中 `0x1722c0`（`0x1723f4`）与动作事件 `0x29cec4`（`0x29e630`）、`0x2ee508`（`0x2ee5f8`/`0x2ee9a0`/`0x2eecf8`）、`0x2f0f04`（`0x2f12f0`）调用；
  - 对 `rawAmount` 依次叠乘倍率（`vt+0x1b0` 标志位调 `0x282828(43)` / `0x282828(103)`、技能 `200`/`301` 经 `0x2864c4` 乘常数 `[0x2a28e8]`）；
  - 遍历 `slot = 0..2`：跳过空槽（`0xe79c8 == 0`）或禁止充能槽（`vt+0x198 != 0`），将 `*(s16*)(player + 0x2758 + slot*2) + delta` 钳位在 `[0, *(s16*)(player + 0x275e + slot*2)]` 写回；首次达到上限时依 `0xe7a6c` SP 标记通过 `vt+0x380` 发送 `0x281`（SP）或 `0x282`（普通）满槽提示。
- **满槽可释放判定函数 `0x2a26c8(player, slot)`**：
  - 由 UI（`0x64cdc8`、`0x64cfc0`）调用；校验 `slot <= 2` 后比较 `*(s16*)(player + 0x2758 + slot*2) >= *(s16*)(player + 0x275e + slot*2)`，满槽时再调 `0x2862f4(player, artId)` -> `0x277848` 校验武器匹配；
  - 玩家输入校验 **`0x2a8b34(player)`** 内联同一判断：依次经 `vt+0x2e8` 检查输入槽 `64 / 65 / 66`，写入 `player + 0x2754 = slot` 并核验 `cur >= max` 与 `0x2862f4`，失败则置 `player + 0x2754 = 3` 返回 `0`。
- **消耗清零函数 `0x2ac4bc(player)`**：由 `0x2e9d54`（`0x2eb3cc`）及 `0x2ab670`（`0x2ab690`）在触发狩技时调用，读取 `slot = *(player + 0x2754)` 并将 `*(u16*)(player + 0x2758 + slot*2)` 清零，随后在 `0x2ac668` 将 `player + 0x2754` 复位为 `3`。

### 4.3 `wNN_sa` (`LMT`) 挂载字段与切入 `_sa` 动作调用链 `[C]`

1. **`wNN` 与 `wNN_sa` 挂载字段 (`0x29b514`)**：
   - 在 `0x29b514(player)` 中通过资源加载器 `0x152960` 加载两套 `rMotionList` (`LMT`) 并挂载于玩家实例独立指针（与 `[+0x2384..+0x23a4]` 的 `bankIdx` 子对象及 `[+0x23a8/+0x23ac]` 区分）：
     - **`player + 0x24ec`**：主动作库 `wNN`（以索引 `style + 21` 加载，经 `0x285f28` 写入、`0x285f1c` 读取）；
     - **`player + 0x24f0`**：狩技动作库 `wNN_sa`（以索引 `weaponType * 6 + style + 27` 加载，经 `0x285f74` 写入、`0x285f68` 读取）。
2. **切入 `_sa` 动作的调用链（`motionId >= 2000` 编码约定）**：
   - 动作切换入口 **`0x2e9b7c(player, motionId, blend)`**（全代码段 `414` 处调用，含 `0x2ab6e4`、`0x2a8de0`、`0x2a4d20` 等）及 **`0x2e9c50(player, motionId, blend, flag)`**（`uPlayerQuest*` 内 `8` 处调用）按 `motionId` 区间分流：
     - **`1000 <= motionId < 2000`**：调用 `0x285f1c(player)` 取 `[player + 0x24ec]`（主 `wNN` `LMT`），取槽号 `slot = motionId - 1000`；
     - **`motionId >= 2000`**（`0x2e9bbc: cmp r6, #2000`）：调用 **`0x285f68(player)`** 取 **`[player + 0x24f0]`（`wNN_sa` `LMT`）**，取槽号 **`slot = motionId - 2000`**（`0x2e9bd4: sub r2, r6, #2000`）。
   - 随后校验 `slot < *(u32*)(lmt + 0x68)`，从 `(*(lmt + 0x74))[slot]` 取出 64 B `LMT` 动作头写入 `player + 0x24a8`，将 `motionId` 写入 `player + 0x24ac`、混合时间写入 `player + 0x24e0`（`f32`），清除 `player + 0x2500` bit10..11 与 `player + 0x24b0..+0x24df`（`48 B`），交由帧更新管线读取并由 `0x280984` 逐帧求值 `LMT +0x34` 事件通道。
