本文件只收 **`[C]`（有命令或反汇编引文）** 与少数明确标注的 `[B]`/`[U]`。来源逐条标在括号里，指向 `MHRS/docs/reference/FOR-SE-REPLY.md` 的节号——那份是按时间追加的流水，本文件是可顺序阅读的摘要。

## 1. 处理器派发（不是脚本解释器）

`em[0xba4e]`（**u16**）选中一个处理器，走 141 项表：

```
0x8d418 push {r4,r5,r6,lr}
0x8d420 movw r0,#0xba4e
0x8d424 ldrh r0,[r4,r0]
0x8d428 cmp  r0,#140
0x8d42c bhi  0x8d84c          ; >140 直接收尾
0x8d434 add  r3,pc,#4         ; r3 = 0x8d440
0x8d43c add  pc,r0,r3         ; target = 0x8d440 + entry
```

- 表项是**相对 `0x8d440` 的偏移**（`add pc` 是寄存器分支）。〔§348〕
- 141 项里只有 **23 个不同目标**：id 0、1 是派发器内部的内联 case 体；id 2–9 与 128–140 是 21 个 3 字蹦床（`mov r0,r4; pop {r4,r5,r6,lr}; b <handler>`）；**id 10–127 全部指向 `0x8d84c`，也就是派发器自己的 `pop {r4,r5,r6,pc}` 收尾**。〔§348/§349〕
- 23 个处理器分三类：**11 个私有相位表驱动**、**7 个比较链驱动**、**3 个委派守卫**（id 3、5、136：`phase != 0` 就 `b 0x96208`），外加 id 0（提交/关闭）与 id 140（3 参，内含第二张表）。〔§348/§349〕
- 23 个处理器**没有一个是 EMC 脚本运行器**（`refs_to 0x82f80` 只有一个调用者，在该区域之外）。〔§349〕

**第二张表（`0x954e4`）不属于 id 140**，它属于**另一个函数 `0x9549c`**——`em[0xba4e]` 有**两个平行的消费者**，不是父子层：〔§360〕

- 消费者 A：`0x8d418`（表 `0x8d440`），调用者是 `0x85524`、`0x8a74c`。
- 消费者 B：`0x9549c`（表 `0x954e4`），调用链 `0xa54c4 → 0xc8ddc → 0xc90ac → bl 0x9549c`，与 A **不相交**。

B 的 141 项分三类（16 + 5 + 120 = 141）：`{2,7,9,128..140}` 直接返回；`{0,1,5,6,8}` 过 `em[0xba44]` 的 **bit6** 守卫；`{3,4,10..127}` 走主体。

**B 在读到 id 之前还有两道前置门，任一不成立就直接返回**〔§360〕：

```
em[0x1406] & 8        ; = dword em[0x1404] 的 bit19
em[0xba44] & 0x20     ; bit5
```

两门都成立才**读到** id。且 `id > 140` 会落进**最重**的第三类 —— 141 是 enum 上界，不是安全阀。

## 3. 脚本 VM

- **256 项 opcode 表在 `0x837ac`**（`0x837a0 add r1,pc,#4`），`add pc` 式相对偏移。opcode `0x97` 已证：`entry = *(0x83a08) = 0x1bb8`，`0x837ac + 0x1bb8 = 0x85364`。〔§353〕
- **256 项只解析出 155 个不同目标**：`0x8470c`（空操作）占 **101** 个 opcode（13 活 + 88 不可达，因为 `0x50ce0` 对 `op > 0xa6` 返回 255）；`0x83bac` 占 **2** 个（`0x10` 与 `0xff` 是同一个体，对 section 索引 `em[0x72fc]` 做 21 项子派发）；其余 **153** 个各一。〔§369〕
- **家族（合计 256）**：switch/compare 112、空操作 101、动作 13、存取/字面量 9、实体 7、虚调用 2、调用 2、跳转 2、循环 1、自跳过 1、section 派发 2、单例 4。〔§369〕
- **`0x7307` 栈：`0x20` 是唯一的压栈 opcode**（`refs_to 0x8572c` 只有一条引用 `0x84020 b`），**没有专用弹栈 opcode**——`0xff`（及别名 `0x10`）在 `em[0x72fc] == 0` 时隐式弹栈（`0x85b80`）。兄弟栈 `0x7350` 由 `0x14` 压、由同体的 section 1 弹（`0x85bc8`）。〔§369〕
- 派发头 `0x83770`：`r3 = *r4`（游标）→ `r9 = r3+1` → `*r4 = r9` → `opcode = *(u8*)r3` → 查表。**`arg1` 是操作数起点。**〔§353〕
- 游标寄存器 `r4` 就是 **`em[0x72f8]`**。〔§353〕

## 4. 两个栈（都是"满栈替换栈顶"，不报错）

### 4.1 `0x7350` 栈 —— 打包记录

| 槽内 | 宽度 | 内容 |
|---|---|---|
| `+0` | u8 | `em[0x72fc]` |
| `+1` | u8 | `em[0x72fd]` |
| `+2,+3` | — | 填充，两侧都不碰 |
| `+4` | **u32** | **脚本游标**（压栈时的 `arg1+1`），弹栈写回 `em[0x72f8]` |

- base `em[0x7350]`、stride 8、**12 槽**；`0x7350 + 12*8 = 0x73b0` 正好是下一个结构的起点（自洽验算）。〔§344〕
- 压栈 `0x8b650-0x8b694`（唯一调用者 `0x85378`），弹出 `0x8de50` / 孪生 `0x95e0c`。〔§344/§353〕
- 上限：`cmp r1,#12` → `subcs r1,r1,#1` → `strbcs` ⇒ **满栈时计数器改成 depth−1、记录覆盖槽 11，三条 store 照写，无分支无错误码**。〔§344〕

### 4.2 `0x7307` 栈 —— 两个并列阵列

| 内容 | 地址 |
|---|---|
| 深度 | `em[0x7307]`（u8） |
| entry | `em[0x7308 + d]`（u8） |
| script | `em[0x7314 + 4d]`（u32） |

- 压栈 `0x85734`：`cmp r2,#10` → `subcs r2,r2,#1` ⇒ **上限 10、同样替换栈顶**。〔§350〕
- 压栈侧**不物化** `0x7307`（复用解释器帧的 `[sp,#180]`），所以按常量普查找不到它。〔§350〕
- 拆除清零：`0x82b30`（`r6 = em+0x7307`），另有 `0x82748`。〔§350〕

## 5. 回锚手势

**清 `em[0x1404]` 的 bit10 ⇒ `bl 0x95ca0`**，是**7 站点固定语式**（全 `.text` 298 个 `0x1404` 物化点全枚举后得出）：

`0x8f728`、`0x91e5c`、`0x92594`、`0x94538`、`0x95210`、`0x9609c`、`0x96350`

置 bit10 的站点 7 处（`bic #0x440; orr #0x400`）：`0x8f7ac`、`0x92280`、`0x92794`、`0x945d4`、`0x950fc`、`0x95fb0`、`0x962a4`。〔§350〕

**移植注意**：任何实现"返回锚点"的路径都必须同时清这一位，否则 `0x95ca0` 的后续行为与原版不同。

**该字段不是单 bit 三态**：存在 2-bit BFI、4-bit BFC、双 bit ORR、15 处掩码 AND RMW、22 处整字写/拷贝，无 `eor` 翻位。〔§350〕

### 回锚函数 `0x95ca0` 进门就清 17 位

它是"回锚/恢复"的唯一入口（**15 个调用者**：1 个 `bl` + 14 个 `b`）。入口第一段不是只清 bit10，而是两张掩码一次抹掉 17 个标志位：

| 掩码 | 作用于 | 清掉的位 |
|---|---|---|
| `0xEFFEFBBF` | `em[0x1404]` | **6, 10, 16, 28** |
| `0xC1FFF5C0` | `em[0xba44]` | **0,1,2,3,4,5, 9, 11, 25, 26, 27, 28, 29** |

⇒ **移植时只复现"清 bit10"会在恢复后带着 16 个残留位继续跑。** 另外它同时把 `em[0xba50]` 的相位与步进一起清零，并清 `0x73f0/0x73f3/0x73f4/0xba52/0xb7b0`。〔§372/§374〕

**它是 5 路恢复派发器**（按当前的 `em[0x72fc]`）：idx0 = 弹 `0x7307` 续延栈；idx1 = 弹 `0x734c`/`0x7350` 整帧；idx2,18 = `0x7340/41/44`；idx3-7,11,17 = `0x73b4/35/38`；idx10 = `0x73c0/1/4`。**不是两路**——历史文档里的 "A/B" 指代的是其中两对，别把它当两路。〔§372〕

## 6. 已知的读法陷阱（写代码前先读这段）

1. **`ldr rX,[rY],rZ` 是 post-index**：先读 `[rY]`，再 `rY += rZ`。**两处已栽**：`0x82b14`（→ 调用目标是 `[[em]+0x300]`，不是 `[[em+0x7307]+768]`）〔§350〕与 `0x9573c`（→ `[[em]+0x9c]`，不是 `[*[em+0x7604]+0x9c]`）〔§360〕。
   **机械判据**：字的高半字节 `0xE6`（`ldr rD,[rN],rM`，P=0/W=0）就是写回形式——基址取 `rN` 的**旧值**，读完后 `rN` 变成 `rN+rM`。写成 `[rN,rM]` 的（`0xE7…`）才是寄存器偏移相加。
2. **`em[0x73e0]` 是 u8**，但同一 `u8[4]` 组也会被 4 字节批量写覆盖（初始化写 `0xFFFFFFFF`、复位写 0）——**当 u32 处理会吞掉 `0x73e1`，只当 u8 处理会丢掉那两次 4 字节覆盖**。〔§362/§363〕
3. **`em[0xba4e]` 有两个平行消费者**（表 `0x8d440` 与表 `0x954e4`），不是嵌套。〔§360〕
4. **`0xba50 >= 64` 是关闭梯子**，不是"更大的相位"。〔§349〕
5. **判"有无调用者"必须 `bl` 与 `b` 一起扫**（ARM：`bl` 高半字节 `0xB`、`b` 是 `0xA`，目标 = `vaddr+8+off<<2`）。蹦床用 `b`，所以每个尾调用的处理器 `bl` 数都是 **0**——只扫 `bl` 会把它们全判成不可达。`0x8f460` 就是 `bl=0 / b=1`。〔§366〕
6. **`literal_loads` 的窗口模式会漏报**：同一查询在全文是 39 命中、在含其中一条的窗口内是 **0**。窗口参数只能用来缩小打印量，**不能用来判定存在性**；任何"这个窗口里没有 X"的说法无效。〔§367〕
7. **只数 `movw` 会低估使用次数**：`em[0x734c]` 有 39 个物化点，但真实访问是 **47 个站点 / 34 条 store**，因为缓存进栈槽（`[sp,#284]`）后的 8 个消费者不再物化常量。〔§367〕

## 8. 发布任何计数之前：过门禁，别信单一读器

本文件里出现过的**三个错误数字**都是"自己跟自己一致"造成的：`0x1404` 的 298（真值 301）、`0xba44` 的 126（真值 127）、`0x73e0` 的"3 个写者"（真值 4）。

**门禁覆盖范围是有边界的，别夸大**：

| 计数类型 | 自动覆盖？ |
|---|---|
| **物化计数**（"某常量有多少个 `movw` 站点"） | **是** —— `literal-counts-check.mjs`，两个独立读器 + 锁定值 |
| **写者计数**（"某字段有几个写者、各是什么宽度"） | **否** —— 只能靠人工，**必须逐条 `disasm` 并列出覆盖过的编码通道**（`str`/`strb`/`strh` × 寄存器索引 / imm12 / pre/post-index 写回） |
| **访问计数**（"某字段被访问多少次"） | **否** —— `movw` 普查只是**下界**：缓存进栈槽（§367）或用 `add/sub` 算基址（§373）都会绕过物化 |

所以：门禁只挡第一类；第二、三类目前**没有机器保护**，写结论时必须自己列出"我扫了哪些通道"，并说明结果是下界还是全集。

**`literal_loads` 不能当枚举器**（全量上也少报），只能当打印器。〔§367/§370〕
**"两个读器一致"不等于"两个读器都对"** —— 它们可以共享同一个错误的覆盖口径。必须有**已知正样本**；`0x73e0` 的 `movweq@0xe90998` 就是这样一个样本〔§371〕。
