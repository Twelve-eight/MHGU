## 坐标系与对齐
- `bl` 顺序 = 文件顺序（成员序列化按调度器顺序写盘）
- member[2] = **成员#4 外层**（之前 DEVELOP.md 的 member#4 是它的内层子对象 `0x51dc40`）
- member[3] = **装备箱成员**（2000+1000 装备，与 DEVELOP.md「装备箱 72000B / 猫装备」结构吻合）
- obj_off 相对各成员对象基址 `r5`（=`ldr[r5,#0]` 解引用），≠ file_off；各成员 file 基址需按序列化顺序累加前序成员 size 定位

## 与已测绘区的对应
- member[2] 内层 `0x51dc40` = 已全标注的 134 字段成员#4（`member4-semantics.md`）
- member[2] 的 obj+0x72C/0x83E 274B = 怪物击杀/捕获 137 槽数组（`monster-slot-map.md` 137 槽定案的代码侧实证）
- member[3] = 装备箱（`EquipsForm` 操作的 2000 玩家 + 1000 猫装备 + 5440B 套装 + 1632B 尾）
