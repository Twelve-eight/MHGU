## 已确认（有证据）

### 0. 坐标前提：旧 dump 全部早 `0x550` —— 本次定案先立这一条

三处残留的前两条（尤其"63/54/56 FF 涂块"）**建立在旧坐标上**。必须先证伪/证实坐标，否则结论全反。

**0.1 循环字节账（[D] 反汇编直读，非推断）**

`0x51dc40` 内只有两处循环体（`reader-window-b.txt`）：

```
0051e144: movw r0, #0xe58       ; obj+0xE58
0051e148: mov  r7, #21          ; 21 次
0051e14c: add  r6, r5, r0
0051e150: (循环) bl 0x3df2a8    ; 读 20B @ r6+0
0051e160: add  r1, r6, #40      ; 读 20B @ r6+0x28
0051e16c: bl   0x3df2a8
0051e170: add  r6, r6, #60      ; 步长 60（0x3C）
0051e174: sub  r7, r7, #1
0051e178: bne  0x51e150
0051e17c: movw r0, #0x1344      ; 第二组 obj+0x1344
0051e180: mov  r7, #15          ; 15 次，同型
0051e1b0: bne  0x51e188
```

每次迭代落盘 40 B（两份 20 B），obj 前进 60 B。故：
- 循环 1 文件消耗 `21 × 40 = 840 = 0x348`；
- 循环 2 文件消耗 `15 × 40 = 600 = 0x258`；
- 合计 `0x5A0`。旧表把每对循环只算了一次（80 B），少算 `0x5A0 - 0x50 = 0x550`。

**0.2 端到端闭合（独立于任何存档字节）**

`0x280B + 0x400 = 0x2C0B`（外层 1024 B 头 → 内层基址，与 Main 本轮修正一致）；
`0x2C0B + 0x3297 = 0x5EA2`（12,951 B = 134 站点含循环）；
`0x5EA2` 之后正是编辑器实测可用的怪物击杀计数块（写点 `24230 = 0x5EA6 = 0x5EA2 + 4`，137×u16）[T][S]。
若按旧账（不含循环）内层应止于 `0x5952`，与 `0x5EA6` 无法对齐 ⇒ **含循环的账才对**。

**0.3 结论**：`member4-file-layout.txt` 的 `file_off` 列（含循环）正确；
`families-dump.txt` 的 **288B / 68B / 尾 3444B** 段与 `followup-dump.txt` 的 **128B 全 hex**
**全部按旧账取样，早 `0x550`**，其字节内容与所标 obj 偏移**不对应**，不得再引用。
（同文件的 164B / 20B / 16B 段属行 27..38，不受本次修正影响，仍可用。）

### 1. 残留①：128B 记录族（obj+0x2A78..0x3178，行 86..100）

**1.1 几何 [T]**：15 条 × 128 B，连续无空洞；`0x2A78 + 15×0x80 = 0x31F8`（下一条 656 B 块起点）。
文件侧 `0x45DF..0x4D5F`（`0x45DF + 0x780 = 0x4D5F`）；族内 `file − obj = 0x1B67` 恒定。
与 288B 族（`0x3907..0x4447`）、68B 族（`0x4447..0x45DF`）、656B 块（`0x4D5F..0x4FEF`）**三向闭合**。

**1.2 读调用 [D]**：15 条各自一条 `movw #imm / mov r2,#128 / add r1,r5,r0 / bl 0x3df2a8`，**无循环**：

| i | obj | bl vaddr | i | obj | bl vaddr |
|---|---|---|---|---|---|
| 0 | 0x2A78 | `0x51e300` | 8 | 0x2E78 | `0x51e3a0` |
| 1 | 0x2AF8 | `0x51e314` | 9 | 0x2EF8 | `0x51e3b4` |
| 2 | 0x2B78 | `0x51e328` | 10 | 0x2F78 | `0x51e3c8` |
| 3 | 0x2BF8 | `0x51e33c` | 11 | 0x2FF8 | `0x51e3dc` |
| 4 | 0x2C78 | `0x51e350` | 12 | 0x3078 | `0x51e3f0` |
| 5 | 0x2CF8 | `0x51e364` | 13 | 0x30F8 | `0x51e404` |

（写侧镜像：`0x51d764..0x51d8f0` 同型 15 站点，`bl 0x3df378`。）
15 条独立 `bl` ⇒ I/O 层把每条当**不透明 128 B 字段**；内部结构只能从 gameplay 消费者取。

**1.3 差分（[T] 重生成版，正确坐标）**

| i | 7 | 8 | 9 | 10 |
|---|---|---|---|---|

⇒ **本族无编辑器涂块**（全族仅 1 个 FF 字节，落在 i7）；i11..i14 两档差 0/0/1/0 字节
⇒ [I] 大概率未使用槽（"完全一致"只证明不随进度变，不证明全 0）。
⇒ 与 `records-128.md` §3 的 "i7/i8/i9/i10 被编辑器毁" **相反**；那 4 个数属 68B 族（§3.4）。

**1.4 字段切分（本片能得到的最硬结构）**

**(a) rec+0x5C 起 = `{u16 id, u16 value}` 4 B 条目数组（rec0 内 9 条容量）** —— 两处独立指令：

```
006fccf8: e3021ad4  movw r1, #0x2ad4        ; r11 = obj+0x2AD4 = rec0+0x5C
006fccfc: e084b001  add  r11, r4, r1
006fcd34: e5940088  ldr  r0, [r4, #136]     ; 计数器 @ obj+0x88（不落盘）
006fcd38: e08b0100  add  r0, r11, r0, lsl #2 ; &entry
006fcd3c: e1c050b0  strh r5, [r0, #0]       ; entry+0 = u16 id（来自运行期 id 表）
006fcd44: ebf94c50  bl   0x54fe8c           ; value = f(id)
006fcd50: e1c100b2  strh r0, [r1, #2]       ; entry+2 = u16 value
```
同数组的**读-改-写**（扣减后 clamp 0）：
```
006fcd74: e3021ad6  movw r1, #0x2ad6        ; 0x2AD6 = 0x2AD4 + 2
006fcd78: e0840100  add  r0, r4, r0, lsl #2
006fcd80: e1b010f1  ldrsh r1, [r0, +r1]     ; 注意：转储把该编码印成 "[r0,#1]"，
                                            ; 0xE1B010F1 实为"寄存器偏移"形式 ⇒ 地址 = obj+0x2AD6+4i
006fcd84: e0411002  sub  r1, r1, r2
006fcd8c: e3510000  cmp  r1, #0
006fcd90: d1a01002  movle r1, r2            ; clamp 到 0
006fcd94: e1c010b0  strh r1, [r0, #0]
```
⇒ **rec0+0x5C..+0x7F = 9 × {u16 id @+0, u16 value @+2}**（`0x2AF8 - 0x2AD4 = 0x24 = 9×4`）。
**[I] 保留意见**：`0x6fcd78` 的基址是 `r4` 而非 `r11`（转储原文），若按字面则读 `obj+4i+0x2AD6` 而来写 `obj+4i`
——两处基址不一致，只能是转储/编译器其一有误；**读侧（`0x2AD6` 寄存器偏移 + `strh [r0,#2]`）无歧义**，
故"4 B 条目 = {id, value}"成立，但"该数组是不是这条记录的真字段" [I] 中置信。

**(b) rec i1 的 +0x00 / +0x01 是两个独立 u8 字段** —— `0x848040/0x848050` 把它们当**字段 id 常量**登记：
```
00848040: e3021af8  movw r1, #0x2af8   ; = obj+0x2AF8（做"值"用，不是地址）
00848048: e18810b0  strh r1, [r8, #176]
00848050: e3021af9  movw r1, #0x2af9   ; = obj+0x2AF9
00848058: e18810b0  strh r1, [r8, #176]
```
（`records-128.md` §1.4 把它读成"逐字节走查 rec1 的 +0/+1"是误读：本段 `r1` 自始至终是 `movw` **立即数常量**，
没有任何以 `r5`(obj) 为基址的 `add`；`0x2711 → 0x2AF8 → 0x2AF9 → 0` 是依次写入 `[r8,#176]` 的一串"值"。）
与此同时 `0x848018..0x848038` 用 `movw/movt` 拼 `0x134EC/0x134F2/0x134F8/0x134FC` 并以寄存器偏移 `str` 出去，
形态是"（值, 地址）描述符表"初始化。
⇒ 该函数**只能**证明 `0x2AF8`、`0x2AF9` 作为两个相邻标识出现在同一张表里（[I]：把"标识"读成"obj 偏移"是
本项目的既有约定，此处未获指令级佐证）；**不提供语义，也不构成对 rec1 字节的访问**。

**(c) 同型 4 B 条目在族外复现**：`obj+0x28E8`(u16) / `obj+0x28EA`(u8 读) 被 `0x6FCCE0/0x6FCCEC`
（`str r1,[sp,#4]` = &0x28EA、`str r1,[sp,#20]` = &0x28E8，随后 `ldrh` 比对 + 字节扣减）
⇒ `obj+0x28E8..0x28FB` = 5 × {u16 id, u16 val}。注意 **`0x28E8` 不在任何记录内**，它是 68B 族 g1 的
**中槽 `0x28B8` 的 +0x30**（`0x28E8-0x28B8 = 0x30`）⇒ "4 B 条目"是**成员级通用语法**
（`{id,val}` 列表/映射），中槽是同语法的运行期副本。**这解释了为何不能把 4 B 条目一概归给 128B 记录。**

**1.5 判定**：本族 = **15 条 128 B 不透明记录槽**（I/O 层无字段视图）；已证的仅有
`+0x5C..+0x7F = 9×{u16,u16}` 与 `+0x00/+0x01 = 2 个 u8`。语义仍**未知**，
"委托/任务记录"仍是低置信候选（唯一弱证据：任务判定簇 `0x524AC0..0x524BB8` 读 rec0，`records-128.md` §1.4）。

### 2. 残留②：3444 B 块（obj+0x3684，行 121）

**2.1 读调用（逐条，[D] `reader134-dump.txt`）**

```
0051e598: e2851dda  add  r1, r5, #13952      ; 13952 = 0x3680，前一条 1 B
0051e5ac: ebfb033d  bl   0x3df2a8
0051e5b0: e3030684  movw r0, #0x3684         ; ← 目标 obj_off
0051e5b4: e3002d74  movw r2, #0xd74          ; ← size = 0xD74 = 3444（单条，非循环）
0051e5b8: e0851000  add  r1, r5, r0
0051e5bc: e1a00004  mov  r0, r4
0051e5c0: ebfb0338  bl   0x3df2a8

```
**不在循环内**：`0x51dc40` 的全部回边只有 `0x51e178 → 0x51e150`（21 次）与 `0x51e1b0 → 0x51e188`（15 次），
都在 `0x51e1b0` 结束；`0x51e5b0` 位于两循环之后的直线段，其后直到 `0x51e6cc`（`add sp,sp,#8` 出栈）无回边。
⇒ **单条静态 3444 B 读，obj_off = 0x3684，file = 0x50BA..0x5E2E。**
闭合自检：`0x3684 + 0xD74 = 0x43F8`（下一条 3 B 字段起点）；`0x50BA + 0xD74 = 0x5E2E`（同上）—— 两向无空洞。

**2.2 引用集完备**：`0x3684` 无法编成 `add imm12`（置位位跨 2..13，超 8 位窗口）⇒ 全 .text 的 `movw` 站点
即全静态引用集 = `{0x51DA98(writer, bl 0x3df378), 0x51E5B0(reader)}`（`families-disasm.txt` 已列 writer 窗口
`0x51da84: movw r0,#0x3682` / `0x51da98: movw r0,#0x3684` / `0x51da9c: movw r2,#0xd74`）。
⇒ **除存档 I/O 外无静态消费者**（寄存器间接寻址排除不了，见未知）。

**2.3 差分 [T]：`diff = 0`（3444/3444 字节两档完全相同），dirty_FF = 0。**

这是本块**唯一**的强语义约束：HR5（猎人A）与 HR198（猎人B）两个不同进度档在该块**逐字节相同**
⇒ 它**不是**玩家进度量（不是任务记录/委托记录/击杀数一类的累积表）。
对照邻域（同为 [T]）：`0x3680`(1B) SAME、`0x3682`(2B) PROGRESS(1 B)、`0x43F8`(3B)/`0x43FB`(1B)/`0x43FC`(4B)/`0x4400`(4B) SAME、
`0x4418`/`0x441C`/`0x4420` PROGRESS、`0x4424`/`0x4448`(36B×2) PROGRESS、`0x446C`(4B) PROGRESS。
⇒ 3444 B 块是被 PROGRESS 字段**包围**的一块常量区。

**2.4 内部切分：无证据。** 现有 `families-dump.txt` 的 "tail char_off=0x4b6a" 是旧坐标（早 0x550），
其"头 64 B/尾 32 B 全 0、diff=104、FF×22" 与 [T] 的 `diff=0` **矛盾**，**整节作废**。
可用的只有算术因数分解（**均为候选，无字节支撑，逐条标 UNCONFIRMED**）：
`3444 = 21×164 = 84×41 = 12×287 = 14×246 = 28×123 = 6×574 = 4×861 = 3×1148 = 2×1722`
（21 与行 66 循环次数/村·集·G 星级组数同值；14 与武器种数同值；80（`cQuestDaily` 的 `mListData[80]`）配合
`4 + 80×43 = 3444` 也成立 —— 皆为数字巧合级证据，**不得据此定语义**。）

**2.5 语义判定**：**未知**。可证事实 3 条：①单条 3444 B 直线读、无内嵌步长；②静态引用只有存档 I/O；
③两档逐字节相同（常量/未使用区）。与"任务/委托记录表"的旧猜想**方向相反**（那类数据必然随进度变化）。
最可能的两解释（[I]，无法区分）：(a) 版本/模板常量表（如 DLC、竞技场、图鉴模板）；
(b) 两档都从未写入的保留区（全 0 也会得到 `diff=0`）。**判据只有 dump。**

[I] 补充推理（本条较强）：既然全 .text 里既无 gameplay 读者也无 gameplay 写者（§2.2），
则该字段在运行期是**纯穿通**（load 进来什么，save 就原样写回什么）——除非有人通过间接指针整块 memcpy。
穿通 + 两档相同 ⇒ 它更像是"游戏一次性生成、与进度无关的常量表"，或从未被填充的保留区；
无论哪种，**对编辑器都无写入价值**（写它不改任何可观测行为，只增风险）。

**3.3 位图语法（[D] `families-disasm.txt` 0x520c7c 窗口）**

```
00520c6c: and  r1, r0, #31          ; bit = id & 31
00520c74: mov  r1, r9, lsl r1       ; mask = 1 << bit
00520c78: add  r7, r6, r7, lsl #2   ; &word = base + (id>>?)*4
00520c7c: movw r6, #0x27a8
00520c80: ldr  r6, [r7, r6]         ; u32
00520c84: biceq r6, r6, r1
00520c88: orrne r6, r6, r1
00520c90: str  r6, [r7, #0]
```
（`and #31` 在本窗口 `0x520c6c` 直读；字索引 `id>>5` 的 `lsr #5` 见 `fam-small.md` §8.0b 的同函数邻域 [D]。）
⇒ **`u32[id>>5]`、`1<<(id&31)`、LSB-first、544 bit/槽**。同一 mask 同一条 `biceq/orrne` 依次写
`0x27A8`(0x520c7c) → `0x27EC`(0x520ca4) → `0x2830`(0x520ccc)，g1/g2 同型
（`0x520DA4/0x520DCC/0x520DF4`、`0x520ECC/0x520EF4/0x520F1C`），循环上界 `cmp r4,#384`（0x520CE4）。
⇒ A / 中 / B 是**同位同步的三份副本**（不是同一 1632-bit 空间的三段）。
**位号来源（本节修正 fam-small 的"类别表"说法）**：`mov r6,#50`(0x520BCC) / `#51`(0x520CF4) / `#52`(0x520E1C)
与 `mov r7,#3`(0x520BD0 等) 一起写进栈上描述符，然后 `bl 0x6aa9b8`：

```
00520d14: str r6, [sp, #52]     ; desc.type   = 51
00520d18: str r7, [sp, #56]     ; desc.count  = 3
00520d2c: strh r4, [sp, #48]    ; out2 = 0（rabbitRecordNo）
00520d3c: strh r5, [sp, #44]    ; out1 = 0xFFFF（rabbitNo，作终止符）
00520d44: ldr r0, [r10, #0]     ; 全局槽 *(0x1839388)
00520d48: bl  0x6aa9b8          ; 记录迭代器
00520d4c: ldrh r0, [sp, #44]
00520d50: cmps r0, r5           ;  == 0xFFFF ⇒ beq 0x520e08（本类结束）
00520d58: ldrh r1, [sp, #48]    ; out2 = rabbitRecordNo
00520d70: and  r3, r1, #31      ; bit = recordNo & 31
```
⇒ **68B 族的位号 = 迭代器第 2 个 u16 输出（`rabbitRecordNo`）**，与 288B `cTrialArts` 族**共用同一个迭代器
`0x6aa9b8`、同一个全局槽 `*(0x1839388)`、同一个包含函数 `0x520A44..0x52139C`**（`fam-288.md` §8.2/§8.3/§9.3
已定：288B 族的位号 = `rabbitNo*4 + j`，`desc.type = 44+r9`）。
`cmp r4,#384` 是**迭代上限**（与 288B 循环里的 `cmp r0,#1536` 同角色），**不是位宽**；位宽由槽尺寸决定 = 544 bit。
⇒ 三族（288 / 68 / 36）是**同一 `cTrial*` 位图系统的不同容量实例**，键空间都是 rabbit 记录。

**迭代器第 5 个参数 = 键字段名**：`0x520d0c add r8, pc, r0`（`r0 = 0x1048517`，pc = `0x520d14`）
⇒ `r8 = 0x156922B`，与 `name-dictionary.txt:1838` 的 `rabbitNo @0x156922b` **逐字节同址**；
288B 族算出同一个地址（`fam-288.md` §8.3）。⇒ 描述符 `{type, count, &out1, &out2, "rabbitNo"}`
= "取类型 T 的记录表里每条记录的 `rabbitNo`（0xFFFF 结束）与 `rabbitRecordNo`"，
故 **out2 = 记录序号**，位图 = 按记录序号的状态位。该字符串块（`name-dictionary.txt:1837..1896`）
同时列出 `cTrialArts / cTrialBowBottle / cTrialDataCommon / cTrialDataNyanter / cTrialEquipData / cTrialItemPoach …`
⇒ 类型码 50/51/52 属于 `cTrial*` 这一族（[I]，同块同函数，但类型码→类名的逐一对应仍未证）。

**3.4 编辑器岛**就是这族的三个 A 槽（本节是残留①的判决证据）

`0x4447 = obj+0x27A8`、`0x44CF = obj+0x2874`、`0x4557 = obj+0x2940`；岛边界与 68B 网格**逐条对齐**：

|---|---|---|---|---|---|
| g0.A | 0x4447 | A1 `0x4447..0x4485`(63B) + A2 `0x4486=0x0F` | 63 | 63（A2 非 FF） | **63** ✓ |

**3.5 中槽是活的**：`0x27EC` 站点 `0x520CA4 / 0x73E8E0`；`0x28B8` `0x520DCC`；`0x2984` `0x520EF4`；
且 g1 中槽 `0x28B8+0x30 = 0x28E8` 被 `0x6FCCE0` 当 `{u16 id, u16 val}` 表读写（§1.4c）
⇒ 中槽 = 运行期影子/暂存，**永不落盘**。

**3.6 语义判定**：结构 = 高；**id 空间 = 中高**；**具体类别 = 未知**。

- **id 空间（本残留的主要答案）**：位号 = 迭代器 `0x6aa9b8` 的第 2 个 u16 输出 `rabbitRecordNo`
  （键空间与 288B `cTrialArts` 族同源）；每槽容量 544 位 ⇒ **每类最多 544 条 rabbit 记录**
  （迭代上限 384 是表中记录条数上限，不是位宽）。
  ⇒ 这**不是**"按装备/物品 id 的解锁表"，而是**按 rabbit 记录号的逐记录状态位图**（3 类 × 3 状态）。
- **与 288B 族的关系**：同函数、同迭代器、同全局槽 `*(0x1839388)`、同 `{type, count, out1, out2, name}`
  描述符 ⇒ 两族是同一"rabbit 记录 → 位图"子系统的不同容量实例。288B 用 `bit = rabbitNo*4 + j`（每记录 4 bit），
  68B 用 `bit = rabbitRecordNo`（每记录 1 bit）。
- **类别 50/51/52 是什么**：未知。三者在 `desc.type` 里连续，且 288B 族用 44..48 —— 同一类码体系。
  `quest/CURRENT-RULING.md` 的"类码 47..86"体系可对照，但**没有**命名证据。
- **对编辑器标签"猫装备解锁"的评价**：**不采信**（[S] 只是编辑器作者的意图，且与"键 = rabbit 记录号"
  这一指令级事实不符）。此外该族的三个 A 槽会被"全 1"写成"每条记录都置位"，等价于对所有记录打勾，
  与猫装备 id 无对应关系。容量对账 [M]（`palico_weapons=495` / `palico_armor=1001` / `quests=1355`）
  只能说明 544 位装得下 495 只猫武器 —— 属**数字巧合级**证据，不足采信。
- 与任务系统的关联：`0x524B14`（`mov r3,#204` + `mla` → `movw #0x27a8`）与 36B 记录对（`0x2A0C/0x2A54`）同函数，
  该函数紧邻任务判定簇 `0x524E58/0x525040`；但按 3.3 的迭代器证据，本族更可能是 **`cTrial*`（试炼/狩技侧）
  记录状态**，而不是委托完成态（后者在 `0x42C/0x52C/0x62C` 三态位域）。
