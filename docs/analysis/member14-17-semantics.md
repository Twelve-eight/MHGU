### 4.3 ★ 载入期重标定浮点（本报告的实质发现之一）

`0x1ac014` 里有 **VFP 指令**（`arm32.mjs` 未解码，显示为 `.word … ; coproc`）：

```
0x1ac060  ed9f8aa6  vldr s16,[pc,#0x298]   → [0x1ac300] = 0x40033333 = 2.05f     （dump3 实测）
0x1ac064  ed950a0a  vldr s0,[r5,#0x28]
0x1ac070  ee200a08  vmul.f32 s0, s0, s16
0x1ac074  ed850a0a  vstr s0,[r5,#0x28]
```

- 该模式在 `0x28/0x2c`、`0x40/0x44`、`0x58/0x5c`、`0x70/0x74` 各出现一次（= 4 个 13B 子记录的 `+8`/`+12`）⇒ **这 8 个浮点字段在存档里是「归一化值」，读档后被 ×2.05**。⇒ 存档字节 ≠ 运行时数值，**编辑器不能把存档值当显示值**。**（定案：常量实测 0x40033333=2.05f）**
- 15B 子记录的构造器 `0x1bac00`（`m1417-out.txt:836..907` 之后）给出**默认哨兵**：`+0x10 = +0x14 = 0xC47A0000 = -1000.0f`（= 该类型两条 `+16`/`+20` 浮点的「未设置」值）、`+0x28 = 0xFF`、`+0x04 = 5`、`+0x08 = 0`、`+0x18 = 指向 0x14F0D76 的指针`、`+0x1c/+0x20/+0x24/+0x2c = 0`；分配 48 B。13B/15B 记录是**带「未设置」哨兵的记录**（时间/评分型）。**（定案：指令 + 常量）**
- **5 字节**记录构造器 `0x1baf10`/`0x1baf64`/`0x1bafa0`：写 `+0x04 = 458752 = 0x00070000`、`+0x08 = 0`（与 `0x1bb038` 读的 `+4..+8` 五个 u8 精确同址）；另有变体从 `r1+4..+8` 复制 5 字节。**（定案：偏移吻合）**

### 5.2 ★ 104 B 记录库的来源（决定语义的关键）

`0x1caafc` 之后的同族函数（`m1417-out.txt:1017..1149`）：

```
0x1cab8c  cmp r1,#71  ; bxhi lr          → 池 A 访问器：索引 0..71，步长 104
0x1cab9c  mla r0,r1,#104,r0 ; r2=104 ; b 0x7bd990     （memcpy(dst=obj+i*104, src, 104)）
0x1caba8  cmp r1,#26  ; bxhi lr          → 池 B 访问器：索引 0..26
0x1cabc0  r0 += 7488   ; 同样 memcpy 104
```

`0x55da44`（池重建器，`m1417-out3.txt:319..411`）——**这是语义钥匙**：

```
0x55da60  r9 = obj + 0x1d90                     ; 记录库基址
0x55da70  bl 0x1ca81c(bank, page)               ; 按页清零（104 stride，页=24/9 分块，见下）
0x55da78  cmp page,#3
0x55da8c  addne r6,r1,r0,lsl #3   (r0=3*page)   → 池A: [24*page, 24*page+24)
0x55da90  lslne r7,r0,#3                        → 起始 24*page
0x55daa4  ldr r2,[r10, r7, lsl #2]              ; 取静态 id 表 r10（=0x162D860）第 r7 项
0x55dab8  bl 0x55bc4c(manager, 7, id)           ; ← getById(kind=7, id)
0x55dac8  bl 0x1cab90(bank, r7, ret)            ; 把主数据记录复制进存档库
0x55dad8..0x55db20                             ; 池B: 9/page，id 表 0x162D98C，0x1cabac
```

- `0x55bc4c(manager, kind, id)`（`m1417-out5.txt`）：`ldr r0,[r0,#92]` → `[r0]` → `[0]` → `r0 = table[kind]` → `[0]` → `r0 = entries[id]` → `b 0xb84114(entry, id)`。典型的 **`cDataManager::getData(kind, id)` 二级表查找**。⇒ **记录库内容 = 「kind 7」主数据的 104 B 快照**。**（定案：指令级）**
- **静态 id 表**（`m1417-out5.txt` §1 实测）：
  - 池 A `0x162D860`，72 项 = **3 页 × 24**：每页值域 **0..23**（页内第 1 项为 0/23 的轮换，余下 `0..22`）；
  - 池 B `0x162D98C`，27 项 = **3 页 × 9**：主体是 `44..52` 的轮换（页首从 `46` 起：`46,47,48,49,50,51,52,44,45`）；**末页最后 2 项换成 `77`、`0x01001007`**（特殊条目）。
  - ⇒ **每页 = 24 + 9 = 33 条，3 页 = 99 条**；`page==3` 分支覆盖全量（72+27）。**（定案）**
- `0x1ca81c(bank, page)` = **按页清零**（`cmp r1,#3` 分支 + 104 stride 的 `strb 0` 循环，4 条/轮）。⇒ 库是可**分段重建**的缓存。**（定案）**
- **24+9 页结构的三重证据**：① 访问器调用计数（`m1417-out3.txt` §callers）`0x55d5fc` 调 `0x1cab90`（池 A）**24 次**、调 `0x1cabac`（池 B）**9 次**；② 重建器 `0x55da44` 的页循环 = 24 + 9；③ 两张静态 id 表的 72/27 = 3×(24/9)。**（定案）**
- 写侧 `0x55d5fc`（`m1417-out3.txt:226..318`）先用描述符表（`0x6aa9b8`，与 `0xdaba4` 同族的 staging 描述符）写 `obj+0x1ac/0x1b2/0x1b8/0x1be`（6 B 各、宽度 8/12）、`obj+0x1c4`（48 B、宽度 9/13）、`obj+0x1f4`（2 bit），再调 `0x55da44` 重建库，再 `0x1cab90(bank, i, …)`（24 次）/`0x1cabac`（9 次）逐条落盘 ⇒ **「导入一页」路径**（源 = `r4+104` 起的外部结构，步长 60）。**（定案）**
- `0x1c9b68`（唯一同时调用两个访问器的外部函数，`m1417-out3.txt:133..225`）= **8 状态状态机**（`sub r1,[r4,#4],#2; cmp #7; ldr pc,[pc,r1,lsl#2]` 跳表 `0x1c9ba8`，条目 `0x20/-0x28/0x28/0x64/0x200/0x284/0x32c/0x368`），栈上开 **104 B 缓冲**（= 一条记录大小），并调 `0x65e794/0x65e994/0x65eb0c/0x65e874`（UI/脚本层）⇒ **外部来源（下载/网络/合并）逐条灌入记录库**。**（高）**

### 5.3 记录内容（104 B）

- clean 档 99 条全 `nz=38..103/104`，`24 49 92 24` 周期与 `0x9249` 满布；dirty 档 `nz=20..59/104`，且**同族相似度高**（`m1417-out5.txt`：rec0 与 rec1..5 相同字节 clean `20/23/18/25/28` vs dirty `45/34/35/44/36`）⇒ **clean = 未使用/未初始化内容，dirty = 真实记录**。**（高）**
- dirty 记录里出现的**明确浮点**：`0x44000000`=512f、`0x43280000`=168f、`0x42c40000`=98f、`0x42180000`=38f、`0x3f800000`=1f、`0xc0400000`=-3f、`0x47ee6660`≈122 158 f、`0x41d00000`=26f、`0x40600000`=3.5f。记录内**字段非 4 对齐**（同一记录里浮点相位从 3 mod 4 变到 1 mod 4）⇒ 记录是**紧凑打包（packed）结构**，不能按 u32 网格解析。**（定案：字节相位）**
- 页/列一致性打分（`m1417-out5.txt` §对齐打分）在 104 网格上**平坦**（3398 vs 3400，差异 < 0.1 %）⇒ 104 网格**不能**靠自相似验证，只能靠 `7488/104=72`、`2808/104=27` 整数整除 + 访问器 `mov r3,#104` 定案。**（定案：以整除+指令为准）**

## 7. 未知 / 保留

1. ~~`0x7ca404` 语义~~ **已定位到模块级**：它在 **UTF-8 文本模块**（邻居 `0x7ca480` 判 2..6 字节 UTF-8 首字节）；但两档存档的 `record+0x04`/`record+0x24` **无任何可解码文本**（§2.5）⇒ 这两段要么不是文本源，要么存的是转换前/压缩后的形式。**具体转换算法（`0x7c98c4` 的 5 参语义）未展开。**
2. **member[14] 的 14 条记录对应什么游戏数据**：22 B + 56 B 源字段 + 7×44 B 子记录 + 9×u32 + 大量浮点 + 每记录 1 个子对象。14 与「14 武器种」数字吻合，但**无 id 表、无消费者、无文本**，**不下结论**。
3. **member[15] 的 152 B 语义**：无周期、无 id 表、无消费者（只有读写两侧），**未知**。
4. **member[16] 的 10 个子记录槽（4×13 + 1×5 + 5×15）对应什么**：`-1000.0f` 哨兵 + `0xFF` 哨兵指向「时间/评分型记录」，但槽位语义未定。
5. **member[17] 的 kind 7 = 哪种主数据**：id 空间 ≥53（每页选 `0..23` ∪ `44..52`），需要 `cDataManager` 的 kind 枚举（`0xb84114` 上游）才能命名。**这是把 [17] 从「结构定案」推进到「语义定案」的唯一缺口。**
6. `obj+0x45c8`（**不落盘**的 u32 槽）被 `0x1cab58` 规范化为 `0xF8FC7E3F`（浮点 ≈ −4.1e34）——「上界/最大值哨兵」的方向未定；同一函数的写入侧 `0x1cab40` 说明它是**运行期统计量**。

8. **「会话期指针」假设未证**：记录里 `0x47Exxxxx/0x48xxxxxx/0x51xxxxxx` 量级的 u32 密集出现，形态像堆指针/句柄；但存档若真的序列化指针，读档后 `0x159b18`（`record+0x230`）与 `0x1cab58` 会被垃圾值驱动，故更可能是**大整数/定点/位模式**。**未裁决**。

## 10. 对主会话两条交叉证据的回复

**① 「104 B 是通用记录单位？」—— 支持，但用途不同**
- 本区实测：`7488 = 72×104`、`2808 = 27×104`，访问器 `mov r3,#104` / `mla r0,r1,#104,r0`（`0x1cab98`、`0x1cabbc`）⇒ **104 B 是本作确定的记录单位**。
- 但 [17] 的 104 B 记录**不是尾部那种零填充周期**，而是 **kind-7 主数据快照**（`0x55bc4c(manager,7,id)`）；尾部「104 B 周期零段」若同为 104 网格，则两者共用步长、**内容层不同**。
- 附带线索（未证）：成员外尾部「469 B 定长槽 ×10」与 m14 的 **470 B 载荷**只差 1 B。若尾部确认 469（而非 470），值得比对是否同族记录的不同版本。

**② 「zlib 原语是否也出现在 [17] 的 7488/2808？」—— 否**
- `0x335A8..0x3783A` 全域 zlib 探测（`78 9c`/`78 01`/`78 da` 校验 `%31==0` + `inflateSync`）在 clean 与 dirty 中均 **0 命中**（`m1417-out3.txt` 末节 `[zlib probe …] total=0`）。
- ⇒ member[14..17] **不含** member[13] B1 / 成员外尾部 73 B 那种「`1d 00 00 00` + `78 9c`」压缩原语。这 4 个成员是**未压缩的运行期镜像**。

**③ 「[17] 尾块是否跨成员共享容器？」—— 否**
- 7488+2808 = 99×104，边界由 `cmp r1,#71` / `cmp r1,#26` 夹死，且 `0x35000`（页对齐起点）+ 0x1D40 + 0xAF8 + 2 = `0x3783A` **正好等于成员终点**（零余量）。⇒ **自包含**，不是跨成员共享容器。
- 但语义上是**外部主数据的快照**（`0x1c9b68` 状态机从外部来源灌入），所以「数据来源在成员外/主数据里」这层关系成立。
