## 1. Evidence base, and why the `strings` column is not usable as-is

`docs/data/functions.csv.gz` has 23 885 functions; 1 937 carry ≥1 string (4 462 string entries). That column was
built by `tools/mhgu/func-inventory5.mjs`, which has four defects that matter here:

1. `w&0xFFFFF000 == 0xE59F0000` matches only `ldr **r0**, [pc,#imm]` with `imm[11:8]==0`. The dominant PIC idiom in
   this image is `ldr rX,[pc,#imm]` (any `X`) + `add rD,pc,rX`; it was missed whenever `X != r0`.
2. `slice(0,32)` per function and a 100-byte limit in `strAt`. Mangled names are 49 bytes median, 145 max, so long
   symbols are dropped whole: the image holds **527 distinct `_ZN2nn…` names**, the column keeps **2**.
3. A literal that is really a **pc bias** is also read as a string pointer (`if(!inText(V)) strAt(V)`). Of the 855
   column strings my re-extraction cannot reproduce, **754 are exactly this class** (see §1.3 below for the proven
   mechanism); e.g. in `0x1168` the value `0x154fbe2` — whose real target is `0x1550d76` — yields the fake string
   `_ZN2nn3ldn16GetNetworkConfigEPNS0_13NetworkConfigE`.
4. No code-vs-data distinction, and no check that the target is the start of a string.

Attributions are therefore built on a corrected re-extraction over the **same function ranges**
(`start`/`insns` from `functions.csv.gz`); scratch code: `G:/tmp/LibFp/extract2.mjs`.

Accepted reference kinds (what "the function's own string" means here):

| method | rule | example |
|---|---|---|
| `addpc-lit` | `ldr rD,[pc,#imm]` (mask `0x0FFF0000 == 0x059F0000`, cond `0xE`), then `add rD2,pc,rD` within 9 insns → target = site+8+V | `0x134d4f0` → `0x158cde9` `"NatDetectionJob::StepEnd"` |
| `addpc-imm` | `add rD,pc,#imm12` → target = site+8+imm | build paths at `0x13f1a08` |
| `addpc-reg` | `add rD,pc,rM` with `rM` from `movw/movt` | 0 hits in this image |
| `movwt-abs` | `movw/movt` pair whose value is a string address | 0 hits |
| `poolptr` | `ldr rD,[pc,#imm]` then `ldr rD2,[pc,rD]` where the **loaded word** is a clean string address | 2 hits |
| `inline` | ASCII string stored in the literal pool | 0 hits |
| ~~`dptr`~~ | literal value read as a string address, **rejected** — see below | 53 hits, all artefacts |

**The rejected `dptr` class (53 hits).** A literal that is not consumed by `add pc,rX` can still be a table offset
for the next instruction: `ldr rD,[pc,#imm]` (V) followed by `ldr rD2,[pc,rD]` means `*(pc+V)`. When the table
lives in `.rodata` (~`0x183xxxx`) and the code in `.text` (~`0x2bxxxx`), the offset `table − pc` is numerically
~`0x158xxxx` — i.e. **inside the message-string region**. Worked example (`0x2b1630`):
`0x183abc8 − 0x2b1638 = 0x1587590`, and `0x1587590` is exactly `"RendezVous::DeniedByParticipants"`; the word
actually loaded from `0x183abc8` is `0x173f2ec`, a data pointer. All 53 sites are of this shape, which is also the
mechanism behind the 754 column artefacts of §1.3. They were dropped from the TSV: 17 rows whose only evidence was a
`dptr` value (15 nex, 1 nvn, 1 `nn::fs`), each of which stays out rather than being attributed on coincidental text.

Validation of the accepted extraction:

* 3 216 functions have ≥1 reference (column: 1 937); 16 317 raw hits, 11 857 distinct strings.
* 3 607 / 4 462 column strings reproduced **exactly**; the rest are the artefact class (754) or bytes inside
  compressed blobs (101).
* `addpc-lit` targets: 16 247 / 16 254 start right after a NUL; the 7 exceptions are inside compressed blobs.
* `poolptr`: 2 / 2 loaded words are clean string addresses.

Confidence rule: **A** = the function's code materialises the address of a string that names a library symbol;
**B** = the string names the subsystem but not a library symbol (field name, message body, printf table).

## Difficulties

* **The provided `strings` column is not a safe evidence base.** Its literal-as-pointer heuristic produced a
  reproducible artefact class (754 of 855 unreproduced column strings; proven mechanism in §1: table offset
  `.rodata − .text` lands inside the string blob), and its masks/caps dropped most mangled names (527 `_ZN2nn`
  names in the image → 2 in the column). Cost: a full re-extraction plus a bisect of the artefact (5 sites
  disassembled, 53 classified) before any attribution could be trusted; the first TSV draft used the `dptr` class and
  had to be rebuilt.
* **Mangled names are data, not code references.** All 527 `_ZN2nn…` names live in the NSO dynamic-symbol string
  table; `findLiteralLoads` over `.text` finds no instruction that materialises any of them, and the RTTI-style blob
  (`N2nn3nex15BackEndServicesE`) is referenced only from `.rodata` (`0x1573004`). Suspected cause: imports are
  resolved through a link table by index, so names never enter a function's address space. Consequence: the classic
  `_ZN2nn…` fingerprint channel is structurally unavailable, which is why nex/pia had to be recognised from assert
  paths, job state-machine names, SDK banners, heap names and socket names instead.
* **Residual risk.** 7 of 16 254 `addpc-lit` targets are not NUL-aligned (compressed data), and `poolptr` trusts two
  literal-table words (both verified to be string addresses). Messages reached only through a *table* of strings
  would still be missed, because the table word is not read back into a string in those functions.
* **A cannot override A**, so 15 better-evidenced rows stay invisible to the meter; fixing those needs an
  adjudication pass, not another source file.
* **The spine is a shared, mutable input.** `docs/analysis/code/inventory/tiers-recomputed.csv` was rewritten by
  another process at 10:29:36 while this task was measuring (A 9 188 → 11 634 by 10:31:22, headline 53.1 % → 61.2 %),
  which made a repeat `report.mjs --source …` print `0 fn` for the same file. Tried: re-ran the meter, compared all
  505 starts against the new spine (all `A`, labels identical → absorbed, not rejected), then rebuilt the measurement
  on the committed `tiers.csv` spine in a scratch copy so the quoted contribution stays reproducible. Cost ≈20 min and
  three extra measurement runs. Suspected cause: the spine is regenerated by a different owner that merges new
  sources without freezing the baseline the ticket quotes.
* **Ceiling of this method.** 20 669 functions reference no string; the remaining 14.5 k conf-B mass is field-name
  evidence (`mVillage…`, `mParam.net_em.uid`) that names data, not a library. String evidence alone moves the
  headline 53.1 % → 53.4 %; the library slice is worth 44 functions / 0.3 pp, and further gains need vtable,
  registrar or call-graph evidence.
