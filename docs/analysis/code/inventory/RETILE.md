# 函数清单重切（2026-11-03）

`docs/data/functions.csv.gz` 是**区域平铺**（23,885 段），不是函数表：镜像里有 **46,087** 个 `push {...,lr}` 前导，
其中 **22,202** 个不是区域起点。后果：函数级分母偏小一半；68,626 个 vtable 槽里 62,787 个因目标不是区域起点而无法归属。

重切起点 = 前导 ∪ BL/BLX 立即数目标（断言：BL 目标数 ≈ 23,336、旧起点全部保留、指令总和 = 5,228,277、带字符串函数 ≈ 1,937）。

## 已知局限（抽样实测）

- 起点只来自「前导 ∪ BL 目标 ∪ 旧起点」，因此**不以 `push` 开头的叶子函数/薄 thunk 仍会被并进相邻函数**：PrecisionB 抽 160 行发现 71 行的真实体比行跨度短（最多短 2,223 条指令），12 行≤ 4 条指令。
- 试过用「`pop {…,pc}` / `bx lr` 之后」作为额外起点：起点涨到 102,945（早返回也被当成函数边界），指令和偏差 29，已回退。要正确切分需要区分 `bx lr` 的早返回与真正结尾，属于额外工作。
- 影响：函数级百分比会被高估（函数数偏少），指令级百分比不受影响（平铺完整覆盖 .text）。报告函数级数字时带上这一条。
