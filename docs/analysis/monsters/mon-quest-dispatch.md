> 已有反汇编：`.tmp/mhgu/analysis/qp4/fn-2484c0.txt`（721 条，含字面量池 0x248f4c..0x249000）。

> （任务书写的是 `.py`；这里用 `.mjs`，因为要复用 `.tmp/mhgu/tools/arm32.mjs` 的 ARM 解码器，避免再写一套。）

## 已确认（有证据）

### 0. 结论先行

1. **`0x2484c0` 不是「任务/结算动作表」，而是一张 114 项的「全局条件谓词表」**。
   它对 `condId` 求值并**返回布尔**：唯一出口 `0x248f40: mov r0,r4 / add sp,sp,#32 / pop {r4,r5,r6,pc}`。
   函数体里没有任何写存档、发报酬、解锁、加计数器的语句；所有 case 只**读**全局单例的字段并比较。
   证据：入口 `0x2484e4: mov r4,#0`（默认假），每个 case 结局只有 `mov r4,#0`、`mov r4,#1`、
   `movwcc/movwhi/movweq r4,#1`（条件置位）三种形态；**全函数没有一条以通用寄存器为基址的
   `str/strb/strh`**（`grep 'str[bh]? rN, [rN'` 于完整反汇编：0 命中），所有 `str` 都写 `[sp,#…]`。
   → 因此「任务结算动作」这一前提需要改写：作用是**判定「该条件是否满足」**。
2. **表基址 = `0x2484f0`，114 项，目标 = `0x2484f0 + entry`**（基址相对跳转）。
   解码链：`0x2484d0 sub r1,r3,#1` → `0x2484d4 cmp r1,#113 (0x71)` → `0x2484d8 bhi 0x2487e4`
   （越界）→ `0x2484dc mov r1,r1,lsl#2` → `0x2484e0 add r2,pc,#8`（pc=0x2484e8 → r2=0x2484f0）
   → `0x2484e8 ldr r1,[r1,r2]` → `0x2484ec add pc,r1,r2`。
3. **dispatch 键 = 第 4 参 `r3` 减 1**，合法 `condId = 1..114`；`condId-1 > 113`（即 0 或 ≥115）→ `0x2487e4` → **返回真**。
4. **114 个 case 只落到 49 个不同目标**：43 个独占 case + 6 个共享块
   （`0x2486b8`×14、`0x2486d0`×14、`0x2486f0`×6、`0x248704`×6、`0x2487e4`×9、`0x248f40`×22）。
5. **唯一与怪物系统相连的点**：`cond 10/11/12` 三处 `movw r1,#0x72c`（`0x248984 / 0x2489a8 / 0x2489cc`）
   → `add r0,r0,#0x72C` → `bl 0x52308c` → 与 51 / 300 比较（`§4.1` 已把 `0x52308c` 解到指令级：
   它是 `Σ(kill[slot]+capture[slot])`，即**总狩猎数**）。
   **函数体内 0 处 `0x83E` 立即数**——捕获数是经 `0x52308c` 的 `+0x112` 间接读到的，不是本表直接寻址。
6. 「未知 condId ⇒ 真」这一点很重要：老版本/未知条件类型会被当作**已满足**，不会卡住任务。

### 4. `0x72C` / `0x83E` / `0x52308c` 的精确落点

| 站点 | 指令 | 含义 |
|---|---|---|
| `0x248984` | `movw r1,#0x72c` | cond 10：`sum = 0x52308c(obj+0x72C)` |
| `0x2489a8` | `movw r1,#0x72c` | cond 11：同上 |
| `0x2489cc` | `movw r1,#0x72c` | cond 12：同上（结果直接进 `0x248c4c` 的 `cmp #300`） |
| — | 无 | **`0x83E` 在此函数中出现 0 次** |

三处都走同一个形状：`slot → [slot]`（存档对象）`+ 0x72C` → `bl 0x52308c`；
即 `0x52308c` 的入参是**击杀计数器数组的基址**（137×u16），返回值参与阈值比较。

#### 4.1 `0x52308c` 的精确语义（已由 `counter-slots.out.txt` 的逐条解码确认）

```
005230ac: add r7, pc, r0        ; r0=[0x523100]=0x1108e58 -> r7 = 0x5230b4+0x1108e58 = 0x162bf0c  (u16 EmId 表)
loop (r6 = 0; r6 != 332; r6 += 2):
005230b0: r0 = u16[r7 + r6]                       ; 第 i 个 EmId
005230b8: bl 0x50b64                              ; EmId -> 槽位 0..136（查 137 项表；未登录返回 -1）
005230bc: cmp r0,#136 ; bhi  next                 ; -1 / 越界 -> 跳过
005230cc: r1 = r4                                 ; r4 = 入参 = obj+0x72C
005230d0: r0 = u16[r1 + 2*slot]                   ; 击杀计数（kill 数组 0x72C 起）
005230d4: r1 = u16[r1 + 0x112 + 2*slot]           ; 捕获计数（capture 数组 = 0x72C+274 = 0x83E 起）
005230d8: r1 = r1 + r0
005230dc: r0 = r1 & 0xfff0 ; cmp r0,#9999 ; movwhi r1,#9999   ; 每条上限 9999
005230ec: uxtah r5, r5, r1                        ; r5 += 该条（低 16 位）
005230f8: return r5
```

结论（**确定**）：`0x52308c(obj+0x72C)` = **166 条 EmId 表逐条取 `kill[slot] + capture[slot]` 再累加**，
即「**总狩猎数（含捕获）**」。
注意 `+0x112` 正好是 137×2，所以第二条 `ldrh` 读的就是**捕获计数器**（`obj+0x83E`）。
→ 虽然 `0x2484c0` 自身没有 `0x83E` 立即数，但 cond 10..12 的**返回值里包含捕获数**；
「此表只读击杀不读捕获」在*函数内*成立，在*语义上*不成立（捕获经 `0x52308c` 间接计入）。

`0x52308c` 全二进制只有 4 个调用者：`0x248994 / 0x2489b8 / 0x2489dc`（本表 cond 10/11/12）+ `0x3d440c`（`fn 0x3d17f8`）。
同文件另有 `0x523104(ptr, EmId)` = 「单个怪物」版本（同样 kill+capture、同样 9999 钳制），本表未使用。

### 5.1 两个私有转发器的部分解码（`0x249004` / `0x2493c8`）

在整份二进制里只有本表调用（`bl` 站点 `0x2486e4` / `0x2486f8`），所以它们就是 cond 28..61 的实现本体。
用 `movw-index.json`（该文件第 1 列 = **十进制 vaddr**，已用本函数三个已知站点自检：
`2394500` = `0x248984` → imm 1836 = `0x72c` ✓、`2394440` = `0x248948` → imm 994 = `0x3e2` ✓、
`2395228` = `0x248c5c` → imm 2186 = `0x88a` ✓）可读出部分常量：

- `0x249004` 内 `movw` 站点 **29 处**，地址 `0x249028..0x2491bc`，立即数全部为**偶数**、范围 **2270..2350**
  （`0x8de..0x92e`，即 `obj+0x8de..0x92e` 这段 **u16 字段块**）：
  `2270 2274 2276 2278 2280 2282 2284 2286 2290 2292 2300 2302 2306 2308 2310 2312 2314 2316 2318 2322 2332 2334 2338 2340 2342 2344 2346 2348 2350`。
- `0x249004` 只调用 1 个函数 `0x13efdc4`（`inventory/functions2.csv` 第 4480 行）⇒ 基本是**纯读 + 比较**的分派体。
- `0x2493c8` 只调用 3 个函数：`0x690`、`0x13efda0`、`0x7aedcc`（同上第 4481 行）。

→ **[INFERENCE，中] `0x249004(a0, mode, id)` 是 14 路（id 0..13）× 2 模式（mode 0/1）的字段读取器**：
29 ≈ 2×14 个 `movw` 常量、且每组只差一个 `mode` 标志，正对 §2 里「同一张 14 词表、两个模式」的结论。
若成立，cond 28..55 判的是「`obj+0x8de..0x92e` 那批 u16 计数器里第 `id` 个」的两种状态（置位/清零或 ≥1/=0）。

### 5.2 数值上的强暗示（供下一轮验证，**未证实**）

- cond 28..55 = **14 个槽 × 2 模式**；MHXX 恰好有 **14 种武器**。→ [INFERENCE，低-中] 「武器種ごとの使用回数」的两种状态。

  MHXX 恰好有 **6 种狩猟スタイル**。→ [INFERENCE，低-中] 「スタイル別使用回数」，62..67 判「该风格是否用得最少」。

### 6. 全局单例槽的定位规则（供后续命名）

所有 case 都使用同一形态取全局：

```
ldr rX, [pc,#k]      ; 字面量 L（例如 0x15f03f8），L 是「相对 pc 的偏移」而非地址
ldr rX, [pc, rX]     ; slot = (本条指令地址 + 8) + L
ldr rX, [rX, #0]     ; obj = *(slot)
... 读 obj + 固定偏移
```

例（cond 10）：`0x248980 ldr r0,[pc,#1620]` → 字面量 `0x15f03f8` 位于 `0x248fdc`；
`0x248988 ldr r0,[pc,r0]` → slot = `0x248990 + 0x15f03f8`；`0x24898c ldr r0,[r0,#0]` → obj；`+0x72C` → 计数器基址。

- 字面量呈两条连续带：`0x15efe00/38/64/84/b4/d8/ed8`（步长约 0x24–0x2c）与 `0x15f0068…0x15f0920`（步长约 0x24）。
  两条带分别对应两批「全局访问器槽」，同一 case 家族（D/E/F/G/L/K）落在同一带内 ⇒ 这些全局是**同类对象的多个实例**，
  不是随意挑选的地址。
- 因为每个 case 用**各自的槽**，cond 13..16 虽然同调 `0x526348(obj,28,-1)`，比较的却是**不同对象**的同一字段
  ⇒ **[INFERENCE，中] 这批 id 是「同一条件 × 不同对象（类别/地区/存档域）」的展开**，而不是同一数值的四档。
  这一点与「4 档阈值递增」的解读冲突，故 §5 里对 13..16 / 17..20 / 21..24 的含义只给「低」置信。

### 7. 调用者（上下文）

- `0x2484c0` 的**唯一**调用者：`0x2456e8`（位于 `0x2451c8..0x246b1c`）。
  该函数自身也是一张分派表：`0x2451d0 sub r6,r1,#1; cmp r6,#162; bhi 0x246810`，163 项，
  `0x2451ec add r5,pc,#8` → 表基址 = `0x2451ec+8+8 = 0x2451fc`，`0x2451f4 ldr r6,[r6,r5]` + `0x2451f8 add pc,r6,r5`。
  （注意 `add rd,pc,#imm` 的 pc 已是 `insn+8`，故基址是 `0x2451fc` 而不是 `0x2451f4`；首项 `0x2b4` → `0x2454b0`。）
- **外层 key 29 就是「全局条件」入口**（算术自检）：委托体在 `0x2456dc`，`entry = 0x2456dc - 0x2451fc = 0x4e0`；
  表里 `0x24526c` 的值正是 `0x000004e0`，其 index = `(0x24526c-0x2451fc)/4 = 28` ⇒ key = 29。
  即：外层 163 项里第 29 项 = 「把这个 id 交给 `0x2484c0` 判」。
- 外层的返回值默认是 **1**（`0x2451f0 mov r4,#1`），与内层默认 0 相反；越界走 `0x246810`（不在已导出的 1200 条内，未确认）。
- 委托点：
  ```
  002456dc: e3a01000  mov r1, #0
  002456e0: e3a02000  mov r2, #0
  002456e4: e1a03008  mov r3, r8      ; r8 = 0x2451d4 mov r8,r3（外层第 4 参）
  002456e8: eb000b74  bl 0x2484c0
  002456ec: e28dd018  add sp, sp, #24
  002456f0: e8bd8bf0  pop {r4, r5, r6, r7, r8, r9, r11, pc}   ; 直接尾返回
  ```
  → 外层某个 key 的语义就是「把第 4 参当作**全局条件 id** 交给 `0x2484c0`」。
  即外层 163 项里至少有一类 case 是「全局条件」入口；`0x2484c0` 的 id 空间与外层的分派键（r1）**不是同一个**。
- 实践含义：想找「谁在判定任务条件」，应从 `0x2451c8` 的调用者（`0x2441a4 / 0x2441f4 / 0x244244 / 0x244474 / 0x2444c4 / 0x244520`）继续往上。
