# Q5b · MHGU 一条攻击行如何变成命中/反应/伤害：哪些字段是代码分支开关

> 归属：本文件由上游会话 **S-G** 于 2026-11-07 写入（S-G 的写盘边界包含 `MHGU/docs/analysis/re/**`）。

**结论（一行）**：GU 的一条攻击行是 **32 字节**；它被读进一个 **184 字节命中记录**
（`[[em+0x1428]] + 0x998 + slot*0xB8`，只有 2 个 slot）。行里**没有碰撞体几何**——形状来自独立的 hitsize 资源、由行内
`+0x19` 索引。**代码分支开关**只有三类：`+0x06 react`（9 个值对应跳转表）、`+0x00/+0x02` 帧窗口（`+0x02 == 0` 的命中永远不生效）、
以及 `+0x0C attr` / `+0x08` / `+0x0E` 的位域；`+0x04 dmg` 等是**纯拷贝**（之后参与乘算）。

本 note 是我复核过的部分 + 子代理报告 `G:/tmp/slices/sr-q5/REPORT.md`（525 行，草稿，逐条带指令）的汇总；
未复核的条目按 §2 标注。

## 1. 我亲自复核的两段（ARMv7，vaddr = flat − 0x100）

**行读取器 `0x168be8`（行指针 r7，记录指针 r5）** —— 逐字段拷贝：
```
168c44: ldrsh r0,[r7,#0]  -> vstr s0,[r5,#0x5c]    行+0x00 -> rec+0x5C  (f32 帧起点)
168c54: ldrsh r0,[r7,#2]  -> vstr s0,[r5,#0x60]    行+0x02 -> rec+0x60  (f32 帧终点)
168c64: ldrh  r0,[r7,#4]  -> strh  r0,[r5,#56]     行+0x04 dmg  -> rec+56
168c6c: ldrb  r0,[r7,#6]  -> strb  r0,[r5,#58]     行+0x06 react-> rec+58
168c74: cmp r0,#0 / 168cc4: strbeq r6,[r5,#58]     react==0 时归一化为 0
168c7c: ldrh  r1,[r7,#8]  -> strh  r1,[r5,#54]     行+0x08 -> rec+54
168c84: ldrb  r1,[r7,#10] -> strb  r1,[r5,#59]     行+0x0A -> rec+59（kb 低字节）
168c8c: ldrb  r1,[r7,#11] -> strb  r1,[r5,#60]     行+0x0B -> rec+60
168c94: ldr   r1,[r7,#12] -> str   r1,[r5,#64]     行+0x0C..0x0F（attr + u0e）-> rec+64
168c9c/ac: ldr r1,[r7,#16] / r2,[r7,#20] -> [r5,#72] / [r5,#76]
168cac: ldrb r1,[r7,#24] -> strh r1,[r5,#80]；168cb4: ldrh [r7,#26] -> [r5,#82]
168cbc: ldrb r1,[r7,#28] -> strb r1,[r5,#85]；168cd8: ldrb [r7,#31] -> [r5,#158]
```
**命中记录定位 `0x7dc2c`（slot = r10）**：
```
7dddc: mov r0,#184            ; 0xB8 步长
7dde0: ldr r5,[r11,#12]
7dde8: smlabb r0,r10,#184,r1  ; slot*0xB8 + base
7ddec: movw r1,#0x998
7ddf0: add r9,r0,r1           ; r9 = base + 0x998 + slot*0xB8
```
`0x7dc50: cmp r10,#1 / bhi` → **只有 slot 0/1**。

**arm 之前的状态相关 kb0a 调整（`0x7dc98..0x7dd28`）**：`bl 0xc21c8`（按 `[block+0x5C2F]` 取 `0x3E` 的某一位，状态 1..5 为真）→ 真则
`r0 = [block+0xFEC] + [block+0x54]`（`add r0,r0,r1`）再 `add r0,r1,r0; strb r0,[sp,#34]`，即**对 kb0a 低字节做状态相关加算**。我读过这段。

## 2. 分支 vs 拷贝（子代理逐条读出的结果，标 `[B]` 的部分为未复核）

| 行偏移 | 字段 | 处理 | 后果（作者视角） |
|---|---|---|---|
| +0x06 | `react` | **分支**：9 个值的跳转表，跨 4 个函数；动画是每个分支里的**常量** | 值不在表内 = 走默认（71 通用反应）；这是"反应"的唯一入口 |
| +0x00 / +0x02 | `u00` / `u02` | **分支**：被改写成一个帧窗口；`u02 == 0` 的命中**永不生效** | 作者必须给非零终点帧 |
| +0x0C | `attr` 位域（2/4/5/6/7 优先链、bit14、bit27） | **分支**：选伤害类型 → 每类型 s16 表（`0xe173c`） | 决定走哪张伤害表 |
| +0x08 | `u08` bit 6/8/9/10/13 | **分支** | 行为开关 |
| +0x0E | bit 3/4 | **分支**（arm 时写记录模式字节） | 影响 slot 记账 |
| +0x10 / +0x14 | 位掩码 | **分支**：选每部位 slot（19 处位测试） | 部位绑定 |
| +0x04 | `dmg` | 拷贝 + 乘算：×`f32[[[em+0x1428]]+0x384]` → 防御公式 → 技能 → clamp≥1 → **累加**到 `pl+0x321C` | 数值来源 |
| +0x0A/+0x0B | `kb0a` | 拷贝（低字节另有状态相关加算） | 击退 |
| +0x19 | `hts` | **索引**（不是分支）：查 hitsize 资源组，形状由 `0x1696fc` 的 `vt[68]` 取 | 碰撞体在这里，不在行里 |
| +0x18 / +0x1D / +0x1E | — | 拷贝/累加（`u1d` 累加到 `pl+0x3226`） | — |
| +0x1A / +0x1C / +0x1F 高位 | — | **在"怪→玩家"这条路上没找到读取者** | `[U]` |

## 3. 被推翻的草稿说法（子代理复核，我未逐条重读）

- `em + slot*0x140` 结构不存在（实测 `block + 0x998 + slot*0xB8`，我已独立复核）。
- `0x168960 / 0x168e98` 不是 HDE 行读取器（它们是**写**记录的构造器，输入是另一种 56 字节结构）。
- 斩味函数 `0x178030` 不在"怪→玩家"路径上（它属于"玩家→怪"）。
- `u00/u02/u08/u10/u14/u18/u1d` 都有读取者（草稿标成死字段是错的）。

## 4. 所以移植需要什么数据

1. **必填**：`+0x00`/`+0x02`（帧窗口，`+0x02` 非 0）、`+0x04 dmg`、`+0x06 react`（或用表内的默认值）、`+0x0C attr`（决定伤害表）、
   `+0x19 hts`（决定碰撞体组）。
2. **可沿用模板值**：`+0x08`、`+0x0E`、`+0x10`/`+0x14` 位掩码、`+0x18`、`+0x1D`、`+0x1E`（除非要做对应的特殊行为）。
3. **行里没有的东西**（必须在别处给）：碰撞体几何（hitsize 资源，按 `hts` 索引）、arm 时的 flags（`0x7dc2c` 的 r3）、tag、
   以及 `rec+109` 通道 2（子代理列的三个"代码侧常量"）。
4. 两个 slot 的上限（`cmp r10,#1`）意味着**同一时刻只有 2 条命中记录**；多段命中要靠时间上错开，不是靠加 slot。

## 5. `[U]`

- `[U]` `rec+82`（行 +0x1A）、`rec+85`（行 +0x1C kind）、`rec+158`（行 +0x1E 高位）的读取者没找到。
- `[U]` `rec+0x14` 的写入者、`0x2effac` 由哪个执行子分支到达、`pl+0x321E..0x3254` 这个 slot 数组的含义。
- `[U]` `react` 的 9 个值我只从报告里知道"有跳转表"，没有逐个值对到动画常量。
