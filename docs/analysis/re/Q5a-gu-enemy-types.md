**结论（一行）**：GU 的敌人类型**完全编译进镜像**：每个 `uEmNNN_nn` 是一个 C++ 类，由**同一个注册函数在开机时**用
"字面量类名 + 编译期类大小"注册进运行时类型记录（我读到的形状是 `movw r3,#0xcad0` 类大小 → `add r1,pc,#…` 类名 →
`bl 0x7aedcc` 注册 → `str r1,[r0,#0]` 把记录+8 发布到类全局）。资源侧按 `emId` 找数据的容器是**固定 160 槽**
（`cmp r11,#160`），槽步长 0x1C00。**没有数据驱动的注册路径**（与 MHRS 侧 116 条编译期登记同形）。

本 note 是我复核过的部分 + 子代理草稿 `G:/tmp/slices/re-gu-enemytypes/REPORT.md` 的汇总。

## 1. 我亲自复核的（ARMv7，vaddr = flat − 0x100）

**开机注册器 `0x4f078`（片段 0x4f140-0x4f1a4）**：
```
4f15c: movw r3,#0xcad0        ; 类大小 51920
4f16c: ldr r4,[pc,r1]         ; GOT 槽
4f178: add r1,pc,r1           ; r1 = 类名字面量指针
4f180: bl 0x7aedcc            ; 注册(name, size, ...)
4f18c: movw r3,#0xcae0        ; 下一个类的编译期大小
4f1a0: add r1,r1,#8
4f1a4: str r1,[r0,#0]         ; 把 record+8（工厂槽地址）发布到该类的全局
```
即：类名与类大小都是**编译期常量**，不存在"从资源读类列表"的路径。`[C]`

**每 em 资源管理器的容量 `0x3a2c0`**：
```
3a5e0: movw r3,#0x1fb
3a5e4: add  r11,r11,#1
3a5e8: cmp  r11,#160          ; 160 个槽
3a5ec: bne  0x3a350           ; 循环体
```
槽步长 0x1C00（草稿给出，`rsb r6,r11,r11,lsl#3` ×`lsl#10`，我未逐条复核）。`[C]`（160 这一个数我读了）

## 2. 草稿里没复核的要点（标 `[B]`，引用前需再读）

- 97 个 stride-0x14 的静态类记录在 `0x173227C-0x1732A10`，注册器 0x4f078 做 93 次注册调用。
- 路径生成器 `0x15339c` 是"一个 77 分支的 kind switch"，`enemy\em%03d_%02d` 在 0x154320 段、格式串在 0x155734F。
- 资源集 id 的 translate 发生在 quest/field 加载器里，不在 0x3a2c0 内。

## 3. 所以移植需要什么数据

- GU 侧**没有**"注册一个新敌人类型"的数据通道：新类型要么复用已有的 `uEmNNN_nn` 类（我们的做法），要么改代码。
- 与 MHRS 侧一致：**身份是编译期事实**，所以两个游戏的 `emNNN ↔ 怪物` 映射都必须以 KB 里的可复算来源为准（AGENTS §2f）。
- GU 资源侧 160 槽 / 0x1C00 步长给了"最多多少 em 资源集"的量级；不要把它当成"最多 160 种怪物"（emId→资源集 id 还有一层 translate）。
