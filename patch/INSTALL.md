# MHGU v1.4.0 道具箱扩容补丁（V7，实验）

设计目标是道具箱 **2300→2992槽、道具预设24→14组**。**当前不推荐普通玩家在主存档上启用：V7仍有已记录的辅助表容量不足与越界风险。** 看见30页或补丁指令全部匹配，不等于排序、预设、保存和重载安全。

## 先选对运行方式

| 运行方式 | 代码修改入口 | 本包是否对应 |
|---|---|---|
| yuzu / suyu 模拟器中运行MHGU | Mod目录下的 `exefs/1.4.0.pchtxt` | 是，仅实验测试 |
| SUYU-GURecomp导出的PC游戏程序 | Forge PC原生插件 `itembox.dll` | 否，本包不含DLL或Forge加载器 |

导出版不支持把 `.pchtxt/.ips` 放进去改变已生成的原生代码。Forge PC路线在仓库 `forge/itembox-v7/`，与Switch上的原版Forge不是同一个插件接口；其V7实现同样继承下述风险，不能当作安全替代。本包不提供经过验证的Switch主机安装步骤。

## 仅用于隔离测试副本的模拟器安装

1. 退出游戏，备份整套存档（含 `system`、`system_backup`、实际存在的 `*.hnt`）和当前Mod配置。不要使用唯一存档或日常游玩目录试验。
2. 确认游戏为 **v1.4.0，build `FB08F1D20FD1204FE7070672777F869B`**。其它版本不支持，不能强行套用。
3. 在模拟器游戏列表右键MHGU，打开该游戏的Mod数据目录。将本包根目录的补丁放成：

   ```text
   <Mod数据目录>/ItemBoxV7/exefs/1.4.0.pchtxt
   ```

   模拟器数据目录下对应 `load/0100770008DD8000/ItemBoxV7/exefs/1.4.0.pchtxt`。保留文件中的 `@nsobid`，不要自行添加 `offset_shift` 或修改补丁地址。该文本用文件内build ID匹配，不靠重命名文件选择版本。
4. 只在测试配置启用这一种扩容实现；不要与V8或其它修改相同代码的Mod叠加。**旧原版存档不能直接裸载入后点 Sort**：原版预设区（`charOff+6095..7737`）会被当成第 24–30 页幻影道具解码，点击整理后会把幻影素材顶到第 1 页。启用前请先备份原存档，并用仓库脚本迁移一份新副本：

   ```bash
   node tools/migrate-save-v7.mjs <备份的system或.hnt> --out <迁移后的system或.hnt>
   ```

   该脚本会完整保留前 2300 格道具和前 14 组道具预设，并将第 24–30 页清零。另外，V7/V8 补丁已在排序累加循环（`0x199cb8..0x199ce8`）内置 `1 <= item_id < 2991 && count > 0` 运行时越界拦截，防止非法 ID 写穿 `counts[2991]` 栈缓冲或生成 `id=0` 幽灵条目。
5. 只有在后续专门的验收计划下测试新增槽位、排序/整理、预设、保存后重载和原数据保持。**当前包没有完成这条验收链。**
6. 回到原版时，退出游戏、停用测试补丁并恢复整套原备份。已经由扩容环境写出的存档不能假定被原版正确读取；卸载Mod不转换存档。

## 未解除的风险

- V7只移动B/C/D辅助表，没有把它们全部扩到2992条；历史分析记录整理/填充路径会越过原容量。详见包内插件规格 §4 R2，以及仓库 `forge/itembox-v7/README.md` 的 Limits。
- 预设记录复制还有未设边界的历史风险（规格 §4 R4）；本轮未修补该代码。
- V8是另一个实验布局，不能把版本号或离线字节匹配当成运行安全证明。
- Forge PC的V7插件使用不同加载机制，但并未消除上述V7布局风险。

## 证据范围

旧记录包括补丁站点比对、模拟器启动以及用户确认30页；它们不替代本次的完整容量/排序/保存验收。发行打包只保证具名成员和校验清单对应，不证明扩容功能完成。

存档编辑器是独立工具，只在内存中改副本、下载 `.edited`；必须手选与文件真实来源一致的布局。选择 `v7` 不会转换存档，也不会安装本补丁。
